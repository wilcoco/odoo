# 업무 승인 체계 정리 (2026-07-24)

> 목적: "담당자가 그냥 처리하는 것 / 승인이 필요한 것 / 이력만 남기면 되는 것"의 전사 기준을 세우고,
> 현재 시스템 구현과의 갭을 드러낸다. 코드 사실은 2026-07-24 기준 실사( grep·플로우 확인) 결과.

## 1. 판단 원칙 (3단계)

| 등급 | 기준 | 처리 방식 |
|---|---|---|
| A. 단독 처리 | 되돌리기 쉽고, 돈·외부에 영향 없음 | 담당자 즉시 처리, 시스템 기록만 |
| B. 승인 필요 | **돈이 나가거나, 되돌리기 어렵거나, 외부(고객·협력사·세무)에 나가는 것** | 상신→승인 후 실행. 승인 전 실행은 시스템이 차단 |
| C. 이력 필수 | 실행은 담당자/관리자가 하되 감사추적이 반드시 남아야 하는 것 | 불변 로그 + 사유 입력 |

핵심 질문 하나로 판정: **"이게 잘못 나가면 누구 돈이 움직이거나 외부에 문서가 나가는가?"** — 그렇다면 B.

## 2. 현재 시스템 지도 (실사 결과)

### ✅ 승인 체계가 이미 있는 것 (B 구현됨)
| 업무 | 구현 | 비고 |
|---|---|---|
| 품의서 (지출·계약) | pumui_approval — 다단계 결재(상신/승인/반려·사유 필수), **승인 전 전기 서버 차단** | 결재선은 건별 수동 지정 — 기본 결재선 템플릿 없음(갭 ①) |
| IATF 검사서 (IQC/PQC/SPC/부적합) | iatf.approval.mixin 결재선 | 판정 권한의 품질 그룹 제한 여부는 UAT #8 대기 |
| 운영 태스크 (월마감 등) | ops.task todo→done→**approved** (승인자 역할 검사) | 작동 확인됨 |
| 급여 확정 | hr.payslip 표준 흐름 (계산→확정) | 확정 권한 그룹 정리 필요(급여 담당 한정) |

### ⚠️ 승인 없이 실행되는 것 중 B 여야 하는 것 (갭)
| 업무 | 현재 | 위험 | 권장 |
|---|---|---|---|
| **부품 정산서 발행** (vendor.mrp.settlement.wizard) | 회계 사용자면 즉시 매입계산서 발행 | 협력사 대금이 승인 없이 확정됨 | 발행 전 승인 단계(품의 연계 또는 자체 승인) — 갭 ② |
| **톤정산 확정·발행** (raw.material.settlement) | 상태 가드만(재발행 차단은 됨), 승인선 없음 | 수백만 원 단위 대금 단독 확정 | 확정 버튼에 승인 단계 — 갭 ② |
| **가단가→정단가 확정** (_confirm_firm) | 합의근거 문자열 입력만 | 확정 즉시 **소급 정산 자동 발행**(불가역성 높음) | 확정 전 승인 + 합의서 첨부 — 갭 ③ |
| **특채(검사 전 긴급투입)** | 현재 전면 차단(예외 절차 없음) | 현장 긴급상황 대응 불가 or 우회 시도 | 품질팀 UAT #2 결정 후 "권한자 승인+사유+이력" 절차 신설 — 갭 ④ |

### ✔️ 단독 처리가 맞는 것 (A — 현행 유지)
- BR 자동발행(서열 특성상 실시간 무승인 — unique·멱등·no_mo 가시화로 통제), PLC 단위실적, 근태 기록,
  수요 로드·계획 계산(확정 전), 재고 이동(보류 lot 차단은 별도), 검사 기록 "작성"(판정 전 단계)

### ✔️ 이력만 필수 (C — 구현됨)
- 마감 잠금 변경(kr.lock.log 불변 로그, 방향 판별) / 정단가 대체 링크(supersede) / 계획 재계산(채터 각인) /
  삭제 대신 취소+사유(품의 반려사유 필수)
- C 갭: **정산서·계산서 취소/재발행 사유 입력**은 표준 Odoo에 의존 — 사유 필수화 검토(갭 ⑤)

## 3. 결정이 필요한 것 (시스템이 아니라 회사가 정할 것)

1. **결재선 인물 매핑** — 품의 금액구간별 승인자(예: 100만 이하 팀장, 이상 대표), 정산 승인자, 특채 승인자.
   시스템은 준비돼 있고 **누가** 승인자인지가 비어 있음. ※ §8 사용자 권한 UAT와 함께 확정 권장.
2. 정산(부품·톤) 승인을 품의로 태울지, 정산 문서 자체에 승인 단계를 넣을지 — 갭 ②의 구현 방향.
3. 특채 허용 여부와 승인자 (품질팀 UAT #2).

## 4. 실행 순서 제안

1. 대표님이 3장(결재선 인물·정산 승인 방식·특채)을 결정 →
2. 갭 ②③(정산·정단가 승인 단계)을 개발 반영 (승인 전 실행 차단은 품의와 같은 패턴 재사용) →
3. 갭 ①(품의 기본 결재선 템플릿), ⑤(취소 사유 필수화) 후속 →
4. 승인 체계 전체를 품질 매뉴얼·운영 태스크 정의에 반영.
