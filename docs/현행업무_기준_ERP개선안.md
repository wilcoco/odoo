# 현행 업무(회계 담당 확인) 기준 — ERP 개선 가능성과 순서

작성: 2026-08-27 · 근거: 회계 담당자 확인 답변 + 설치 모듈 실사

## 1. 확인된 현행 업무

| 영역 | 현재 방식 |
|---|---|
| 매출 세금계산서 | **대부분 역발행** (공급받는자가 발행) / 우리 발행분은 **스마트빌 또는 홈택스**에서 수동 |
| 매입 세금계산서 | 홈택스·스마트빌에서 확인 |
| 계좌 조회 | 인터넷뱅킹에서 사람이 조회 |
| 이체 | 인터넷뱅킹 수동. **대량이체는 은행 엑셀 양식에 맞춰 작성 후 업로드** |
| ERP 연동 | **없음** — 국세청·은행 사이트에서 별도 작업 |

## 2. 이 사실이 바꾸는 판단

앞선 검토(2026-08-27 오전)는 "발행 API 연동"을 주요 과제로 봤으나, **역발행 중심**이라면
우리가 발행하는 건수 자체가 적어 **발행 자동화의 효익이 낮습니다.** 대신 부담은 다른 데 있습니다:

- 역발행분·매입분을 **홈택스/스마트빌에서 확인해 ERP에 옮기는 일** (반복·누락 위험)
- **대량이체 엑셀을 사람이 작성하는 일** (금액·계좌 오타 = 사고)

→ 개선 우선순위를 **"반입 자동화 + 이체 파일 자동 생성"** 으로 바꿉니다.
둘 다 **외부 계약 없이** 우리 개발만으로 됩니다.

## 3. 개선안 — 3단계

### 1단계 · 계약 불필요 (지금 가능, 합계 3~4주)

| 과제 | 내용 | 근거 |
|---|---|---|
| **A. 대량이체 엑셀 자동 생성** | Odoo에서 지급 대상을 골라 **은행 양식 그대로** 파일 출력 → 은행 사이트에 업로드만. 계좌·금액을 사람이 옮겨 적지 않음 | `account_batch_payment` 설치됨 + `_generate_export_file()` 이 **공식 확장 지점**(주석에 override 용도로 명시). 은행별 양식 모듈만 추가 |
| **B. 역발행·매입분 반입 자동화** | 스마트빌/홈택스 **다운로드 파일 형식 그대로** 읽어 전표 생성·승인번호 기입 | 승인번호 중복차단·매출 백필 매칭·CSV 반입이 **이미 구현됨**. 파일 파서만 추가 |
| **C. 거래내역 업로드 정착 + 자동 매칭** | 은행에서 내려받은 거래내역을 올리면 미수/미지급 후보 자동 제시 | `account_bank_statement_import_csv` 설치됨 |
| **D. 역발행 누락 탐지** | 마감 체크리스트에 **"역발행 미수취 매출"**(매출 전표는 있는데 승인번호 없음) 항목 추가 | 기존 `kr.close.checklist` 9종에 1종 추가 |

> D가 중요합니다. 역발행은 **상대가 발행해 줘야** 성립하므로, 상대가 빠뜨리면
> 우리 매출만 장부에 남고 세금계산서가 없는 상태가 됩니다. 지금은 이걸 잡는 장치가 없습니다.

### 2단계 · 기존 계약 활용 (확인 후 2~3주)

- **스마트빌 API 연동** — 이미 스마트빌을 쓰고 계시므로 **신규 업체 선정이 불필요**합니다.
  계약에 API/연동 옵션이 포함돼 있는지만 확인하면 됩니다.
  - 우리 발행분: ERP에서 발행 → 승인번호 자동 회신
  - **역발행·매입분: 목록 조회 API로 자동 수집** (1단계 B의 파일 작업을 대체)

### 3단계 · 신규 계약 필요 (건수 늘면)

- 계좌 **조회 자동화**(쿠콘·CODEF 류) — 매일 자금 현황을 봐야 할 때 착수
- **펌뱅킹 이체 실행** — 1단계 A(엑셀 자동 생성)로 대부분 해소되므로 **후순위**.
  이체는 오조작 손실이 즉시 발생해 자동화 이득 대비 위험이 큼

## 4. 담당자에게 확인할 3가지

1. **스마트빌 계약에 API(연동) 옵션이 포함돼 있는가** — 2단계 착수 가능 여부가 여기서 갈림
2. **주거래 은행과 대량이체 엑셀 양식 샘플** — 1단계 A는 양식 파일 1개만 있으면 바로 개발
3. **월 건수**: 우리 발행 세금계산서 / 역발행 수취 / 대량이체 실행 — 2·3단계 손익분기 산정용

## 5. 기대 효과 (1단계만으로)

- 대량이체 엑셀 **수기 작성 제거** → 계좌·금액 오타 사고 위험 제거
- 역발행·매입분 **전표 반입 시간 단축** + 중복 등록 차단(승인번호)
- **역발행 누락이 마감 전에 잡힘** (현재는 발견 수단 없음)
- 은행 거래내역이 ERP에 들어오면서 **자금 현황·수금/지급 예정표가 실제로 작동**
