# 발주 없는 매입 UAT 순서서 (사용자 인수 테스트)

서버: http://10.10.21.20/odoo (DB: odoo18) · 작성 2026-08-14
사전검증: 시스템 로직은 자동 검증 완료 — **이 UAT의 목적은 "화면·용어·절차가 실무와 맞는지" 담당자가 확인하는 것**입니다.
시드 데이터: `TEST-` 접두 데이터(품목·협력사·발주·정산서·포털 토큰)가 깔려 있어 3단계부터 바로 시작할 수도 있습니다.

## 준비 (시작 전, 관리자)

1. 역할별 계정 3개 생성: 구매, 생산, 회계 (admin 계정으로 테스트하지 말 것 — 권한 검증 겸용)
2. 각 담당자에게 이 문서와 함께 자기 단계 배정
3. 검증용 임시 데이터는 `TEST-` 접두어 / **아래 '입력 자료 준비물'은 실값으로 입력** (UAT가 곧 실값 구축이 되도록)

## 입력 자료 준비물 — 담당별 (서버 실사 기준 2026-08-14)

이미 들어간 것: 품목 707·BOM 524·작업장 89·금형 19·capability 18·사일로 4·거래처 250.
**비어 있어서 UAT 중 실값으로 입력할 것**:

| 담당 | 입력할 자료 | 어디에 | 관련 단계 |
|---|---|---|---|
| 구매 | **부품 협력사 목록 + 품목 연결 + 계약단가(가단가) + 수지 톤단가** — 실 협력사 2~3곳부터 | 실값입력 템플릿 4·5번 시트 → 구매 화면 | 1단계 |
| 구매 | 포털 사용 협력사 지정(토큰 자동 발급) | 거래처 화면 | 6단계 |
| 품질 | **검사기준 마스터(품목별 검사항목·규격)** — 현재 0건 | IATF 검사기준 메뉴 | 5단계 전 |
| 회계 | 사업자번호 없는 거래처 8곳 보완 | 거래처 화면(체크리스트가 목록 제공) | 7단계 |
| 생산기술 | **기존 입력분 실값 검증**: 금형 형체력·capability 사이클/불량률·품목 최대재고 — 값이 실제와 맞는지 | 계획 마스터 메뉴 | 1단계 |
| 경영지원 | 결재선 템플릿 (대표 결재 결정 후) | 결재선 템플릿 메뉴 | 별도 |
| 인사 | 급여 요율·간이세액 브래킷 (급여 모듈 배포 후) | 급여 설정 | 별도 |

※ 1단계를 TEST 품목 대신 **실 협력사 실값으로 진행하면 UAT 종료 = 실값 구축 완료**가 됩니다.

## 담당자별 요약

| 단계 | 담당 | 소요 |
|---|---|---|
| 1. 마스터 입력 | 구매 + 생산기술 | ~1시간 |
| 2. 생산 실적 | 생산 | ~30분 |
| 3. 부품 정산 | 회계 | ~20분 |
| 4. 단가 소급 | 구매 → 회계 | ~20분 |
| 5. 협력사 납품·검사·사일로 | 자재 + 품질 + 현장 | ~40분 |
| 6. 협력사 포털(협력사 역할) | 구매 2인 1조 | ~30분 |
| 7. 회계 대사 | 회계 | ~20분 |
| 8. 마감 리허설 | 회계 | ~20분 |

## 1단계. 마스터 입력 (구매 + 생산기술)

**입력**: 품목 3개(완제품·외주부품·수지) + BOM 1벌 + 협력사 2곳 + 부품 계약단가(가단가) + 수지 톤단가
- ⚠ 품목 등록 전 「품목 등록 3단 판정 규칙」 시트 확인 (실값입력 템플릿 첫 시트)
- 일부러 **계약단가 없는 부품 1개**를 BOM에 포함할 것 (뒤에서 폴백 경고 검증)

**확인 포인트**
- [ ] 톤단가를 등록하면 그 품목의 "톤당 정산" 표시가 자동으로 켜지는가
- [ ] 화면·용어가 실무와 맞는가 (다르면 기록)

## 2단계. 생산 실적 (생산)

**실행**: 조립 제조오더(완제품 10개) 생성 → 확정 → 완료 처리

**확인 포인트**
- [ ] 완료 즉시 [협력사 정산 적립]에 부품 사용량이 자동 생성됐는가 (수량 = BOM × 10)
- [ ] 계약단가 있는 부품은 계약가로, 없는 부품은 표준단가+경고로 잡혔는가
- [ ] 수지(톤정산 품목)는 부품 적립에서 빠져 있는가

## 3단계. 부품 정산 발행 (회계)

**실행**: 정산 위저드에서 기간·업체 선택 → 매입계산서 발행

**확인 포인트**
- [ ] 금액 검산: 수량 × 계약단가 = **공급가**, 부가세 **별도** 표시 (포함가로 나오면 즉시 보고)
- [ ] **같은 조건으로 한 번 더 발행 시도 → "미정산 데이터 없음" 차단**을 직접 확인
- [ ] 계산서 전기 후 거래처원장에서 미지급금 잔액 = 계산서 총액

## 4단계. 가단가→정단가 소급 (구매 → 회계)

**실행**: 구매가 부품 계약단가에서 정단가 확정(예: 150→165, 합의근거 입력)

**확인 포인트**
- [ ] 확정 즉시 소급 계산서가 자동 발행되는가 (금액 = 기청구 수량 × 단가차액)
- [ ] 같은 행 재확정 시도 → 차단되는가
- [ ] 회계: 소급 계산서 전기 후 원장 반영 확인

## 5단계. 협력사 납품 → 무지(無紙) 입고 → 검사 → 사일로 (협력사 역할 + 자재 + 품질, 2인 1조)

> ※ 무지 입고(ASN·QR·인수확인서) **서버 배포 완료** (2026-08-20 원격 검증: /supplier/asn·
> /supplier/receipts 200, QR 스캔 라우트 정상). 이 단계 전체 UAT 가능.

**실행 순서**

*협력사 역할 (포털, 브라우저/휴대폰):*
1. 【납품 예정 등록】 수지 1,000kg·LOT 기재·도착일·차량번호 입력 → 등록
   - [ ] 등록 즉시 이력에 "납품 예정" 표시
2. 목록에서 [납품 패스] → [ ] 휴대폰에 QR+품목표 화면

*자재(입고 담당) 역할:*
3. 경로 A(QR): 담당자 계정으로 로그인된 태블릿에서 기사 QR 스캔
   - [ ] 입고전표가 **자동 생성되어 화면에 열림** (품목·수량·LOT 프리필)
   - 경로 B(수동): 【구매 > 납품 예정(ASN)】 건 열기 → [입고전표 생성] — 같은 결과
4. 실물 대조 → (차이 시 수량 보정) → [확정]
   - [ ] ASN 상태 "입고 완료" / [ ] IQC 자동 생성 + LOT 품질보류
   - [ ] 위조 QR(주소 조작) 접근 → 404 차단

*협력사 역할:*
5. 포털 【납품 인수증】 → [ ] 방금 건 PDF 다운로드 (수량·LOT·처리담당·IQC 결과 확인)

*품질·현장 (기존 유지):*
6. IQC 합격 전 사일로 적재 시도 → [ ] 차단 / 합격 판정 → [ ] 보류 해제 → 적재
   ★사일로 화면은 자동검증 못함 — 꼼꼼히
7. 회계: 톤정산 집계 → 확정 → 계산서 발행 (톤수 × 톤단가 검산) / 확정 후 재집계 → [ ] 차단

**확인 포인트 (추가)**
- [ ] 담당자 타이핑이 **수량 보정 외 0**인지 (무지 입고의 핵심 지표)
- [ ] 부족 납품(1,000 중 800 도착) 시 800 확정 → 협력사 포털에 **800으로 표시**되는지 (차이 투명성)

*아래 4개는 ⏳ SCM 검토수정(fix/scm-review-9) 배포 후 유효 — 배포 신호 전에는 건너뛸 것:*
- [ ] **같은 품목 2줄** ASN 등록(LOT 다르게) → 전표에 라인 2줄, 각 LOT 정확히 프리필
- [ ] ASN 폼에 수량 0 행 섞어 제출 → **전체 거부** + "N번째 행 오류" 안내, 어떤 행도 등록 안 됨
- [ ] ASN 번호가 `ASN-26-####` 형식으로 이어짐 (상수 중복 없음)
- [ ] 🔒 일반 사무 계정(재고/구매 권한 없음)으로 사내 ASN 열기 → 조회만 가능 (역할 계정 확보 후)

## 6단계. 협력사 포털 — 협력사 역할 체험 (구매 2인 1조)

**준비**: 거래처(TEST-클립텍)의 포털 토큰 링크 확인 → 한 명은 "우리 회사", 한 명은 "협력사" 역할

**협력사 역할(브라우저에서 토큰 링크 접속)**
- [ ] 납품 예정 등록·납품 패스 화면 표시 (배포 완료 — 테스트 가능)
- [ ] 발주 목록에서 신규 발주 확인 → [전체 승인] 응답 제출
- [ ] (우리 회사 역할이 응답 승인한 뒤) 납품/출하 현황에 표시되는가
- [ ] **납품 인수증 메뉴에서 인수확인서 PDF 다운로드** (배포 완료 — 테스트 가능)
- [ ] 참고: 포털 발주 목록에는 외주계획이 자동 생성한 발주만 표시됩니다(수동 발주는 미표시 — 정상)

**협력사 역할 — SCM 검토수정 추가분 (⏳ 배포 후 유효):**
- [ ] 자동발주 건 입고 확정 후 포털 새로고침 → 발주 상태 **"납품완료"**, 대시보드 완료 숫자 +1
- [ ] 포털 대시보드 상태별 숫자 = 발주 목록 동일 상태 필터 건수와 일치
- [ ] 협력사 간 발주 [확정] 후 브라우저 뒤로가기로 재[확정] → 오류 안내, 상태 그대로
- [ ] 출하 완료된 협력사 간 발주에 [취소] 시도 → 차단
- [ ] 발주 폼에 수량 0 또는 과거 납기일 입력 → 차단 메시지

**우리 회사 역할**
- [ ] 협력사 응답 수신 → 승인 → 완료 처리 흐름
- [ ] (⏳ 배포 후) 【구매】 공급망 경로 "공급 단계 보기" 버튼 → 단계 목록 정상 표시

## 7단계. 회계 대사 (회계)

**확인 포인트**
- [ ] 3중 대사: 사용실적 합계 = 계산서 공급가 합계 = 거래처원장 미지급금 (1원 단위 일치)
- [ ] 발행 계산서가 매입매출장·부가세 집계에 잡히는가
- [ ] 전표 조회 화면에서 해당 전표가 일자별로 조회되는가

## 8단계. 마감 리허설 (회계)

**실행**: 일부러 0원 청구서 1건 생성 → 마감 전 체크리스트 열기

**확인 포인트**
- [ ] 체크리스트가 0원 청구서·미전기 결제·잔액 불일치를 잡아내는가
- [ ] 항목 정리 후 마감 잠금 설정 → 과거일자 전표 입력 시도 → 차단되는가
- [ ] 잠금을 **되돌리기(과거로) 시도 → 차단**되는가 (보안 모듈 — 잠금 예외 절차 안내가 뜨는지)
