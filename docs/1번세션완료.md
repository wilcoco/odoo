## 3. 적발·수정 3건 (코드, push 완료)
1. **[운영결함] injection_costing — 실측중량이 영원히 표준 폴백**: PLC 는 record 를 mo_id=계획MO/unit_mo_id=단위MO 로 저장하는데 원가엔진이 mo_id 로만 검색 → 실측이 안 잡혔음. unit_mo_id 포함 검색으로 수정. 수정 후 src=plc 확인. (escon e4d9399)
2. **injection_planning — 계획→MO 사출필드 유실(단독설치 폴백 경로)**: 호기/금형/교대/is_injection_mo 전달 + 생성실패 채터 가시화. 풀스택에선 worksite 의 planning_run_bridge 가 우선하므로 영향 없음. (wilcoco feat/e2e-sim-fixes)
3. **engel_injection — 사출품 자동 LOT 생성 제외**: confirm 시 LOT-YYYYMM 임의 명명 lot 생성 → escon_serial 14자리 체계 밖 lot 발생. 사출 MO/사출품은 스킵(시리얼 발행은 escon_serial 소관). (동일 브랜치)

## 5. 2번 세션에 제안하는 보완 (다른 시각에서 봐줄 것)
1. **계획 MO 완료 시점의 재고 이중계상 검증**: 단위 MO 가 실물 재고(+5)를 만들었는데, 계획 MO(200개, progress 상태)를 나중에 완료 처리하면 재고가 또 생기는지 — 계획 MO 의 done 경로 차단/우회 정책을 확인·보강해줘. (시뮬에선 계획 MO 를 done 으로 만들지 않았음)
2. **worksite bridge 와 planning 폴백의 이중 유지보수**: generate_manufacturing_orders 가 두 곳(injection_planning 원본, worksite bridge 오버라이드)에 있다 — 한쪽 수정이 다른 쪽에 누락되기 쉬운 구조. 공통 훅(_get_mo_vals)으로 합치는 리팩토링 검토.
3. **production.record 무결성**: 시뮬은 record 를 수동 생성했지만 실제는 PLC 컨트롤러 경유 — record 없는 완료 단위 MO(백필 직후 등)의 원가 커버리지%가 낮게 나오는 상황에 대한 알림/재수집 절차가 있는지 점검.
4. **품의 결재선 기본값**: 시뮬에선 결재선을 수동 지정 — 부서/금액별 기본 결재선 템플릿이 없으면 운영에서 매번 수동. iatf_approval 에 기본 결재선 규칙 추가 검토.
5. **매출 세금계산서 흐름**: 매출 쪽은 kr_approval_number 수기 입력이었음 — 홈택스 발행분 업로드→고객 청구서 매칭 흐름(매입은 있음)의 매출판 필요 여부 판단.
6. **BR 발생 단계**: FDW 설치된 환경(운영)에서 BR→사출계획 연결 리허설은 아직 아무도 못 돌려봄 — 운영 점검 항목으로.
7. 시뮬 데이터가 sim_e2e_1 에 그대로 있으니, 위 항목 검증 시 재사용 가능 (계획 MO=WH/MO/00069, 시리얼 1526071870010x, 정산·소급 계산서, 품의 PUM-2026-000x).
