# 협력사 SCM 포탈 — 사용자 테스트(UAT) 순서서

> 테스터가 **협력사 담당자 역할**로 포탈을 처음부터 끝까지 따라가는 대본.
> 브라우저(PC/휴대폰)만 있으면 되고 별도 앱 설치 없음. 각 단계 ✔는 "이렇게 보이면 정상".
> 서버: http://10.10.21.20 · 기준일: 2026-08-20

## 0. 시작 전 준비 (관리자/사내에서 미리 — 테스터는 안 함)

- [ ] 테스트 협력사 파트너 생성: 이름 `TEST-협력사A`, **협력사 포탈 사용 ✓**, 접속 토큰 발급
- [ ] 그 협력사가 납품하는 품목 매핑(supplierinfo) 1~2개 (ASN 품목 선택지에 나오게)
- [ ] 원청(에스콘)→협력사 **자동발주 1건** 시드 (아래 2단계에서 응답할 대상)
- [ ] 2-tier 테스트용 하위 협력사 `TEST-협력사B` 1개(포탈 사용 ✓) — 5단계에서 사용
- [ ] 테스터에게 전달: **포탈 접속 URL**(토큰 포함) 한 줄. 예:
      `http://10.10.21.20/supplier/portal?token=<발급토큰>`

> 접속 링크만 있으면 됩니다. 로그인 아이디/비번은 협력사용이 아니라 토큰 방식입니다.

## 1. 접속 & 대시보드 (모든 협력사 공통 첫 화면)

1. 전달받은 URL 클릭 → 포탈 대시보드 진입
   - [ ] ✔ 상단에 협력사명(TEST-협력사A) 표시
   - [ ] ✔ **발주 현황** 카드: 응답필요·검토중·반려됨·확정완료·납품완료 숫자
   - [ ] ✔ 금주 납품 일정, 알림 영역 표시
   - [ ] ✔ (잘못된/만료 토큰으로 접속 시) "유효하지 않은/만료된 접근 토큰" 안내 — 위조 차단

## 2. 원청 발주 응답 — 「에스콘에서 받은 발주」

원청이 생산계획으로 자동발주한 건을 협력사가 확인·응답하는 핵심 흐름.

1. 좌측/상단 메뉴 **[에스콘에서 받은 발주]** 클릭 → 발주 목록
   - [ ] ✔ 0단계에서 시드한 자동발주 1건이 "응답 필요" 상태로 보임
2. 발주 클릭 → 상세 (품목·수량·희망납기)
3. 응답 제출 — 세 가지 중 택1:
   - **전체 승인**: 요청대로 납품 가능 → 제출
     - [ ] ✔ 상태가 "검토중"으로 바뀜(사내 승인 대기)
   - **조건부 승인**: 수량/납기 수정해 제출 → [ ] ✔ 수정값이 응답에 반영
   - **납품 불가(반려)**: 사유 입력 → [ ] ✔ 상태 반려로 표시
   - [ ] ✔ **(배포 후)** 잘못된 입력 시 화면에 사유 안내 표시 (⑨ 수정분)

## 3. 무지(無紙) 입고 — 납품 예정 등록 → QR → 인수증  *(서버 배포 완료·검증됨)*

협력사가 실제 납품할 때 종이 명세서 대신 쓰는 흐름. 사내 입고 담당 1인과 2인 1조 권장.

*협력사 역할:*
1. 메뉴 **[납품 예정 등록]** → 도착예정일·차량정보 입력, 품목·수량·LOT 입력(최대 5줄) → 등록
   - [ ] ✔ 이력에 "납품 예정" 배지로 즉시 표시, 번호 `ASN-26-####`
   - [ ] ✔ **같은 품목 2줄(LOT 다르게)** 등록도 정상 접수 (⑤)
   - [ ] ✔ 수량 0/빈 품목 섞어 제출 → **전체 거부 + "N번째 행 오류" 안내**, 일부만 등록 안 됨 (⑨)
2. 이력에서 **[납품 패스]** → 휴대폰에 대형 QR + 품목표 화면
   - [ ] ✔ 기사에게 보여줄 화면이 뜸

*사내 입고 담당 역할:*
3. 담당자 계정으로 로그인된 태블릿/폰 카메라로 그 QR 스캔
   - [ ] ✔ 입고 전표가 **자동 생성되어 화면에 열림** (품목·수량·LOT 프리필)
   - [ ] ✔ 같은 품목 2줄도 각 LOT 정확히 프리필 (⑤)
4. 실물 대조 후 [확정] → [ ] ✔ ASN "입고 완료", IQC 자동 생성 + LOT 품질보류

*협력사 역할:*
5. 메뉴 **[납품 인수증]** → 방금 건 PDF 다운로드
   - [ ] ✔ 공급자/인수자/일시/수량/LOT/처리담당/IQC결과/서명란 포함

## 4. 납품/출하·입고 현황 조회

1. **[납품/출하 현황]** → 납품 예정·완료 목록
   - [ ] ✔ 승인된 건은 예정에, 완료 건은 완료에 (최근 30일)
   - [ ] ✔ **(배포 후)** 입고 확정 시 상태가 "납품완료"로 정확히 바뀜 —
         분할 납품이면 잔량 남는 동안은 완료로 안 바뀜 (④ 수정분)

## 5. 협력사 간 2-tier 거래 (협력사A ↔ 하위 협력사B)

협력사가 자기 하위 업체에 다시 발주/수주하는 흐름 (다층 공급망).

*보낸 발주(A가 B에게):*
1. **[보낸 발주]** → [새 발주] → 공급업체 B·품목·수량·납기 입력 → 등록
   - [ ] ✔ 목록에 "발주완료"로 생성, B에게 알림
   - [ ] ✔ **(배포 후)** 수량 0/과거 납기 입력 → 차단 + 사유 안내 (⑥⑨ 수정분)

*받은 발주(B 역할로 재접속해서 — B 토큰 URL):*
2. **[다른 업체에서 받은 발주]** → 해당 건 → [확정] → [ ] ✔ "확정"
3. → [출하] → [ ] ✔ "출하", A에게 출하 알림
   - [ ] ✔ **(배포 후)** 이미 확정된 건을 뒤로가기로 다시 [확정] → 오류 안내, 상태 안 꼬임 (⑥)
   - [ ] ✔ **(배포 후)** 출하 완료 건 [취소] 시도 → 차단 (⑥)

*입고 확인(A 역할로 돌아와서):*
4. **[입고 현황]** → 출하된 건 → [입고 확인] → [ ] ✔ "입고완료", 날짜 기록

## 6. 공급망 단계 & 이슈 보고

1. **[공급망]** (진행중/완료/취소 필터) → 내가 담당하는 단계 목록
2. 담당 단계에서 [확정]/[출하]/[완료] 순차 처리
   - [ ] ✔ 각 단계 상태 전이, 다음 단계에 알림
3. 문제 발생 시 [이슈 보고] → 사유 입력 → [ ] ✔ 상태 "이슈", 사내 통지

## 7. 재고 현황

1. **[재고 현황]** → 협력사가 담당하는 품목의 입고예정/출고예정/가용 집계
   - [ ] ✔ 대시보드·발주 목록과 숫자 기준 일치 (③ 수정분 — 배포 후 특히 확인)
