# 통합 후 전체 검토 — 새 세션용 프롬프트 (머지 완료 후 그대로 붙여넣기)

---

담당 개발자가 우리 작업 브랜치들을 main에 머지 완료했다. 너는 지금부터 **통합 후 독립 검토자** 역할이다. 이 작업들의 원작성 세션이 아니므로, 작성자를 변호하지 말고 **적대적으로 깨뜨리는 관점**으로 검토해라. 해피패스 통과만 보고 완료 선언하는 것을 금지한다. 통과 못 한 항목은 통과 못 했다고 정직하게 기록해라.

## 환경
- 작업 루트: `~/cams-odoo` (Docker Compose: `cams-odoo-odoo-1`=Odoo18, `cams-odoo-db-1`=PG)
- 저장소 2개:
  - **escon-odoo/odoo_gh** → 로컬 `~/cams-odoo/odoo_gh` (remote 이름 `escon`)
  - **wilcoco/odoo** → 로컬 `~/cams-odoo/_incoming/wilcoco_odoo` (remote `origin`) — ⚠️ 이 클론의 워킹트리는 다른 세션이 사용 중이니 **checkout 금지, `git worktree`로만** 작업
- DB: `cams`(개발 실DB)·`cams_demo`(테스터) — **이 둘엔 파괴적 작업 절대 금지(읽기만)**. 검토는 스테이징 복제본에서.
- Odoo 셸/업그레이드 패턴 (비번은 `~/cams-odoo/odoo.conf` 참조):
  - `docker exec cams-odoo-odoo-1 python3 /mnt/odoo/odoo-bin -c /etc/odoo/odoo.conf -d <DB> -u <modules> --no-http --stop-after-init --db_password=<odoo.conf 값>`
  - 셸: 같은 명령에서 `shell` 서브커맨드, heredoc 입력 시 `docker exec -i`
  - SQL: `docker exec cams-odoo-db-1 psql -U odoo -d <DB> -tAc "..."`
- 마운트: `/mnt/addons_custom`=odoo_gh/odoo_plugins, `/mnt/addons_wilcoco`=addons_custom(wilcoco 사본)

## PHASE 1 — 머지 무결성 (코드 레벨)
1. 두 저장소 `git fetch` 후, 아래 8개 브랜치의 커밋이 **전부 main에 포함**됐는지 확인 (`git log main..<branch>` 가 비어야 함):
   - odoo_gh: `fix/settlement-review`, `feat/provisional-pricing`, `feat/injection-costing`, `feat/injection-actual-cost`, `feat/plc-weight-capture`
   - wilcoco: `fix/sim-found-defects`, `feat/planning-safety-nets`, `feat/planning-optimization`
2. **충돌 해결 3곳 검증** (injection_worksite — 3브랜치 공유 구역, 사람 손을 탔음):
   - `__manifest__.py` 버전이 단일값(권장 18.0.3.0, 최소한 2.5 이상 단일)으로 정리됐는가
   - `models/product_template.py` 와 `views/product_template_views.xml` 에 `settle_by_ton` 과 `is_injection_part` **둘 다** 존재하는가 (한쪽 유실 = 머지 사고)
   - `migrations/18.0.2.4/post-flag_injection_parts.py` 존재하는가
3. **유실 스캔**: main 최종본에 다음이 존재하는지 grep — `machine_mold_capability_cost_bridge`(표준원가 브리지), `_plc_backfill_get_or_create_unit_mo`·`weight_is_measured`(백필/실측), `provisional.price.mixin`·`_create_retro_settlement`·`retro_bill_id`(소급), `_flag_injection_products`(사출품 플래그), planning의 `plan_issues`·`_suitable_caps`·`x_clamping_force_ton`(안전망/최적화). 하나라도 없으면 🔴 머지 유실.

## PHASE 2 — 스테이징 설치·마이그레이션 리허설
1. 스테이징 DB 생성(cams 복제): `docker exec cams-odoo-db-1 createdb -U odoo -T cams cams_stg` (접속 중이면 pg_dump/psql 경유). **이후 모든 파괴적 검증은 cams_stg에서만.**
2. main 코드로 `-u injection_worksite,injection_costing,gh_provisional_pricing,gh_vendor_settlement,injection_planning` → 에러 0 + **18.0.2.4 마이그레이션 실행 로그** 확인.
3. 백필 결과: `SELECT default_code,is_injection_part,tracking FROM product_template WHERE is_injection_part;` — 금형/capability 걸린 품목만 TRUE+serial, 완제품/외주/수지는 미변경이어야.

## PHASE 3 — e2e 흐름 재현 + 적대 공격 (cams_stg)
`회사운영_전체시뮬레이션_원가통합.md` 9단계를 통합본에서 재현: 기준정보→생산계획(수요→BOM전개→배정)→사출(PLC 실측 마커·불량)→재고떨기→소요통보→입고→월마감(생산량 정산+톤정산)→표준vs실제 원가→소급.
각 단계에서 **일부러 깨뜨려라** (전부 시도하고 결과 기록):
- 정산 매입계산서 **동시 5클릭** → 1장인가 (threading+registry.cursor 병렬 트랜잭션)
- 원가 재집계·정산·소급 **재실행 멱등** / 소급전표 **반려(button_cancel) 후 재실행** 시 재발행되는가(유실 금지)
- **미지 시리얼(prefix 2, 14자리) 백필** → 단위 MO 소급 생성 + done 후 재전송 = already_processed ack
- 같은 품목에 **활성 BOM 2개** 만들고 계획 계산 → 경고 채터 뜨는가
- **수요 품번 미매핑**(가짜 품번) Oracle 수요 → 제외 보고 채터
- 형체력: 요구 형체력 > 사출기 형체력 조합 → 배정 제외되는가 / 대수요 → 2대 병렬 분산되는가
- 원가 **대사 정합**: 모든 행에서 (실제−표준)=가격+수량+능률, 월마감 recon_ok 전건
- 소급: frozen 불변 + restated 반영 + retro_diff 정확

## PHASE 4 — 회귀 가드 (하나라도 깨지면 "통합 보류" 판정)
1. **회계 무변경**: 원가·소급 작업 전후 `stock.valuation.layer` 건수와 원가법(`standard`/`manual_periodic`) 불변 — 관리원가는 회계 정본이 아니어야 함(재무제표 영향 0).
2. **tracking=serial 후폭풍**: 정상 PLC 완료(`action_complete_unit_mo`)에서 완제품 시리얼(lot_producing_id) 자동 지정으로 완료가 막히지 않는가. 조립 MO(사출품 소비)도 가상LOT→시리얼 대치 흐름이 성립하는가.
3. 기존 기능: 금형교체 최소화·교대 타임라인·정산 위저드·이종검사 연동 필드(`is_injection_part`) 조회 — 회귀 없음.

## 산출물·규칙
- 결과는 `docs/통합후_전체검토_리포트.md` 로 작성: PHASE별 표(✅/🔴), 결함은 **재현 절차·원인·수정안** 포함, 마지막에 종합 판정(통합 승인 / 조건부 / 보류)과 근거.
- 결함 수정 시: **main 직접 push 금지** — `fix/post-merge-review` 브랜치(worktree) → PR. 수정 후 해당 항목 재검증까지가 완료.
- 금지: Enterprise 소스 커밋 / credential 하드코딩·문서 기재 / cams·cams_demo 파괴적 작업 / 다른 세션 워킹트리 checkout.
- 검증 데이터는 가능한 한 rollback으로 원복하고, 스테이징 DB는 검토 종료 후 보고서에 폐기 여부를 명시해라.

시작 전에 PHASE 1 결과(머지 포함 여부·충돌 3곳)를 먼저 보고하고, 이상 없으면 PHASE 2로 진행해라.
