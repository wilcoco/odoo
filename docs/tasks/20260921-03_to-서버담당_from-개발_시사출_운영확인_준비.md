# 시사출 운영 확인 — 9/22(화) 준비·수행·기록 (2026-09-21 작성)

**전제**: 운영은 옛 코드(0b36e7f: injection_worksite 8.8.0, injection_planning 1.11.0, escon_bom_util 2.5.0). 이번 릴리스(PR #9/#10)는 리허설 전이라 내일 아침까지 운영 코드를 바꾸지 않는다. 내일의 목적은 **실제 사출이 일어날 때 지금 운영 기능이 어디까지 받아 주는지 관찰하고 기록**하는 것이다. 운영 데이터를 SQL 로 고치거나 새 모듈을 넣지 않는다.

| # | 확인 | 어디서 | 기준 |

| P8 | 사전 카운트 기록(§4 SQL) | 읽기 전용 | 전후 비교용 |

## 2. 내일 수행 순서 (현장 + 원도영 + 사용자)
| 단계 | 하는 일 | 봐야 할 것 | 기록 |
|---|---|---|---|
| S1 | 계획 MO 생성(사출 계획 실행 또는 수동 계획 마법사) | MO 에 사출기·금형·사출 BOM 이 붙는다. BOM 없음 경고가 뜨면 P1 미비 | 화면 캡처, MO 번호 |
| S2 | 작업장 화면에서 사출기 선택 → 작업 시작 | 진행 중 MO·금형·작업자 표시 | 시각 |
| S3 | 실제 사출 시작(PLC 가 요청/완료 신호 전송) | 단위 MO 가 완료마다 생성·완료, 시리얼 발행, 화면 실적 증가 | 첫 3건의 시각·시리얼, go_relay 로그 |

## 3. 문제가 나면
- 그 자리에서 고치지 않는다. 증상·화면·시각·MO/시리얼 번호를 적고 계속 진행한다(우회 가능하면 우회).
- 옛 코드에서 이미 알려진 것(릴리스에 고쳐져 있음): (a) 작업장을 지정해 MO 를 만들면 호기 번호가 0 으로 남을 수 있음, (b) PLC 완료 신호의 호기 표기가 정규화되지 않아 양품 원천 대사가 안 맞을 수 있음, (c) 계획 재고 계산이 캐시 때문에 틀릴 수 있음, (d) 사출 BOM 이 아닌 표준 BOM 을 잡을 수 있음. 이런 증상이 나오면 "릴리스에서 수정됨" 으로 분류한다.
- 나머지는 새 결함으로 큐에 올린다. 개발이 정본에서 재현·수정한다.

## 4. 전후 카운트 SQL (읽기 전용, 원도영)
```bash
docker exec -e PGOPTIONS='-c default_transaction_read_only=on -c statement_timeout=15000' postgresdb psql -U odoo -d odoo18 -P pager=off -Atc "
select now()::text
union all select 'MO 사출 계획|'||state||'|'||count(*) from mrp_production where is_injection_mo and not coalesce(is_ip_unit_mo,false) group by state
union all select 'MO 사출 단위|'||state||'|'||count(*) from mrp_production where coalesce(is_ip_unit_mo,false) group by state
union all select '생산 실적(production_record)|'||count(*) from injection_production_record
union all select '시리얼(LOT)|'||count(*) from stock_lot
union all select '사일로 투입 로그|'||count(*) from injection_silo_load_log
union all select '사일로 잔량|'||name||'|'||coalesce(current_qty::text,'') from injection_stock_silo
union all select 'PLC API 로그|'||count(*) from injection_api_log
union all select '정지 기록|'||count(*) from injection_suspend_history
order by 1;"
```
테이블명이 다르면 그 줄만 빼고 실행(모듈 구조가 옛 버전이라 다를 수 있음).

## 6. 참고: PLC 계약(운영 코드 기준)
- `GET /api/plc/request?machine_no=<호기>&...` → 진행 중 계획 MO 확인, 시리얼 발행(`serial_full`, `work_order_no`, `weight_upper/lower`).
- `POST /api/plc/complete` (JSON-RPC, bearer) `{serial_full, work_order_no, machine_no, final_result(OK/NG), status, weight...}` → 단위 MO 완료·실적 기록. 같은 request_id 재전송은 멱등.
- 모사 도구 `fake_plc/injection_api_tester.py` 로 사전 점검 가능(운영에는 쏘지 않는다. 필요하면 복제본에서).
