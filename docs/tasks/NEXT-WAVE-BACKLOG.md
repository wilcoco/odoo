## NW-1 관리 BOM 변경 이력 (사용자 결정 2026-09-17: "다음 웨이브에 넣어둬")
- **배경**: 활성 관리 BOM 을 화면에서 직접 고치면 개정번호가 오르지 않고 이전 내용이 BOM 에 남지 않는다([새 버전] 은 있으나 강제 아님). 과거 MO·정산은 스냅샷으로 안전하지만, IATF 변경관리(8.5.6) 심사와 협력사 대사 분쟁에서 "언제 누가 왜 바꿨나"를 BOM 에서 못 꺼낸다.
- **채택안**: (b) 자동 이력 — 직접 수정은 허용하되 바뀔 때마다 이력을 남긴다. (a) 잠금은 채택하지 않음(오타 수정 마찰).
- **테스트 케이스(수용 기준)**:
  1. 관리 BOM(직서열·사출품·일반 조립)의 수량·부품·단위·하위 BOM 을 화면에서 수정하면, 이전 값·새 값·변경자·시각·사유가 이력에 남는다.
  2. 이력은 사용자가 지우거나 고칠 수 없다(관리자 포함).
  3. [새 버전] 으로 바꾼 경우도 같은 이력에 "개정 n → n+1" 로 남는다.
  4. 특정 날짜(예: 지난달 말)의 BOM 내용을 이력에서 재구성해 볼 수 있다.
  5. Odoo 표준(미분류) BOM 은 대상이 아니다.
- **의존·범위**: escon_bom_util 확장(운영 미러의 PLM 위에), 새 모델 1개(이력 행). 스냅샷 로직(MO·정산)은 무변경.
- **선행 자료(2026-09-17 사용자 전달)**: 장우영 작성 `Odoo PLM EX 개발자료`(plm_ex개발설명.pptx). 원래 목표는 "설계팀 권한만 BOM 수정 + 관리자 승인 + 변경 이력, ECO 로 관리·전자결재로 승인" 이었으나 실제 구현은 hr_department 의 `업무상세 팀 여부`·hr_employee 의 `work_level` 필드까지에서 멈추고 "Odoo 기본 기능으로 대체" 로 목표가 바뀜. 모듈(GH_MLP_EX)은 정본·미러 어디에도 없음(폐기). NW-1 은 이 원래 목표의 후속이며, 승인은 기존 전자결재(pumui_approval·escon_eapproval), 권한은 escon_bom_util 의 관리부서 접근 믹스인을 재사용한다. 엔터프라이즈 `mrp_plm`(ECO) 채택 여부는 착수 전 비교표로 결정(버전마다 BOM 레코드를 새로 만드는 방식이 관리번호·활성 규칙과 충돌 가능).
- **기존 훅(2026-09-17 확인, 설계 전제)**: 운영 설치 모듈 `iatf_change_management` 18.0.1.0.0 의 `mrp.bom.write` 가 라인·수량·유형·공정 변경 시 변경요청(CR, state=draft)을 자동 생성하고, 미승인 CR 이 있으면 같은 품목 BOM 의 후속 수정을 차단한다. CR 은 제품명·수량·라인 개수만 기록(라인 내용 없음)하고 첫 수정은 승인 없이 통과. NW-1 착수 시 결정: 이 훅을 라인 스냅샷과 사전 승인으로 승격할지, 걷어내고 전자결재로 대체할지. 운영 CR 누적 건수는 원도영에게 확인 요청.
- **상태**: 대기. R145 운영 반영 완료 후 착수.
