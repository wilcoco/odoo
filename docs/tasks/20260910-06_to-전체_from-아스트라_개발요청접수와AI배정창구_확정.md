# 개발 요청 접수·AI 배정 창구 확정

사용자가 직접 다음과 같이 확정했습니다.

> 원도영도 개발할 것을 깃에 올리면 아스트라 (너)가 받아서 각 에이아이에게 할당하여 작업

이후 개발 요청은 다음 순서로 진행합니다.

1. 원도영님을 포함한 요청자가 `handoff`의 `docs/tasks`에 아스트라 앞으로 요청을 등록합니다. 목적·문제·원하는 결과·관련 저장소와 모듈·제약을 요약하고 상세 자료는 원본 링크로 연결합니다.
2. 아스트라가 사용자에게 먼저 알리고 작업 범위·우선순위를 협의합니다. 이미 합의한 범위는 반복 승인받지 않습니다.
3. 아스트라가 구현 담당 AI와 검증 담당, 원본 저장소·모듈, 범위, 완료 조건을 정해 배정합니다. 원래 요청 ID와 배정 기록을 연결하고 중복 착수를 피합니다.
4. 원도영님 측 AI를 포함한 각 AI가 배정된 범위에서 작업하고 결과를 아스트라에게 회신합니다. 각 AI가 새 요청을 독자적으로 골라 구현하거나 다른 AI에 재배정하지 않습니다.
5. 아스트라가 결과와 검증 근거를 취합·검토하고 사용자에게 보고합니다. 코드·상세 기록은 해당 작업 브랜치의 PR로, 승인된 운영 반영은 서버 담당 절차로 진행합니다.

공통 지침과 작업 기록 양식, AGENTS.md·CLAUDE.md에 반영했습니다.

- [작업 기록](https://github.com/wilcoco/odoo/blob/8ab3924b3d7138e2a9dbfe7015e7ced376291f13/docs/tasks/작업/docs/dev-handoff-20260910.md).

이 변경은 요청·배정 창구의 통일입니다. ERP와 MES의 원본 저장소 구분, PR 검토·병합, 배포 저장소 동기화, 운영 반영 승인 절차는 유지합니다. 이미 합의·배정된 작업은 이어서 진행합니다.

앞서 요청한 공통 지침 초안 PR을 생성할 때도 같은 브랜치의 최신 커밋을 포함해 주세요. 별도 문서 브랜치는 만들지 않습니다. 원도영님 측 AI 참여 연결 요청은 `20260910-05_to-전체_from-아스트라_원도영측AI_참여연결요청.md`에서 계속 관리합니다.
