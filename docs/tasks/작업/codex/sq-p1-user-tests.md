# SQ P1 업무 증빙 사용자 시험 절차

대상은 `8070 / odoo18_test`에 P1을 적용한 뒤의 화면입니다. 현재 문서는 적용 전 시험안이며, 실제 8070 브라우저 검증 완료를 의미하지 않습니다. 운영 주소에는 적용하지 않습니다. 기존 UT3C 자료·평가서·생산지시·BR·이종검사·재고는 유지합니다.

## 접속과 역할

1. 승인된 시험 적용 완료 후 `http://10.10.21.20:8070/web/login?db=odoo18_test`에 접속합니다.
2. 아래 업무 담당 계정으로 로그인합니다. 암호는 기존 비공개 계정 전달본을 사용합니다. 이 문서와 Git에는 암호를 싣지 않습니다.
3. 회사명이 `에스콘 [시험DB]`인지 확인합니다. 시험 자료의 이름에는 `[시험] P1`을 붙입니다.
4. 승인 단계는 작성자와 다른 계정으로 별도 브라우저 프로필에서 진행합니다. 작성자가 승인자 비밀번호를 공유받아 대신 승인하는 업무 절차가 아닙니다.

| 역할 | 계정 | 담당 |
|---|---|---|
| 기준문서 | t3.document | 승인 기준서·시험계획 원본 등록 |
| 검사 담당 / 검토 / 책임자 | t3.qc / t3.qclead / t3.qcmgr | 한도견본·정기시험, 2인 검토·승인 |
| 생산기술 담당 / 책임자 | t3.eng / t3.engmgr | 건조·분쇄·도면·지그 기준과 점검 |
| 사출 작업 / 반장 | t3.injworker / t3.injlead | 현장 자재·건조 점검 |
| 보전 담당 / 책임자 | t3.maint / t3.maintmgr | 금형 세척·온도·시사출·지그 |
| 인사 담당 / 책임자 | t3.hr / t3.hrmgr | 자격 사전평가·교육 이력 |
| 경영 승인 | t3.ceo / t3.opsdir | 정성품질 연간 계획·포상 승인 |

## 공통 입력·반려·개정

원본 기준은 기존 **IATF → 문서관리**에서 작성합니다. 문서의 ‘품질 증빙 용도’를 선택하고 품번·유효기간·기준값·측정 방법·근거 파일을 입력합니다. 문서 담당자가 검토 요청하고 지정된 문서관리 책임자가 승인합니다. 타사 예시값이나 미정 기준값을 실제 기준처럼 입력하지 않습니다.

업무 기록에는 실제 LOT·일자·작업장/설비·담당자를 입력합니다. 생산 LOT가 없는 시험실 검사 등은 ‘해당하지 않는 근거’에 실제 사유를 기록합니다. 이 칸은 누락된 양산 LOT를 대신하는 우회 수단이 아닙니다.

업무 기록의 결재선에 순서대로 승인자를 지정하고 **검토 상신 → 다른 계정으로 승인 → 작성자 또는 담당자의 검증 완료**를 진행합니다. 반려된 기록은 사유에 맞게 보완하고 다시 상신합니다. 승인 후 완료한 기록은 직접 수정하지 않고 **새 개정/정정 개정**을 사용합니다. 이전 개정의 값·판정·첨부·승인 기록이 그대로인지 비교합니다.

## 설비가 없는 경우와 설비 연결 뒤

이 시험은 업무 기록·승인·추적·이력 보호를 검증합니다. 사람이 관찰할 수 있는 점검은 실제 관찰값으로 입력하고, 현장 실측이 불가능한 항목은 미실시 또는 합성 시험임을 명시합니다. 생산 일보 대조 화면은 데이터를 만들지 않습니다. 샷 원천과 품질 검사는 기존 수집·매칭 경로를 그대로 사용하므로, 장비가 멈춰 있으면 수신이 정상이라고 판정할 수 없습니다.

설비 연결 뒤에는 별도 현장 인수시험으로 원천 샷 이벤트 키·발생/수신시각·LOT 매칭, 지연 품질 수신, 재전송 중복 방지, 실제 중량·수분·카운터와 화면 값을 대조합니다. 이 결과를 별도로 기록하기 전에는 물리 설비 연동 검증 완료로 서명하지 않습니다.

## 결과·원복 기록

각 시나리오에서 담당자/승인자, 기록 번호, 실제 입력값, 예상 결과, 실제 결과, 화면 증거, 재시험 여부를 남깁니다. 합성 자료는 실제 생산 실적이나 SQ 합격 증빙으로 제출하지 않습니다.

8070 적용 전 DB·파일 저장소·기존 코드·전체 그룹 구성 백업이 필요합니다. 이상이 발생하면 현재 사용자 입력을 먼저 보존하고 별도 복원 DB에서 확인합니다. 복제 DB의 `pre-p1-clone.dump`로 공유 8070을 덮어쓰지 않습니다. 신규 모듈 제거는 새 기록을 삭제하므로 기본 원복 방식이 아닙니다.

원복과 적용의 실제 SHA·백업 경로·검증 결과는 같은 브랜치의 `sq-p1-canonical.md` 및 미러 작업 문서에 기록합니다.
