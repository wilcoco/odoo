## 목적과 범위

- Codex와 Claude가 작업 시작 시 같은 handoff·브랜치·워크트리·문서화 규칙을 발견하게 한다.
- 코드와 병합 단위 문서를 같은 브랜치에서 검토하도록 루트 지침, 템플릿, PR 체크리스트를 연결한다.
- 이번 요청 자체가 문서 체계 구축이므로 이 브랜치의 산출물은 문서이며, 다른 코드 작업과 분리한
  보조 문서 브랜치는 아니다.
- Odoo 런타임 코드와 데이터는 변경하지 않는다.

## 통합 영향

상태·수량·LOT·품질·전표·권한의 런타임 영향은 없다. 향후 해당 축을 건드리는 작업이 문서와 검증
증거를 남기도록 머지 게이트에 포함했다.

## 변경 내용

- `AGENTS.md`, `CLAUDE.md`: 에이전트의 필수 시작 컨텍스트
- `docs/tasks/AGENT_MERGE_WORKFLOW.md`: 두 저장소 공통 운영 매뉴얼
- `docs/tasks/작업/`: 브랜치별 기록 규칙과 템플릿
- `.github/PULL_REQUEST_TEMPLATE.md`: PR 시 작업 문서와 정본·미러·검증 확인

## 정본·미러 대응

- `escon-odoo/odoo_gh`의 동일명 브랜치에도 같은 매뉴얼과 저장소별 에이전트 진입점을 반영한다.
- 런타임 모듈 포팅은 없으며 두 문서 버전의 운영 규칙을 일치시킨다.

## 검증 증거

- 코드 커밋: 이 문서를 포함한 브랜치 HEAD
- DB/환경: 문서 전용 변경으로 해당 없음
- 실행 명령: `git diff --check`, 필수 파일·링크·브랜치명 수동 대조
- 결과 및 로그/산출물: 커밋 전 검사 결과를 PR에 기록
- 미실행 검증과 이유: Odoo 런타임 변경이 없어 서버/DB/브라우저 검증은 미실행

## 배포·롤백

- 모듈 업그레이드/마이그레이션: 없음
- 재기동 및 확인: 없음
- 롤백 조건/방법: 문서가 실제 개발 흐름을 방해하면 해당 문서 커밋 revert
- 사람 승인: PR 머지로 승인

## 남은 위험과 후속 작업

- GitHub branch protection이나 CI 강제는 이번 범위에 포함하지 않았다. 현재는 에이전트 컨텍스트와 PR
  템플릿으로 준수 여부를 확인한다.
- PR 및 handoff 회신: 브랜치 푸시 후 링크를 원 요청 또는 후속 `to-서버` 요청에 기록한다.
