## 목적과 범위

- 해결할 문제
  - 오두 엔터프라이즈 **차입금 관리**(`account_loans`)는 승인하면 상환 일정대로 전표를 만든다.
    더존 이관 전표가 이미 원장에 있는 기간에는 이자·상환이 이중 계상된다.
  - 표준 차입금에는 **대주(거래처)·이자율 필드가 없고**, 만기 동액 연장(차환)과 만기 미정 약정을 표현할 수 없다.
  - 표준 `action_confirm` 은 생성 전표 중 전기되지 않은 것이 있어야만 상태를 '실행 중'으로 바꾼다.
    건너뛰기(`skip_until_date`)가 모든 회차를 덮으면 **오류 없이 초안에 머문다.**
  - 토지처럼 감가상각을 하지 않는 자산, 그리고 **자산(필지)별로 계정과목을 나누는 운영**을 표준만으로는 못 한다.
- 변경 범위: 신규 모듈 2개
  - `addons_custom/account_kr_plus_patch_loans` — 차입금(대출)
  - `addons_custom/account_kr_plus_patch_ncasset` — 비유동자산(고정자산)
  - 둘 다 `account_kr_plus_patch` 에 의존하고 `auto_install: True` 라 함께 설치된다. 엔터프라이즈 전용.
- 변경하지 않는 범위
  - `account_kr_plus_patch`, `account_kr_reports`, `account_kr_guard` 소스는 건드리지 않는다(커뮤니티 설치 유지).
  - 표준 전표 생성 구조(원금을 장기 계정에서 빼고 지급액을 단기 계정에 대기)는 그대로 둔다.
    우리 방식(대변 보통예금)으로 바꾸는 작업은 이관 종료 후 별도 과제.
  - 운영 DB 데이터는 이 브랜치에서 바꾸지 않는다. 재분류 전표는 **초안만** 만들고 전기하지 않는다.

## 통합 영향

- 상태 전이: `account.loan` 승인 경로가 바뀐다. 기준정보 전용은 전표 없이 `running`,
  표준 경로는 super 호출 후 상태가 `draft` 로 남은 경우에만 `running` 으로 보정한다.
- 수량·재고: 영향 없음.
- LOT·시리얼 추적: 영향 없음.
- 품질 승인·기록 보호: 영향 없음.
- 납품·정산·전표: 기준정보 전용에서는 전표를 만들지 않는다. 재분류 마법사는 **초안 전표만** 만든다(전기 없음).
- 권한·회사 분리: 신규 모델 3종에 `account.group_account_invoice`(읽기)·`account.group_account_manager`(전체) 접근을 준다.
  자산별 계정은 자산의 회사(`company_id`)로 만든다.

## 변경 내용

- 변경 모듈/파일
  - `account_kr_plus_patch_loans`: `models/account_loan.py`(확장 + `account.loan.rate` 신규),
    `models/account_loan_line.py`, `views/account_loan_views.xml`, `security/ir.model.access.csv`,
    `tests/test_kr_loans.py`, `README.md`
  - `account_kr_plus_patch_ncasset`: `models/account_asset.py`(확장 + `account.asset.kr.account` 신규),
    `models/res_company.py`, `wizard/asset_reclass_wizard.py`, `views/account_asset_views.xml`,
    `views/res_company_views.xml`, `wizard/asset_reclass_wizard_views.xml`,
    `security/ir.model.access.csv`, `tests/test_kr_ncasset.py`, `README.md`
- 설계 결정
  - **모듈을 둘로 나눈다.** 차입금과 고정자산은 의존 모듈(`account_loans` / `account_asset`)과 운영 주체가 달라
    각각 켜고 끌 수 있어야 한다. 둘 다 `auto_install` 이라 운영에서는 `account_kr_plus_patch` 와 함께 들어온다.
  - **기준정보 전용(`kr_manage_only`)을 기본값으로 둔다.** 이관 기간의 기본 사용법이 '전표는 이관 자료,
    차입금 화면은 대장'이기 때문이다. 이관이 끝나면 끄고 `건너뛰기` 날짜를 그 시점으로 둔다.
  - 표준 검증은 그대로 두되, **만기 미정(`kr_open_ended`)일 때만 '원금 합계 = 차입금액' 검증을 건너뛴다.**
  - 자산별 계정 코드는 **기준 계정 코드 + 자산 일련번호**로 만들고 계정 유형·조정 여부·태그를 물려받는다.
    코드 접두사가 유지되므로 재무상태표(KR)처럼 코드로 매핑하는 보고서에서 성격이 바뀌지 않는다.
  - 재분류는 **초안 전표만** 만든다. 검증이 끝난 기간으로 소급하지 않도록 일자를 사람이 정하고 사람이 전기한다.
- 데이터/호환성
  - 신규 필드 `kr_manage_only` 의 기본값 `True` 는 기존 약정 행에도 적용된다(컬럼 추가 시 기본값 반영).
    이미 있는 약정 9건은 설치 후 그대로 기준정보 전용이 된다.
  - 대주·이자율·차환 연결은 값이 없으면 비어 있다. 운영 데이터 보정은 별도 스크립트로 한다(이 브랜치 범위 밖).
