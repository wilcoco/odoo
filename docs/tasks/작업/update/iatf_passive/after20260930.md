## 구현과 업무 영향

신규 `iatf_passive_verify_test` 앱은 설치 시 회사별 패스를 기본 활성화하고 홈 화면에 **IATF 패스 검증**을 표시한다. 내부 사용자는 허용 회사의 로그를 조회하고, 시스템 관리자는 **패스 설정**에서 회사별로 끌 수 있다. 설정 변경을 기록하며 비활성 이후에는 기존 IATF 처리가 복원된다. 이미 진행한 재고·업무는 되돌리지 않는다.

| 경계 | 활성 시 동작 |
|---|---|
| IQC 입고 준비 | 검사대기 위치 전환을 저장점에서 실행·관찰한 뒤 되돌리고 원래 입고 위치에 전기한다. 이 경로의 신규 입고는 IQC 관리 표시/초안이 남지 않고 관찰 로그를 남긴다. |
| IQC 재고·LOT | 검사대기 이동, IQC 가용재고 및 품질 보류 LOT 투입 검증 실패를 기록하고 계속한다. 기존 LOT 보류 사유·상태를 해제하지 않는다. |
| 공정 시작 | 이전 공정 IPQC 불합격 검증을 통과해도 해당 검사의 `fail` 판정은 유지한다. |
| 출하 | OQC·포장/라벨 승인, 검사 수량, IATF 조립제품 재고·예약 검증 실패를 기록하고 계속한다. 검사/승인을 합격으로 만들지 않는다. |
| BOM 변경 | 미승인 IATF 변경요청에 의한 수정 잠금과 자동 변경요청 생성 실패를 분리한다. BOM 핵심 저장은 기존 ORM 경로를 사용한다. |
| 자동 후처리 | PQC/IPQC·추적 이력·금형 타수·관리계획·PPAP·교육/포장 경고·SPC·NC·LOT 보류 증빙 생성, Engel 금형/추적/SPC 실패를 저장점으로 되돌리고 기록한다. 성공한 후처리는 기존대로 적용한다. |

품질 문서를 직접 판정·승인·완료하는 검증과 증빙 수정·삭제 보호는 유지한다. 금융·정산 오류, Odoo/BOM 핵심 처리, MES 자체 완료 조건은 패스 대상이 아니다. 업무 원본 권한 및 회사·제품·LOT 식별 검사를 먼저 수행한다. 분리된 IATF 기준 조회 또는 자동 품질 후처리의 권한 오류는 기록 후 통과할 수 있으나, 원본 업무 권한·인증·SQL 오류를 일괄 무시하지 않는다.

## 로그와 원본 연결

- `iatf.passive.log`: 통과 일시, 회사/사용자, 분야, 내용, 오류 유형/메시지, 메서드 지점, 원본 모델/ID/이름, 소스 줄 번호, traceback.
- **원본 레코드**, **원본 첨부파일** 버튼은 원본 권한 검사 후 해당 업무와 첨부파일을 연다. 첨부파일의 당시 내용 전체를 별도 복제하지는 않는다.
- `iatf.passive.source`: 당시 IATF/Engel Python 소스 파일 전체, 상대 경로, 파일명, SHA-256. 같은 경로·내용은 재사용한다.
- 로그·소스 스냅샷 및 연결된 스냅샷 첨부파일을 일반 수정·삭제하지 못하도록 보호한다. 로그 생성은 내부 서비스만 수행한다.
- 로그 저장 실패 시 업무를 중단한다. 이후 핵심 업무가 실패해 외부 트랜잭션이 롤백되면 로그도 롤백되므로, 모든 실패 시도의 독립 감사 저장소는 아니다.

## 적용·복구·남은 위험

설치/업그레이드는 실제 WSL 대상 DB와 `addons_path`를 확인한 뒤 기존 경계 변경 모듈을 갱신하고 신규 앱을 설치해야 한다. 파일 복사만으로는 모델·메뉴·권한이 반영되지 않는다. 이 PC WSL 적용 및 재기동은 사용자가 승인했으며 원격 운영 서버를 대상으로 하지 않는다.

가장 먼저 회사 설정을 꺼 향후 호출을 기존 검증으로 복원할 수 있다. 코드·DB 복구가 필요한 경우 적용 전 백업과 코드 스냅샷을 대응시키고 적용 후 발생한 로컬 업무 데이터를 확인해야 한다. 변경된 로컬 DB를 운영 DB로 대체하지 않는다.

활성 상태에서는 미검사/미승인 출하, 보류 LOT 사용, IQC 격리 없는 입고 및 자동 품질 증빙 누락이 가능하다. 패스 로그는 품질 적합성이나 IATF 충족 증명이 아니며, 업무 담당자가 실제 검사·승인·증빙 보완 대상을 확인해야 한다. 모드 해제로 과거 업무를 자동 취소하거나 누락 검사를 소급 생성하지 않는다. 격리 합성 시험과 localhost 화면 확인은 실제 스캐너·설비·운영 통합 및 현장 인수시험과 구분한다.

## MES의 IATF 보류 재검사 연결

- odoo_gh 원본 MES 코드의 품질 보류 조건 7곳을 선택적 `stock.lot._iatf_quality_hold_blocks(message)`로 연결했다.
- `gh_total_mes` 18.0.1.40: EJ 검사 2곳, 생산 완료 1곳. `injection_worksite` 18.0.8.11.5: 양품 LOT 가용성 1곳, SILO 3곳.
- 패스 앱 미설치/회사 비활성 시 기존 차단 유지. IATF hold만 통과하며 MES 양품/NG/수량/원천 검증은 유지. BR의 held/good 재고 분류는 변경하지 않음.
- MES는 odoo_gh의 원본 앱이므로 정본 addons_custom에 중복 복사하지 않는다. 이 배포 전용 연결은 미러 커밋과 함께 검증한다.
- MES 호출 지점의 Python 원본 파일도 로그에 SHA-256 스냅샷으로 보관한다.
