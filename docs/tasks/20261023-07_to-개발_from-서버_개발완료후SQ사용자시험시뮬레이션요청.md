# 개발 완료 후 SQ 사용자 시험 시뮬레이션 요청

사용자 직접 요청: “개발 다되면 클로드 개발 세션에 사용자 테스트 시뮬레이션 하라고 해줘”.
대상은 참여자 문서의 Claude 개발 세션입니다. 이 요청을 접수하고, 아래 시작 조건을 확인한 뒤 사용자 관점의 독립 시험을 진행해 주십시오.

## 현재 상태와 시작 조건

현재 P0는 8070 적용 완료, P1·서류 출력은 코드 후보·격리 검증 완료이고 공유 8070 적용은 대기 중입니다.
지금은 시험 시나리오와 역할·데이터 준비 범위를 검토해 주십시오. **이 문서의 게시 자체를 개발 전체 완료나 공유 8070 적용 완료로 간주하지 마십시오.**

시험 시작은 서버의 후속 준비 완료 회신에서 다음을 확인한 이후입니다.

1. P1·서류 출력 범위의 개발과 개발자 회귀 검증 완료, 차단 결함 또는 보류 범위의 명시.
2. 승인된 절차로 시험 환경 적용 완료: 대상 URL·DB·정본/미러 SHA·모듈 버전·백업·그룹 변경 기록·기동 확인.
3. 시험 가능 기능과 사람의 확정값/실물 장비가 필요한 항목 구분. D-24·D-38 미확정은 임의 숫자로 해소하지 않으며 제안 OFF 유지.

이번 사용자 요청은 독립 사용자 시험의 요청입니다. **운영 배포·PR 병합·공유 시험 서비스 적용 및 재시작의 별도 승인으로 사용하지 않습니다.** 적용 담당자가 준비 완료를 회신하기 전에는 현재 8070에서 후속 후보의 시험을 시작하지 마십시오.

## 사용자 시험 범위

단순 모델 호출이나 완료 상태 직접 변경으로 끝내지 말고, `t3.*` 실제 업무 역할로 로그인하여 UI 입력·제출·검토·반려·재승인·완료를 수행하십시오. SQL은 읽기 전용 대조에 사용하고, 상태·수량·승인을 직접 써서 시험을 통과시키지 마십시오.

| 시나리오 | 사용자 흐름과 확인 사항 |
|---|---|
| UAT-01 역할·결재 | 계획/반장/작업자/품질/구매/영업/회계/인사/SQ/결재권자별 접근과 자기 승인·승인 순서·타 회사 접근 차단. 권한 부족은 관리자 전환으로 우회하지 않고 결함으로 기록 |
| UAT-02 생산계획·BOM | 수동 계획 입력 → BOM/수요 확인 → 신규 생산지시 생성 → 진행/종료. 양품 0 종료 차단, MO 수량 잠금, BOM 활성·삭제·이력 보호, 기존 생산지시·BR·이종검사 보존 |
| UAT-03 사출·품질 | 투입 LOT → 설비 미가동 수동 입력 경로 → 생산 실적 → 초중종물/불량/보류·해제·폐기 승인 → 가용 재고. 실제 PLC 수신과 수동 시험 결과를 구분 |
| UAT-04 조립·출하 | 사출/협력사 부품 투입 → BR·품번 이종검사(오품 차단 포함) → 조립 실적·검사 → 포장·출하 → 생산 LOT 추적 |
| UAT-05 SCM·수지 | 부족 수요 → SCM 통보·발주 초안 → 입고·수입검사·재고 → 생산 투입. 수지 9톤 이하 재주문·20톤 초안 규칙 및 중복 발주 방지, 원재료 LOT/성적서 연결. 외부 메일·포털 통보 실발송은 실행하지 않음 |
| UAT-06 정산·업무 회귀 | 출하/입고 증빙 → 정산·결재·마감, 전표/잠금 권한. 연차 2단계 승인 및 반려 재신청, 전자결재·기존 재고/양품 수량 회귀 |
| UAT-07 일상관리·P1 | 실제 생산 흐름에서 생성한 LOT·일자·설비·담당자를 사용하여 점검표/정기 시험/한도견본/건조·배합·분쇄/지그·용기/도면·검사협정/정성품질/지도점검 기록을 작성·승인. 완료 스냅샷·개정·이력 변경 차단, 평가원식 대조 화면 5종 확인 |
| UAT-08 SQ 증빙·평가 | 새 합집합 85항목 전체에 대해 원천 메뉴·입력 절차·생성 레코드·항목 증빙 연결·권한·기간/회사 필터 확인. 준비현황 → 증빙 열기 → 평가서 답변 → 검토/반려/재승인/발행. 자료 없음/미연결/현장 확인 필요를 합격으로 바꾸지 않음 |
| UAT-09 출력·업로드 | 467행 연결표 전수 대조, 28개 원문 분류·실제 어댑터별 대표 출력과 예외 시험. 점검표 격자/실측/실제 결재3칸/개정·약도, ZIP 업로드 멱등·변경파일 새 초안, 기간별 심사 ZIP·목차·미비목록·원본 연결. 개별 양식 미시험 건은 별도 표시 |

설비가 없을 때는 구현된 수동 입력 경로만 이용하고 시험 데이터로 명확히 구분하십시오. PLC 지연 수신·샷 자동 매칭·물리 스캐너·프린터·실제 설비 정지 등은 장비 연결 후 재시험 목록으로 남기며, 화면 시뮬레이션으로 실물 검증을 대체하지 않습니다. 기초 자료가 없어 진행하지 못하는 경우 필요한 자료·담당자·입력 메뉴를 기록하십시오.

## 공유 데이터와 보호 조건

- 시험 대상은 준비 완료 회신에서 확인한 8070 `odoo18_test`입니다. 포트 없는 운영 DB는 대상이 아닙니다.
- 새 시험 데이터는 충돌 여부를 확인한 고유 접두어 `UT3C-UAT-<실행일시>`를 사용하고 생성 ID를 기록하십시오. 기존 `UT3C`·`[시험]UT3C` 자료, 발행 평가서 `AUD-2026-0017`, `SQ준비 | …` 정의27/할 일27/역할7은 삭제·이름 변경하지 마십시오.
- 기존 생산지시·BR·이종검사·재고·결재·연차 원본을 시험용으로 수정하지 말고, 독립 시험 데이터와 실제 흐름으로 만들어진 변화량을 구분해 확인하십시오.
- D-24 미정22건 및 D-38 임계값은 그대로 보존하고 `proposal_enabled=False`를 유지하십시오. 승인되지 않은 숫자나 데모 실적을 SQ의 실제 증빙으로 확정하지 마십시오.
- 세 결재 계정의 교체 암호는 대표가 비공개로 전달합니다. 암호를 큐/PR/스크린샷/시험 결과에 넣지 마십시오.
- 결함 수정은 원도영 개발 측에 재현 절차와 함께 회신합니다. 본 시험 요청을 근거로 다른 세션이 코드·역할·정책을 임의 변경하거나 운영에 반영하지 않습니다.

## 회신 요청

먼저 접수 여부와 시험 시나리오 보완을 회신하고, 준비 완료 회신 후 위 시나리오를 수행하십시오. 최종 회신에는 다음을 포함하십시오.

- 실제 시험 URL/DB/적용 SHA/모듈 버전/시험 일시와 사용 역할(암호 제외).
- 시나리오 ID별 절차·입력값·기대 결과·실제 결과·통과/실패/보류·생성 레코드 ID·화면/로그 근거.
- 85항목 전수표: 항목 코드 → 업무 메뉴/입력 → 증빙 레코드 → SQ 조회/평가 결과 → 부족사항/담당자.
- 467행 출력 연결표의 실검증 범위, 미시험/양식 부적합/필수 자료 누락 목록.
- 결함 등급·재현 절차·수정 담당·재시험 결과, 기존 자료 보존 대조, 실장비 연결 후 남은 시험.
- 코드 검증·화면 사용자 시험·운영 적용·현장 인수의 상태를 나누어 판정하십시오. 결과는 이 파일 아래 회신하고, 긴 표/증거는 첨부 또는 해당 작업 브랜치 문서로 연결하십시오.
