# 전체 수정 후 7일 재시험·재개발 반복 — 사용자 지시

사용자가 '진행하고 수정사항 다 개선 후 다시 7일 시뮬레이션 돌려보고 수정사항 나오면 다시 개발하고 정리'하라고 명시 승인했습니다. 기존20260911-06 운영기준과07 대기해소 지시를 실행하며 아래 절차로 계속합니다.

1. 개발은 맡은 결함과 BR 기능을 구현하여 작은 후보 SHA·실행로그·문서로 제출합니다.
2. 테스트는 무발주 주간 E2E를 먼저 준비/실행하고 후보마다 독립 시험합니다. 실패는 재현조건·기대값·실제값·로그·SHA를 개발과 아스트라에 전달합니다. 이미 배정된 반례시험은 후속 승인을 기다리지 않습니다.
3. 아스트라가 후보를 검토·통합한 SHA를 제공하면, 테스트는 새 격리 DB에서 전체7일 정상 및 불량/지연/보류/반품/정산차이 경로를 재실행합니다. 아스트라는 결과 대사·최종판정을 맡습니다.
4. 실패가 있으면 해당 결함을 개발에 다시 배정하고 수정→독립재시험→전체합본을 반복합니다. 아무 변경 없이 전체시험을 무한 반복하지 않습니다.
5. 자료가 없어 시험하지 못한 항목은 명시하고 자동합격/강제상태조작/기준완화로 통과시키지 않습니다. 실제 회사정책 변경이 필요하면 아스트라에 먼저 보고합니다.
6. 수정 이유·전후 흐름·가정·시험근거·SQ/IATF 연결·메뉴 사용절차를 코드와 함께 문서화합니다. 단순 단위시험 통과를 전체 운영완료로 보고하지 않습니다.

아스트라가3분 주기 회수·후속배정 감시를 재개했습니다. 각 세션은 지정 격리공간/개별DB와 local exchange만 사용하고, 별도UAT로 통합합니다. 기존 운영 코드/DB는 변경하지 않습니다. 착수/진전/실패/후속필요사항은 Git 큐로 회신하십시오.
