# 21. SQ 합집합 마스터·외부지적 적재 사양 (2026-10-23, claude-test → 원도영 세션)

배정 087(대표 결정: "어디에든 있는 항목은 전부 합집합으로 파악해 개발에 연동").
**우리 평가서를 Ver5.1 로 교체하지 않는다.** 합집합 마스터를 새 개정으로 추가하고, 각 출처 번호를
별칭으로 붙이고, 외부 평가·지적을 항목별 레코드로 연결한다. 코드 변경은 최소(필드 3개 + 신규 모델 1개).

데이터: 같은 폴더의 CSV 4종. 생성 스크립트 `sq_union_build.py`(읽기 전용, 원본 무수정).

## 1. `sq.standard` — 새 개정 2건 (기존 개정은 보관)

| 필드 | 사출 | 전기조립 |
|---|---|---|
| `name` | 사출 합집합 2026-10 | 전기조립 합집합 2026-10 |
| `industry` | INJ | ASM |
| 항목 수 | **49** | **34** |
| 비고 | HKMC Ver5.1(47) ∪ 우리 48 | SW 조립장 준비 LIST_250912(34). 우리 36 과의 대응은 **미확인**(§6) |

기존 개정(사출 48·조립 36)은 **지우지 않는다** — 발행된 평가서 AUD-2026-0017 이 그 개정을 참조한다.

### 적재 매핑 (`union_items.csv` → `sq.item`)
| CSV 열 | `sq.item` 필드 | 비고 |
|---|---|---|
| `union_code` | `code` | `INJ.` / `ASM.` 접두어는 기존 규칙에 맞춘다 |
| `area_no`·`area_name` | `area_id` | 영역 마스터에 없으면 생성 |
| `name` | `name` | |
| `requirement` | `requirement` | **원문 그대로** |
| `points_union` | `points` | Ver5.1 과 우리 배점이 다른 3건은 **max** 로 제안(아래) |
| `in_ver51`·`in_ours`·`in_prep_list`·`note` | `note` 또는 전용 Boolean | 추적용 |

**배점이 다른 3건(제안=max, 확정 필요)**

| union_code | 항목 | Ver5.1 | 우리 | 제안 |
|---|---|---|---|---|
| `6_5` | 자격인증 | 20 | 30 | 30 |
| `6_7` | 품질실적 점검(우리 6_8) | 20 | 10 | 20 |
| `6_9` | 3정 5행(우리 6_10) | 20 | 10 | 20 |

**사내 추가 2건**: `6_X1` 정기적 품질 교안·교육(우리 6_6, 10점) · `6_X2` 주요 품질현황 수평전개(우리 6_11, 10점).
→ 합집합 배점 합계는 1000 을 넘는다(Ver5.1 1000 + 사내 20 + max 보정 20 = **1040**).
**환산은 Ver5.1 방식을 따른다**: `취득 / (배점합 − 해당없음 배점) × 1000`
(근거: 지금강 659.5 / (1000−60) × 1000 ≒ 700.4, 평가서 기재값과 일치).

## 2. `sq.item.alias` — 필드 3개 추가

없으면 추가: `source`(Selection) · `external_code`(Char) · `basis`(Selection: 동일문구/키워드/추정).
`source` 값: `HKMC-Ver5.1` · `OURS-48` · `OURS-36` · `SW-PREP-250912` · `GUMGANG-FOLDER` ·
`CREA-DOCLIST` · `CREA-REVIEW`.

`item_alias.csv` 를 그대로 적재. `union_code` 가 빈 행(크레아 서류 일람 5건)은 **항목이 아니라 서류 구간**이라
`sq.item.alias` 가 아닌 메모로 남기거나 `union_code` 없이 보관한다.

## 3. 신규 모델 `sq.external.finding`

```
_name = 'sq.external.finding'
item_id          Many2one sq.item          (union_code 로 매칭, 빈 값 허용)
source           Selection  지금강평가-Ver5.1 / 지금강지적 / 크레아지적-사출 / 크레아지적-도장 /
                            에스콘지도점검 / SW조립1차평가 / 크레아리뷰 / 평가원관점
evaluated_party  Char       지금강 / 크레아 / 에스콘 / SW조립장 / (일반)
date             Date
external_code    Char       출처 자체 번호(예: NO.12, 1_7, 5-12)
rating           Char       이행상태·점수(있을 때만. 예: "일부미흡 13.5/30")
text             Text       지적·관찰 **원문**
improvement      Text       개선안 원문
status           Selection  미조치(기본) / 조치중 / 완료
action_ids       One2many   iatf.corrective.action (재사용)
evidence         Char       근거 파일 경로
```

- `external_findings.csv` 199행 적재. **한 지적이 여러 항목에 걸치면 이미 행이 나뉘어 있다**
  (예: 지도점검 NO.12 → `2_1`·`2_3`·`6_5` 3행, `external_code` 는 `NO.12` 로 동일).
- 준비현황·평가서 화면에서 해당 `item_id` 의 finding 을 **"외부 지적" 탭**으로 보여 준다.
  평가서의 제안 사유에 `source=에스콘지도점검` 건을 우선 노출(우리 자신에 대한 지적이라서).
- `status` 기본값 **미조치**. 조치는 `iatf.corrective.action` 으로 연결(신규 결재 모델 만들지 않음).

## 4. 기준값

- 각 영역 모델(19 §1 P1)의 기준 테이블로 적재하되, **모델이 아직 없는 것**은 임시 테이블
  `sq.standard.value`(`union_code` · `parameter` · `value` · `source` · `decision_needed`)에 둔다.
- `standard_values.csv` 는 **에스콘 값 / 타사 참고값 2열**이다. 적재 시
  `escon_value` 가 `(미정)` 인 **22건은 `decision_needed=Y`** 로 들어간다 → D-24 결정 대기 목록이 곧 이 22건이다.
- **값이 서로 충돌하는 것**(적재 전 확인): 건조 온도·시간(크레아 ↔ 금강 두 벌) · 호퍼 필터 주기(크레아 ↔ 금강) ·
  조도 측정시간대(금강 기준서 ↔ 지금강 개선안) · 조도 기준값(에스콘 범위 ↔ 금강 1000Lux).

## 5. 적재 후 검증 쿼리

```python
env['sq.standard'].search_count([('name','like','합집합 2026-10')])            # 2
env['sq.item'].search_count([('standard_id.name','like','사출 합집합')])        # 49
env['sq.item'].search_count([('standard_id.name','like','전기조립 합집합')])     # 34
env['sq.item.alias'].search_count([])                                          # 199 (− union_code 빈 5건 = 194)
env['sq.external.finding'].search_count([])                                    # 199
env['sq.external.finding'].read_group([], ['id'], ['source'])                  # §3 표와 일치
env['sq.external.finding'].search_count([('item_id','=',False)])               # 도장 전용·서류구간만
env['sq.standard.value'].search_count([('decision_needed','=',True)])          # 22
# 환산 검증(지금강 재현): 659.5 / (1000-60) * 1000 ≈ 700.4
```

## 6. 애매한 대응 (사람 확인 필요)

| 건 | 내용 |
|---|---|
| **조립 34 ↔ 우리 36** | 8070 `sq.item` 이 **「SQ 기준 관리자 / SQ 조회·평가」 그룹 부재**로 t3 계정 전부 Access Denied. 2건 차이가 무엇인지 미확인. `in_ours=미확인` 으로 적재하고 그룹 부여 후 재대조 |
| 조립 배점 | 준비 LIST 에 배점 열이 없다 → `points_union` 공란. 조립 평가서 원본(배점 포함)이 필요 |
| 크레아 지적 `1_1~1_4` | 사출·도장 평가서가 공유하는 항목인지 **파일에 명시가 없다** → `basis=추정` |
| 크레아 지적 도장 17건 | 사출 대응 항목 없음 → `union_code` 공란 유지 |
| 크레아 서류 일람 5구간 | 항목 코드가 아니라 서류 묶음 번호 → 별칭 `union_code` 공란 |
| 평가원 관점 12행 | 슬라이드의 "구분/요구사항/점검내용" 을 **내용 기준으로** 항목에 배정했다(파일에 항목번호 없음) → `basis=추정` |
| Ver5.1 `1_4` 취약시간대 | 우리 마스터에 없던 항목. 합집합에 포함했으나 **배점(10)·담당·증빙 규칙이 미정** |
| 사내 추가 `6_X1`·`6_X2` | Ver5.1 에 없어 외부 평가에서는 점수가 안 나온다 → **사내 관리 항목으로만** 쓸지 결정 필요 |
