## 3. 심사 패키지 ZIP 확장 사양 (`cams_sq` `action_sq_package`)

평가원이 **서류 일람 순서로** 열 수 있어야 한다. 현재 `assessment.csv` · `evidence.json` · `attachments/` 에
**서류별 출력물**을 더한다.

```
SQ_심사패키지_<업종>_<개정>_<발행일>.zip
├─ 00_목차.csv                     # doc_id · 서류명 · union_code · output_type · 파일경로 · 상태
├─ 00_assessment.csv               # (기존) 항목별 판정·점수
├─ 00_evidence.json                # (기존) 증빙 규칙 충족 내역
├─ 01_생산조건관리/
│   ├─ 1_1_관리계획서.pdf           # iatf.control.plan 리포트
│   ├─ 1_1_공정FMEA.pdf             # iatf.fmea 리포트
│   ├─ 1_1_작업표준서.pdf           # iatf.document 업로드 원본
│   ├─ 1_1_설비일상점검표_2026-10.pdf  # iatf.check.record 리포트(월 묶음)
│   └─ …
├─ 02_검사시험/ … 06_품질경영체제/
└─ 99_미비/
    └─ 미비목록.csv                # 출력물 없음 — 사유(업로드 누락 / 모델 없음 / 외부·수동)
```

**규칙**
1. 폴더는 **영역 번호 + 영역명**, 파일명은 **`<union_code>_<서류명>`** 으로 시작 → 평가원이 평가표 번호로 바로 찾는다.
2. 한 서류가 여러 항목에 걸리면 **첫 항목 폴더에 실물**을 두고 나머지 폴더에는 `00_목차.csv` 로만 참조(ZIP 중복 방지).
3. `output_type`
   - 보고서 → 그 시점 데이터로 **PDF/xlsx 생성**
   - 업로드 → `iatf.document` 최신 승인본 **원본 파일**
   - 조회·내보내기 → **xlsx 내보내기**
   - 외부·수동 → 생성하지 않고 `99_미비/미비목록.csv` 에 "외부·수동" 으로 기록
4. **기간 지정**: 패키지 발행 시 `date_from`·`date_to` 를 받아 일/주/월 주기 서류는 그 구간만 묶는다
   (평가원이 "26년 일보 기준 설비 점검표" 를 보는 방식 — 평가원 관점 ⑤).
5. **결재란**: 리포트 머리에 작성·검토·승인 칸을 둔다. 참조 양식 전부가 그 3칸을 갖고 있고,
   지금강 Ver5.1 지적도 "기록양식 보완을 통한 객관적 입증" 을 요구한다.
6. **미비목록을 반드시 넣는다.** 빈 항목을 숨기면 평가 때 더 나쁘다 — 사유를 적어 낸다.
7. 패키지 발행 이력은 `sq.assessment` 에 남기고, 발행 후 **원본 교체 금지**(이력 불변 규약 ⑨).

**검증**: `00_목차.csv` 행 수 = `sq.doc.requirement` 건수(해당 업종), `99_미비` 사유 합계 + 생성 파일 수 = 총 서류 수.
