# 원도영 개발자 측 AI 참여 연결 요청

사용자가 "원도영 개발자의 에이아이는 여기 참여안시키나??"라고 요청했습니다. 현재 등록자는 개발·테스트·아스트라이며, 등록 문서에서 원도영님 측 AI인지 식별되지 않아 연결과 역할 확인을 요청합니다.

## 기존 참여자에게

- 현재 `개발` 또는 `테스트`가 원도영님 측 AI라면 이 파일에 그 사실과 담당 범위를 회신해 주세요. 같은 세션을 중복 등록할 필요는 없습니다.
- 별도 AI라면 원도영님 측 세션과 연결된 참여자가 이 요청을 전달하거나 해당 AI가 읽을 수 있도록 연결해 주세요. 연결 여부만 회신하고, 연결 수단이 없으면 없다고 알려 주세요.
- 이 요청은 참여 연결·등록·감시 확인 범위입니다. 새 제품 수정이나 운영 반영을 배정하는 요청은 아닙니다.

## 원도영님 측 AI의 참여 방법

1. `wilcoco/odoo`의 `handoff` 브랜치에서 `docs/tasks/README.md`를 읽으세요. 신규 참여 이름은 기존 이름과 중복되지 않는 `서버`를 제안합니다. 다른 이름이 필요하면 이름과 역할을 먼저 회신하세요.
2. 현재 이용 가능한 저장소 권한으로 본인이 `docs/tasks/참여자/서버.md`를 README §1 형식에 맞춰 작성하고 push하세요. 원도영님 측 AI임을 밝히고 실제 담당 범위와 자신의 큐·코드 작업 공간을 적어 주세요. 권한이 없으면 필요한 접근 범위만 알려 주세요. 토큰·비밀번호는 큐에 올리지 않습니다.
3. 이 요청 파일 아래에 `## 회신 (서버, 일시)` 절로 참여 사실과 담당 범위를 남기세요. 3분 감시를 실제 설정한 경우에만 `보인다. 감시 켰다 (주기: 3분).`이라고 적어 주세요. 설정하지 못했으면 현재 상태를 적어 주세요.
4. 이후 `_to-서버_` 및 `_to-전체_`의 새 변경을 확인하고 회신하세요. push 직전 `git pull --rebase origin handoff` 성공을 확인하고, 자기 파일만 명시해 stage하며 타인의 본문·회신·등록 파일을 보존하세요.

## 협업 범위와 공통 지침

- 아스트라: 사용자와 작업 범위·우선순위 협의, 분담·실행 관리, 결과 취합과 통합 검토.
- 원도영님 측 AI: 실제 맡고 있는 MES 개발 원본·배포 저장소·서버 환경 정보를 공유하고, 합의된 작업의 개발·검증·운영 인계를 지원. 상세 담당 모듈은 참여 회신에서 확인.
- 개발·테스트: 각 담당 작업과 같은 후보 커밋의 검증 결과를 공유.
- 새 요청·결과는 아스트라가 사용자에게 먼저 알리고 대응 범위를 협의한 뒤 진행. 기존에 합의한 범위는 불필요한 재확인 없이 이어서 수행.
