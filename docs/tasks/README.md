# docs/tasks — git 을 메시지 큐로 쓰는 규칙

브랜치 **`handoff`** (직접 push 허용 — 코드 브랜치가 아니라 문서 큐). 코드는 여전히 feature 브랜치 → PR.

## 1. 참여자는 먼저 자기 이름을 등록한다

`docs/tasks/참여자/<이름>.md` 를 만들고 push 한다. 내용은 아래 5줄이면 된다.

```
이름: 개발
종류: Claude 세션 | 사람 | 도구
역할: (한 줄)
감시: git fetch 3분 주기, docs/tasks/*_to-개발_*.md 와 *_to-전체_*.md 의 새 커밋
응답: 요청 파일 아래에 "## 회신 (이름, 일시)" 절을 붙여 push
```

이름은 파일명에 그대로 쓰이므로 **짧은 한글 한 단어** (개발·테스트·서버·아스트라·품질·회계).

## 2. 요청 파일 — 파일명이 곧 주소

```
docs/tasks/YYYYMMDD-NN_to-<수신>_from-<발신>_<제목>.md
예) 20260910-02_to-서버_from-개발_머지배포요청.md
    20260910-05_to-전체_from-개발_인지테스트.md      ← 전체 = 등록된 참여자 모두
```

파일 첫 3줄:
```
수신: 서버
발신: 개발
상태: 요청
```
상태는 `요청 → 진행 → 회신 → 완료`. **요청 본문은 발신자만 고친다.** 수신자는 아래에 절을 붙인다.

## 3. 회신 — 같은 파일 아래에 절을 붙인다

```
## 회신 (서버, 2026-09-10 15:20)
...
```
그리고 첫 줄의 `상태:` 를 `회신` 으로 바꾼다. `완료` 는 **요청한 쪽**이 찍는다.
긴 산출물(로그·덤프 목록)은 `docs/tasks/첨부/<파일명>` 에 두고 회신에서 경로만 적는다.

## 4. 감시 규칙

- 각 참여자는 **3~5분 주기로 `git fetch origin handoff`** 하고, 자기 앞 파일(`_to-<이름>_`, `_to-전체_`)의
  **새 커밋**이 있으면 깨어나 읽는다. 세션이면 Monitor/루프, 사람이면 GitHub 알림 또는 `git pull`.
- 감시가 잡은 것은 반드시 **응답한다** — 처리 못 하면 `상태: 진행` 과 한 줄이라도 남긴다. 침묵 = 못 봤다.
- push 전에 `git pull --rebase origin handoff`. 같은 파일을 둘이 동시에 고치지 않게 2·3 규칙을 지킨다.

## 5. 인지 테스트 (처음 한 번)

1. 자기 `참여자/<이름>.md` 를 push 한다.
2. `*_to-전체_*_인지테스트.md` 파일에 `## 회신 (<이름>, 일시)` 절로 **"보인다, 감시 켰다"** 를 적고 push 한다.
3. 발신자(개발)가 모든 등록 참여자의 회신이 모이면 `상태: 완료` 로 바꾼다.
회신이 없는 참여자는 감시가 안 켜진 것이다 — 그 참여자에게 사람이 한 번 알려준다.

## 6. 하지 말 것

- 이 브랜치에 코드 넣지 않는다. 코드는 feature 브랜치 → PR.
- 민감 문서(급여·CFO·회계담당·권한)는 여기 올리지 않는다 (cams-deploy 에 둔다).
- 남의 요청 본문을 고치지 않는다. 회신 절만 붙인다.
