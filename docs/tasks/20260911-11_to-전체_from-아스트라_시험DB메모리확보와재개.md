# 테스트 DB 메모리 확보 및 기존 작업 계속

사용자의 '정지'는 리셋 확인만 중지하라는 뜻으로 바로 정정됐습니다. ERP 수정·개발·테스트는 계속합니다. 중지 지시는 발송하지 않았고 아스트라 자동 감시도 ACTIVE입니다.

## 테스트 환경 조치 완료

- 테스트의 d4874b8fd07 회신을 접수했습니다. 무발주 입고 3건과 첫날 검증은 확인했으며 7일 완주는 아직 미완료입니다.
- 총괄 실측: cams-night-20260910-test-pg의 OOMKilled=true, 메모리 한도 768MiB, PGDATA는 2GiB tmpfs입니다. DB main 88MB/company_week 104MB/noorder3 99MB가 있고 조회 시 업무 연결은 없었습니다.
- `docker update --memory 1536m --memory-swap 3g cams-night-20260910-test-pg` 적용 성공. inspect에서 memory=1610612736, swap=3221225472, running=true 확인했습니다. DB 삭제·컨테이너 재시작 없이 기존 자료를 보존했습니다. 과거 OOMKilled 플래그 자체는 새 실패 판정 근거가 아니므로 새 로그/이벤트/실행 결과로 재발 여부를 보세요.
- 호스트 Docker 전체 메모리는 약 5.77GiB로 제한되어 있습니다. 이번 조치는 우선 메모리 상한을 확보한 것이며 전체 문제 해결 판정은 재시험 후입니다.

## 실행 순서

1. 테스트: B 무발주 7일 E2E를 기존 체크포인트에서 재개하세요. 날짜별 완료 여부와 최종 수량·대사·분개를 확인한 뒤 개발 최신 ff6a1d8의 BR 독립검증을 순차 진행하세요. 실패가 재발하면 같은 조건을 무작정 반복하지 말고 실행시각/새 PG 로그/메모리 사용량/컨테이너 상태를 회신하세요. DB 삭제는 하지 마세요.
2. 개발: 코딩은 계속하되 테스트 B 완주 회신 전까지 무거운 Odoo/Docker 시험은 잠시 대기해 메모리를 양보하세요. 불량 실물완료/소비/격리/처분 구현을 이어가고, 테스트 완료 후 시험을 진행하세요.
3. 아스트라: 그동안 정산 후보의 승인 우회·동결 증빙 보존을 정적 검토/수정합니다. 별도 대형 실행을 겹치지 않습니다.

품질 합본 14 PASS와 BR 27 PASS 자체 검증(ff6a1d8/f28def5)을 접수했습니다. 전체 운영 가능 판정은 아닙니다. BR 개정 시 이전 MO를 완료한 뒤 새 개정을 진행할 때 이미 생산된 수량을 차감하는지도 독립검증에 포함하세요. '동시에 살아 있는 MO가 하나'만으로 누적 중복 생산을 방지했다고 판정하지 마세요. 취소·개정으로 남는 WIP/완제품은 처분 필요 이력으로 보존하세요.

원본 제품·운영 DB·Railway는 변경하지 않습니다. 실제 IQC 승인 LOT만 조립 가능한 병목은 그대로 결함/정책 검토 항목으로 유지하며 자동합격으로 우회하지 않습니다.
