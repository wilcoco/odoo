## 1. PR08 회사 B 계획 생성 시험의 요일 의존

494158ddaaa에서 배정했다. 086d5fd/8880bce의 151건 중 5실패는 `_plan_of_b`에서 계획행 없는 준비실패로 회사격리 본 검사를 시작하지 못했다. `date.today()+7`과 신규회사B 기본 근무달력을 쓴다. 최초19c9089 PASS 로그의 계획일은9/18(금), 같은코드 재실행 FAIL은9/19(토)였다. 동일DB 재실행은 이 날짜 요인을 통제하지 않았으므로 ‘DB 누적상태·후보무관 확정’이라고 보고할 수 없다.

회사B 달력·휴무·미배정 사유를 확인한 뒤, 회사B에속한 명시 합성 가동달력으로 해당 권한 시험이 요일에 무관하도록 고친다. 원래 휴무 차단 제품기준과 회사격리 단언은 유지한다. test_pr_peer_review.py는 개발 소유 injection_planning 범위다. 재현원인과 동일조건 전후 결과를 보고한다.

## 2. 교체 전용 구간의 영속 예약 및 MO 생성

2061e592417에서 배정했다. 전날2h가 교체로 소비되고 당일12h에12개 생산되는 계산 반례는 받아들인다. **이 계산이 맞다는 것과 저장된 계획/MO의 자원 예약이 맞다는 것은 별개**다.

현재 seg_qty<=0 구간은 계획행에서 빠지고 교체2h가 다음날 첫 생산행에 붙는다. 이 상태에서:
- 해당 계획을 정상 확정하고 제조오더를 생성해 시작/종료·교체시간·수량의 정합성을 검증한다. 교체2h를 다음날 다시 더해 납기가 밀리거나 시간을 강제로 덮어쓰면 안 된다.
- 계획을 저장한 다음 다른 계획이 전날 교체구간의 같은 설비·금형을 예약하려 할 때 중복을 막는지 검증한다. 같은 계산 함수 안의 일시적 machine_windows 소진만으로 통과라고 하지 않는다.
- 결함이면 실제 교체구간을 보존하는 기존 계획/bridge 구조 안에서 보완한다. 권한·업무가드를 우회하거나 생산량0 가짜제조오더로 물량을 만들지 않는다.

정확한 실행 명령·SHA·DB·원로그, 실제 예약/계획/MO의 날짜·수량 결과를 남긴다. 미재현이면 관찰근거와 남은 범위를 적는다.
