# [개발 요청] 부품 분류 ↔ 설비 대조표 만드는 방법

발신: UAT/문서 세션 · 2026-09-03 · 수신: 개발 세션
배경: 레거시 ERP의 **스페어파트 분류(4자리)** 와 **설비마스터 분류(2자리)** 가
겹치는 코드 0건이라, 분류만으로는 부품과 설비를 이을 수 없다.
사람이 한 번 짝지어 주는 **대조표**가 필요하다.

> 이 건은 스페어파트 분석을 진행 중인 세션이 따로 있다. **먼저 그 세션과 범위를 맞출 것.**
> (중복 조회·중복 산출물 방지)

---

## 0. 두 층위를 구분해서 시작한다

혼동하면 일이 3배가 된다. 대조표는 **두 개**다.

| 대조표 | 잇는 대상 | 만드는 방법 | 규모 |
|---|---|---|---|
| **A. 기종 대조표** | 부품 분류 4자리(=기종) ↔ 설비 **모델** | 문자열 매칭 + 사람 확인 | 수십 쌍 |
| **B. 호기 적용표** | 부품 ↔ **개별 설비(호기)** | 출고 실적으로 축적 | 점진적 |

**A를 먼저 끝내야 B가 쉬워진다.** A가 되면 "이 부품은 UBE-2200T용" → "우리 공장 UBE-2200T는
이 5대" 까지 자동으로 좁혀지고, 그중 어느 호기인지만 실적으로 채우면 된다.

## 1. 자료 확보 (읽기 전용)

**자격증명은 코드·git 에 두지 말 것** — 기존 `erp_plan_sync` 와 동일하게
`ir.config_parameter` 에 저장된 값을 쓴다. 조회는 **SELECT 만**.

| 필요한 것 | 위치 | 비고 |
|---|---|---|
| 설비 목록 233대 | `T_ZR_MCH` — `MCHMCH`(설비코드) `MCHNAM`(설비명) `MCHSIZ`(규격) `MCHVND`(제작처) `MCHSRT`(설비분류) `MCHLOC`(설치장소) `MCHSAYANG`(사양) `MCHWICHI`(관리번호) | 명세서 (64)항 확인됨 |
| 설비분류 코드명 | `T_ZJ_COD` 에서 `CODGB1='MCH'` (명세서에 `MCH,1` 로 표기) | **2자리 코드의 한글 이름**을 여기서 얻는다 |
| 설치장소 코드명 | `T_ZJ_COD` 에서 `RTG` 계열 | 공장·라인 구분에 쓰임 |
| 부품 분류 60개 + 명칭 | 스페어파트 분류 테이블 (SPMSRT 계열) | **실제 테이블·컬럼명은 DB 에서 확인**할 것 (명세서에 미수록) |
| 부품 목록 | 스페어파트 마스터 (SPMITM 계열) | 분류가 달린 42개만 우선 |
| 부품 출고 이력 | 스페어파트 출고/사용 테이블 | **B(호기 적용표)의 원천** — 설비코드 컬럼이 있는지 반드시 확인 |

## 2. 후보 자동 생성 — 문자열 매칭

핵심 착안: **부품 분류의 4자리째(기종)에는 모델명이 들어 있고**(UBE-2200T, ENGEL-3200T),
설비마스터의 `MCHNAM`·`MCHSIZ`·`MCHSAYANG` 에도 같은 모델명이 들어 있을 가능성이 높다.
코드는 안 겹쳐도 **이름은 겹친다.**

### 2-1. 정규화 (양쪽 동일 규칙)
```
대문자 변환 → 공백·하이픈·언더바 제거 → 괄호 안 제거
예) "UBE-2200 T" → "UBE2200T" / "엥겔 3200톤" → "엥겔3200톤"
숫자+단위 추출: 2200T, 3200T  (톤수는 가장 강한 식별자)
제작처 별칭 사전: UBE=우베, ENGEL=엥겔=엥글, LS=엘에스 …
```

### 2-2. 매칭 점수 (자동 확정 금지, 후보 제시용)
| 조건 | 점수 |
|---|---|
| 정규화 문자열 완전 일치 | 100 |
| 모델명 + 톤수 모두 포함 | 90 |
| 톤수만 일치 + 제작처(`MCHVND`) 일치 | 70 |
| 제작처만 일치 | 30 |
| 설비분류 코드명(한글)과 부품 분류 2~3자리 의미가 같은 계열 | +10 |

> **80점 이상만 후보로 올리고, 확정은 사람이 한다.** 자동 확정은 절대 금지 —
> 잘못 이어지면 엉뚱한 부품이 소요 자재로 잡혀 발주까지 나간다.

### 2-3. 산출물
`대조표_후보.csv` — 부품분류코드 / 분류명 / 후보 설비코드 / 설비명 / 규격 / 제작처 / 점수 / 판정(빈칸)
→ 담당자가 **판정 칸만 채우면** 되는 형태로 낸다 (확정/보류/제외).

## 3. 사람 확인

- 실제 확인 대상은 **42개 분류 × 후보 1~3개 = 100줄 이내**. 하루 분량이다.
- 확인 담당은 **설비·보전 담당**(설비 쪽 이름을 아는 사람). 자재 담당 단독으로는 어렵다.
- 판정이 "보류"인 것은 그대로 두고 **미매핑 목록으로 남긴다** — 억지로 잇지 않는다.

## 4. 개별 호기(B)는 실적으로 채운다

부품 출고 이력에 **설비코드가 남아 있으면** 그것이 가장 정확한 근거다.
- 출고 이력 → (부품, 설비코드) 쌍 집계 → 건수 많은 순으로 적용표에 적재
- A(기종 대조표)로 **후보를 좁혀 두었으므로**, 실적에 없는 호기도 "같은 기종이니 후보"로 제시 가능
- 사람이 최종 확정하되, **"실적 근거 있음 / 기종 추정" 을 구분해 저장**할 것

## 5. Odoo 저장 구조

**신규 모듈을 만들지 말 것.** 설비는 `iatf_equipment`(`iatf.equipment`), 부품은 `product.product` 가 정본이다.

```python
# A. 기종 대조표 — 레거시 분류코드를 우리 설비/모델에 잇는 다리
class SparePartClassMap(models.Model):
    _name = "spare.part.class.map"
    legacy_class_code = Char   # AIAA, APCC …  (원본 코드 보존)
    legacy_class_name = Char
    equipment_model   = Char   # UBE-2200T (정규화 전 원문)
    equipment_ids     = Many2many("iatf.equipment")   # 해당 기종의 우리 설비들
    confidence        = Selection([("confirmed","확정"),("hold","보류"),("excluded","제외")])
    match_score       = Integer
    note              = Text

# B. 호기 적용표 — "이 부품이 어디에 들어가는가" (다대다, 이게 핵심)
class SparePartApplication(models.Model):
    _name = "spare.part.application"
    product_id   = Many2one("product.product", required)   # 부품
    equipment_id = Many2one("iatf.equipment", required)    # 개별 호기
    source       = Selection([("actual","출고 실적"),("model","기종 추정"),("manual","수동 등록")])
    qty_per      = Float        # 소요 수량(알면)
    _sql_constraints = [("uniq", "unique(product_id, equipment_id)", "이미 등록된 조합입니다.")]
```
- **원본 4자리 코드는 지우지 말고 보존**한다(현장이 그 코드로 대화한다).
- 계층은 코드가 아니라 **관계**로 표현한다. `product.category` 는 parent 트리를 그대로 쓴다.

## 6. 검증 기준 (완료 판정)

- [ ] 부품이 달린 분류 **42개 중 몇 개가 확정**되었는지 커버리지 수치로 보고
- [ ] **미매핑 목록**을 별도로 남길 것 (0으로 만들려 억지 매핑 금지)
- [ ] 같은 부품이 **여러 설비에 걸리는 사례가 실제로 나오는지** 확인
      (안 나오면 다대다를 만든 의미가 없다 — 매칭이 잘못됐을 가능성)
- [ ] 재현 가능할 것: 후보 생성은 **스크립트 1회 실행으로 재현**되어야 한다
      (수작업 엑셀 편집만으로 만들면 원본이 바뀔 때 다시 못 만든다)

## 7. 하지 말아야 할 것

1. **점수 높다고 자동 확정** — 발주까지 잘못 나간다
2. **미매핑을 0으로 만들려는 억지 매핑** — 보류로 두는 게 정직하고 안전하다
3. **레거시 코드 폐기** — 현장 언어를 없애면 아무도 안 쓴다
4. **신규 모듈 남발** — 설비는 `iatf_equipment`, 부품은 `product.product` 가 정본
