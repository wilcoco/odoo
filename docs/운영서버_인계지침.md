## 2. 사출 계열은 **escon-odoo/odoo_gh** 로 통합 (= gamehon/odoo_gh 와 같은 혈통)

담당자가 작업하는 `escon-odoo/odoo_gh` 는 우리가 쓰던 `gamehon/odoo_gh` 의 fork/사본이다.
검증 결과: 우리 feat 브랜치들이 이미 `escon-odoo` 에 올라가 있고(escon/feat/* = 우리 커밋 동일),
`escon/main` = gamehon main + 팀 최신작업(이종검사·MES 멀티공정 등) 상태.

→ **사출 계열(injection_worksite·gh_vendor_settlement·cams_ops_dashboard)은 escon-odoo/odoo_gh 로 통합.**

### ⚠️ 단, "브랜치 4개 git merge" 는 하지 말 것 — 대신 **통합 패치 1개** 사용
실제 테스트 머지 결과:
- `feat/vendor-contract-price` → escon/main: 충돌 0 (정상)
- `feat/injection-workcenter-auto-flag` → escon/main: 충돌 1개(`__manifest__.py`만), 나머지 자동
- `feat/silo-auto-reorder` + `feat/ops-dashboard` → escon/main: **history 단절 → git merge 시 가짜충돌 100개+**

→ 그래서 **escon/main 기준으로 충돌까지 미리 다 해결한 패치**를 만들어 두었다:
**`exports/cams-integration.patch`** (+ 적용안내 `exports/cams-integration-적용방법.md`).
담당자는 git merge 없이 **패치 1개 적용**만 하면 된다. `git apply --check` 통과 검증 완료.

> wilcoco(IATF/SCM/injection_planning)는 **다른 repo·다른 폴더, 겹치는 파일 0개** →
> escon 으로 합치지 말고 지금처럼 클론 + addons_path 연동 그대로 유지.

## 4. 통합 절차 (escon-odoo/odoo_gh)
```
# 1) main 최신화 후 통합 브랜치 + 패치 1개 적용
cd <escon-odoo/odoo_gh 클론>
git checkout main && git pull origin main
git checkout -b feat/cams-integration
git apply --3way --whitespace=nowarn <경로>/cams-integration.patch
git add -A && git commit -m "통합: SILO 통보·원재료 톤당정산·운영 대시보드"

# 2) 모듈 설치/업그레이드 (운영 DB)
docker compose exec odoo bash -lc \
 'odoo -d <운영DB> -i cams_ops_dashboard \
   -u injection_worksite,gh_vendor_settlement --stop-after-init --no-http'

# 3) 웹서버 재시작(레지스트리 반영)
docker compose restart odoo

# 4) wilcoco(IATF/SCM)는 건드리지 말 것 — 별도 repo + addons_path 그대로
#    supplier_portal_purchase·injection_planning 변경분은 wilcoco/odoo 에서 정상 PR 머지
```
> 상세 적용 안내: `exports/cams-integration-적용방법.md`

## 5. 통합 후 검증 (필수)

## 6. 운영 데이터 구축 (코드와 별개로 입력 필요)
- 부품 계약단가(vendor.part.price), 원재료 톤단가(material.ton.price) — 정산 정확도.
- 사출 capability(금형·사출기·능력) — 실품번 스케줄링.
- SILO 원재료는 **LOT 추적** 설정(입고 자동충전 전제).
- Oracle 수요연동: config(접속정보는 Odoo 계획설정 화면 참조 — 문서 기재 금지) + Instant Client(이미지에 내장, docker/Dockerfile.odoo).
