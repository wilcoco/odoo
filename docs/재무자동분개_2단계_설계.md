# 재무 자동분개(2단계) 설계 — 실제원가의 회계 자동연결

작성: 2026-07-03. 상태: **설계(의사결정 대기).** 구현 전 회계·CFO 승인 필요(재무제표·세무 영향).
선행: [실제원가_관리분석_설계.md](실제원가_관리분석_설계.md)(1단계=관리분석, 완료). 본 문서는 파킹했던 2단계.

## 0. 왜 승인 없이 실행하지 않았나
2단계는 **재고 평가방법(valuation)을 바꾸는 일** → 재무제표(재고자산·매출원가)와 세무에 직접 영향. 무발주 톤/생산량 정산과 충돌 지점이 있어 **회계·CFO 판단이 필수**. 1단계(관리분석)는 valuation을 안 건드려 이 리스크 없이 이미 가동 중.

## 1. 목표
실제원가·원가차이를 **재무회계에 자동 분개**(재고자산·매출원가 정확 + 원가차이 계정) → 감사·세무 대응, 실시간 원가.

## 2. 필요한 전환
| 항목 | 현재(1단계) | 2단계 |
|---|---|---|
| 평가시점 | manual_periodic(수동) | **real_time(자동 분개)** |
| 원가법 | standard | standard+**차이계정** 유지(권장) 또는 AVCO |
| 원가차이 | 관리 리포트(참고치) | **회계 계정 자동 전기** |

## 3. ★ 톤정산 충돌과 해소안 (핵심 결정)
real_time을 켜면 **원재료 입고(silo load)·부품 소비 시점에 재고자산 분개**가 생긴다. 그런데 무발주 정산(수지 톤 월마감, 부품 생산량 월마감)이 **이미 매입 분개**를 만든다 → **이중계상 위험**.

**해소 후보 (택1, 회계 결정):**
- **(A) GR/IR 패턴** — 수령 시 재고자산 취득 = 표준단가(또는 계약단가)로 real_time 분개(자산+ / **미정산부채** 임시계정). 월 톤정산 확정 시 그 임시부채를 실제 청구서로 정리하고 **차액을 가격차이/소급차이**로. → 표준수령+정산정리(SAP GR/IR 유사). 이중계상 없음.
- **(B) 부분 적용** — 원재료는 periodic 유지(정산이 매입담당), **완제품·재공만 real_time**. 경계 단순하나 원재료 원가차이는 여전히 관리층에만.
- **(C) 전면 AVCO** — 실제 입고가로 재고 자동. 표준·차이 개념 약화 + 정산과 재고취득가 정의 재설계 필요(부담 큼).

**권장 = (A) GR/IR** — 표준 기준선 유지 + 정산과 깔끔히 분리 + 차이 자동. 단 임시계정·정리 프로세스 구축 필요.

## 4. 계정 셋업(안)
재고자산(원재료/재공/제품), 재고변동, **원가차이 계정 4종(재료가격/재료수량/가공능률/수율)**, GR/IR 미정산부채 임시계정. 차이는 발생 시 해당 계정으로 자동 전기, 월말 분석·처리.

## 5. 영향·리스크
- 재무제표: 재고자산 평가액 변동(표준→실제 반영), 원가차이 손익 인식.
- 세무: 재고평가방법 변경 신고, 기중 변경 영향.
- 정산 정합: (A) 채택 시 GR/IR 잔액이 미정산 톤/생산량과 항상 일치해야(대사 통제).
- 마감본 불변·소급차이 당월계상 원칙 유지([[실제원가_관리분석_설계]]와 동일).

## 6. 단계적 실행(권장)
1. **PoC(sim DB)**: (A) GR/IR로 사출 1라인 real_time 전환 → 재고자산·차이 분개 검증, 톤정산과 GR/IR 대사.
2. **병행운영**: 관리원가(1단계) vs 재무원가(2단계) 수치 대사(일정기간).
3. **전환 결정**: 회계·CFO 승인 후 실 DB 적용 + 세무 신고.

## 7. 미결 의사결정 (회계·CFO)
1. 재무 자동연결을 실제로 도입할지(관리분석으로 충분한가?).
2. 도입 시 해소안 A/B/C 중 택.
3. 원가법 standard+차이 유지 vs AVCO.
4. 재고취득원가 기준(표준 vs 계약단가) + 정산과의 대사 통제.
5. 전환 시점·세무 신고 일정.
