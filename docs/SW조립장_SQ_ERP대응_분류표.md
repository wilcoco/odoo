## 3. 신규 개발이 필요한 것 (우선순위)

| 순위 | 항목 | 근거 | 예상 |
|---|---|---|---|
| 1 | **작업일보(융착)** | 6개 평가항목에서 반복 요구. 비가동·재가동 이력의 근거 자료 | 2주 |
| 2 | **일상 점검 일지 3종** (전동공구 토크 / 통전검사 마스터 / 바코드 마스터) | 각 5개 항목에서 반복. 공통 "점검 마스터 + 일일 기록" 한 모델로 처리 가능 | 2주 |
| 3 | **한도견본 관리** (OK/NG 대장·게시) | 2_4 핵심 지적 | 1주 |
| 4 | **리워크 관리대장** | 5_10 필수 | 1주 |
| 5 | 가압면 면압 측정 이력 / t/o 일지 | 융착 설비 고유 | 1주 |
| 6 | 정성품질 운영 | 고객사 프로그램 — 요구 수준 확인 후 결정 | 미정 |

> 2번은 **범용 "점검 일지" 모델 하나**(점검 대상 + 항목 + 주기 + 기록)로 만들면
> 토크·통전·바코드·소화기·조도·3정5행까지 한 번에 덮습니다. **가장 효율이 높은 개발**입니다.

## 4. 보완만 하면 되는 것 (🟡 17종)

대부분 **기존 모델에 항목·유형만 추가**하면 됩니다.
- `iatf_work_environment` 에 조도·소화기·비상대피로·3정5행 점검 항목 추가 → 4종 해결
- `iatf_nonconformity` 에 '낙하품' 부적합 유형 추가 → 1종
- `iatf_process_inspection` 에 통전검사 항목 추가 → 초·종 검사이력 해결
- 식별표·선입선출·날인 점검은 **3번 항목(범용 점검 일지)** 으로 함께 처리 권장

## 5. 확인 필요 (담당자 회신 요청)

1. **조립장(SW)이 현재 ERP 대상 범위인가** — IATF 모듈은 사출 기준으로 구축됐습니다.
   조립 공정 BOM·라우팅·작업장이 등록돼 있어야 검사·추적이 붙습니다.
2. **전수리딩**: 조립장에 바코드 스캐너·시리얼 체계를 적용할 계획인지
   (`escon_serial` 14자리 체계를 그대로 쓸 수 있는지)
3. **정성품질**: 고객사가 요구하는 산출물 형태(시스템 기록 vs 게시판 운영)
4. 평가일(SQ 심사 예정일) — 개발 우선순위를 여기에 맞춰야 합니다
