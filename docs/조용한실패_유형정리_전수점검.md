## 3. 발견·조치

### ① [수정·푸시] env.get falsy 오판 9곳 — T6 실결함
- `env.get(model)`은 설치 시 **빈 recordset(falsy)** 을 반환 → `if X / if X else 0` 검사는 설치돼 있어도 미설치로 오판.
- 영향: **협력사 화면의 부적합·수입검사 카운트, 품목 IATF 문서현황 배지 전부 항상 0** — "0건"이 그럴듯해 아무도 인지 못함.
- 실증: 수정 전 전부 0 → 수정 후 협력사 IQC=1, 품목 검사=20 정상 집계 (sim_hx_1).
- 조치: `is not None` 교정, 브랜치 `fix/envget-falsy-counts` 푸시 (iatf-company-forms 기반).

### ② [기수정 확인] 과거 발견분 전부 유지 확인
- 계획 MO 생성 실패 가시화(T5), BR no_mo/경합(T2·T5·T7), CI 0건 가드(T6), 미매핑 수요(T4), 원가 출처 필드(T3) — 재스캔에서 모두 생존.

### ③ [지적 — engel 소유] 추적기록 생성 실패 침묵 (T2)
- engel 시리얼의 IATF 추적기록 자동 생성이 실패하면 로그만 남음 → 시리얼은 있는데 추적 증빙이 빈 상태가 조용히 누적 가능.
- 권고: 시리얼 화면에 "추적기록 미연결" 필터 추가 + 일일 확인 태스크. (IATF/개발자 전달)

### ④ [백로그] search(limit=1) 무정렬 116곳 (비결정 선택)
- 같은 조건 레코드가 2건 이상이면 "아무거나 1건"이 조용히 선택됨 — 단가·BOM처럼 시점·버전이 있는 조회에서 위험.
- 핵심 경로(vendor.part.price·ton.price·BOM 선택)는 order 지정 확인됨. 나머지는 신규 코드 리뷰 체크항목 + 점진 정리 권고.
- 추가 예방: critical_symbols 방식처럼 "무정렬 limit=1 신규 추가 금지"를 PR 리뷰 규칙에 명문화.

## 4. 예방 체계 (재발 방지)
1. **PR 리뷰 체크리스트**: except 삼킴 금지(수집·보고 필수) / env.get은 is None / limit=1엔 order / 배치엔 failed·skipped 카운트 응답.
2. **CI**: 기존 심볼 스캔 + 테스트에 더해, 이 문서의 패턴 스캔 스크립트를 ci/에 추가 검토(경고성).
3. **설계 원칙(기존 유지)**: 폴백엔 출처 필드, 제외엔 카운트 채터, 배치엔 결과 요약, 상태 마킹은 경합 안전.
