## 4. 코드가 운영에 가는 길 — 가장 헷갈리는 부분

```
wilcoco/odoo 18.0 (addons_custom)       ← 우리가 개발·머지하는 곳 (정본)
        │  원도영이 손으로 복사 ("정본 동기화")   ← CI/CD 없음
        ▼
escon-odoo/odoo_gh main (iatf_plugins)  ← 서버가 실제로 읽는 곳 (배포 저장소)
        │  원도영이 서버에서 git pull → -u → 재기동
        ▼
     운영 반영
```

- **정본에 머지해도 운영에는 아무 일도 일어나지 않는다.** 미러까지 가야 하고, 서버에서 사람이 올려야 한다.
- 왜 이렇게 됐나(원도영 설명): 저장소 하나만으로 운영을 동기화하려고. `wilcoco/odoo` 를 서버에 직접 얹으면 없앨 수 있으나 반영 속도 때문에 유지.
- **함정**: 원도영이 `odoo_gh` 에 직접 넣은 수정이 `wilcoco/odoo` 에 없으면 다음 동기화 때 **서버에서 조용히 사라진다.**
  8월에 그럴 뻔했고, 9/9 스캔에서도 미러가 앞선 모듈 8개가 있었다. → `scripts/mirror_diff.sh` 를 동기화 전후로 돌린다.
- 운영 DB 복제본은 로컬 테스트베드로만. **로컬에서 고친 DB 를 운영으로 되돌리는 것은 불가.**
