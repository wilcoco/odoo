# 품질기록 시뮬레이션 명세 (메인 개발 세션 실행용)

> 작성: 2026-07-02 (IATF/SQ 세션). 목적: 기존 생산 시뮬레이션(MO·LOT)의 연장으로 **품질기록을
> 프로세스로 생성** — 결과값은 시스템 로직이 계산(더미 create 금지). 완료되면 심사평가(SQ·IATF)
> 메뉴의 47+30개 기준 증빙이 실데이터로 채워짐.
>
> **DB = `cams_sim` (시뮬 전용).** sq_evaluation+기준 77건(SQ47+IATF30) 설치 확인됨(2026-07-02)
> → 검증도 cams_sim에서 수행. 운영 `cams` 반영은 별도 결정(동일 스크립트 재실행) — 시뮬 데이터와
> 운영 데이터 분리는 오히려 권장 (cams의 검사3·PPAP9건 등 기존 실데이터와 안 섞임).

## 원칙
- **마스터(기준정보)는 직접 등록 OK** (등록이 곧 실무): 설비·금형·측정장비·관리계획서·공정·검사기준·품질목표.
- **기록은 반드시 프로세스로**: 검사 판정 버튼, MO 완료, GRR 계산 버튼 등 — 지표(불량률·%GRR·Cpk·타수)는 로직이 산출.
- 기존 시뮬레이션의 품번/BOM/작업장/로트를 **재사용**해서 연결(같은 product_id·lot_id에 품질기록이 붙어야 증빙 체인이 성립).

## 1단계 — 마스터 등록 (직접 create 정당)
| 모델 | 내용 | 주의 |
|---|---|---|
| `iatf.equipment` | 사출기 등 설비 2~3 + PM주기 | |
| `iatf.mold` | 기존 시뮬 품번의 금형 2~3 (보증타수·PM주기 포함) | MO와 연결 필드 확인(`iatf_mold/mrp_production.py`) — 연결 시 MO 완료마다 타수 자동증가 |
| `iatf.measurement.equipment` | 캘리퍼 등 2~3 | `equipment_id_number` **required** |
| `iatf.control.plan` | 시뮬 품번당 1 + line_ids(특성) → 승인 상태로 | `bom_id`는 product 선택 시 onchange 자동제안 |
| `iatf.process` (iatf_jig) | 사출/검사 공정 마스터, `workcenter_id` 연결 | |
| `iatf.inspection.criteria` | 품번·협력사별 수입검사 기준 | |
| `iatf.quality.objective` | '검사 합격률'·'불량 PPM' 목표 (kpi_name에 해당 문자열 포함 필수 — 자동집계 라우팅 키워드) | |
| `iatf.jig` + 체크리스트는 SQ 쪽 기완비 | | |

## 2단계 — 프로세스 실행 (버튼/플로우, 결과값은 계산)
1. **수입검사**: PO→입고 흐름 위에 `iatf.incoming.inspection` 생성(quantity_inspected/rejected 입력)
   → `action_start_inspection` → `action_decide`. **1건은 result='fail'로** → 부적합 자동생성 +
   로트 격리 확인. 합격건은 quality_hold 해제 확인.
2. **MO 사이클**: 신규 MO 5~10건 생성→확인→완료 (금형 연결 상태에서) → **금형 current_shots 자동
   증가** 확인. 완료 MO에 `iatf.process.inspection`(초/중/종물 각각, line_ids에 측정값) →
   `action_decide`. fail 1건 → NC 자동 + `_auto_feed_spc` 동작 확인.
3. **MSA**: `iatf.msa.study` 생성(product·instrument 연결) → `iatf.msa.measurement`
   3작업자×10부품×3반복=90행 입력(측정값은 규격 주변 산포) → **`action_calculate`** → %GRR·ndc
   산출 확인 (10~30% 사이 나오게 산포 설계 권장).
4. **SPC**: `iatf.spc.study` 생성(usl/lsl/nominal) → `iatf.spc.subgroup` 25조(x1~x5) 입력 →
   **`action_calculate`** → Cp/Cpk·관리한계 산출.
5. **교정**: 측정장비별 `iatf.calibration.record` 1~2건(교정일→차기예정일).
6. **부적합→시정조치 체인**: 위에서 자동생성된 NC에 `iatf.corrective.action` 생성(8D) →
   진행→완료→검증. 1건은 due_date 과거로 → 대시보드 ca_overdue 잡히는지.
7. **현장/절차 13종**(SQ 전용): 심사평가 메뉴 > 현장/절차 점검 — 각 항목 [점검기록 작성]
   → 체크리스트 자동로드 → 판정 입력 저장. 항목당 2~3회(주기 다르게, record_date 분산).
8. **신뢰성/레이아웃/작업환경**: `iatf.reliability.test`·`iatf.layout.inspection`·
   `iatf.environment.check`(조도 lux 포함) 각 1~2건.
9. **결재선 리허설(선택)**: 주요 기록 1건씩 `approval_line_ids` 지정 → 상신→승인 (전 IATF 모델
   iatf.approval.mixin 배선됨).

## 3단계 — 자동집계 확인 (이게 "제대로"의 증거)
- `iatf.dashboard` 새로고침: iqc/pqc **합격률(%)**, ca_open/ca_overdue, nc_open 실측 반영.
- `iatf.quality.objective.action_auto_calculate_kpi` (버튼 or cron): 합격률·PPM이 **검사 실데이터로
  계산**되는지 (env.get 버그 수정돼 실동작 — a79766ab).
- 심사평가 메뉴: SQ 47·IATF 30 기준의 evidence_count 상승 + [증빙 조회] 드릴다운.
- 샘플 평가서(SQ-2026-0010/0011)에서 이행상태 입력 → 달성률·자체등급 산출.

## 주의
- 같은 스택 공유: 실행 중 이 세션과 `-u`/restart 동시 금지.
- `sq.field.record`는 criteria_id 필수 — 심사평가 메뉴 경유가 편함(자동 프리필).
- 지표가 0/이상하면 그 자체가 버그 신호 → IATF/SQ 세션에 피드백.
