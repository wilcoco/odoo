# 메뉴 재구성 대응 — 경로 매핑과 진단 (2026-09-02)

배경: 「회사 운영 센터」·「원부자재 관리」로 메뉴가 재구성됨 (odoo_gh main).
UAT 문서의 【경로】 표기가 어긋나므로 **코드에서 경로를 추출해** 대조했습니다.

도구: `scripts/menu_paths.py` — 애드온 XML 의 menuitem 을 읽어 전체 경로를 만든다.
```bash
python3 scripts/menu_paths.py <애드온루트>                    # 전체 경로 목록
python3 scripts/menu_paths.py <루트> --find 톤단가 사일로       # 이름으로 위치 찾기
python3 scripts/menu_paths.py <구트리> --diff <신트리>          # 이동·신설·삭제 비교
```
→ **재구성이 또 일어나도 이 도구로 5분이면 문서를 다시 맞출 수 있습니다.**

---

## 1. 결론 먼저 — 대응 가능합니다

- 문서 갱신은 **자동 추출 → 표 대조**로 처리 (수작업 검색 불필요)
- 다만 **지금 문서를 고치면 안 되는 이유**가 있습니다 → 2항의 중복 문제 때문.
  구 메뉴가 살아 있는 동안 새 경로로만 적으면 테스터가 오히려 헷갈립니다.

## 2. 먼저 정리가 필요한 것 — **구 메뉴와 신 메뉴가 병존**

같은 기능이 **두 경로에 동시에** 있습니다 (odoo_gh main 실측):

| 기능 | 구 경로 (아직 살아 있음) | 신 경로 |
|---|---|---|
| 원재료 톤당 월정산 | 사출 현장 › 원재료 정산 › 원재료 단가·정산 › … | 원부자재 관리 › 원재료 단가관리 › 원재료 단가·정산 › … |
| SILO 재고·발주 현황 | 사출 현장 › 원재료 수급 현황 › … | 원부자재 관리 › 원재료 수급 현황 › 원재료 수급 관리 › … |
| 원재료 계약 톤단가 | 사출 현장 › 원재료 정산 › … | 원부자재 관리 › 원재료 단가관리 › … |

- 구 메뉴 정의: `injection_worksite/views/material_ton_settlement_views.xml` 등
- 신 메뉴 정의: `escon_rawmaterial_management/views/rawmaterial_management_menus.xml`

**왜 문제인가**: 사용자는 같은 화면을 두 곳에서 만나고, 어느 쪽이 정식인지 알 수 없습니다.
UAT 기록도 서로 다른 경로로 남아 재현이 어려워집니다.

**요청**: 구 메뉴를 제거(또는 숨김)해 **경로를 하나로** 만들어 주세요.
그 시점에 문서를 신 경로로 일괄 갱신하겠습니다.

## 3. 함께 발견 — 업무 프로세스 안내가 구 경로를 가리킴

`cams_ops_process/data/ops_seed.xml` 의 `menu_path` **13건 중 7건이 구 경로**입니다
(예: "사출 현장 > 원재료 정산 > …", "외주 관리 > …").
운영 센터에서 프로세스를 눌러 안내를 봐도 **없는 경로**로 안내됩니다.
→ 시드 데이터도 신 경로로 갱신이 필요합니다.

## 6. 제안 순서

1. **구/신 메뉴 중복 정리** (개발 측) — 이게 먼저입니다
2. 정리 완료 신호 → `menu_paths.py --diff` 로 최종 경로 추출
3. 문서 5종 【경로】 일괄 갱신 + docx 재생성 (반나절)
4. UAT 재개 — 경로 외 시나리오 내용은 그대로 유효

## 7. 메뉴 재구성 자체에 대한 의견

**방향은 동의합니다.** 업무 흐름(원부자재 → 정산, 운영 센터)으로 묶는 편이
모듈 단위 나열보다 사용자가 찾기 쉽습니다. 특히 원재료 단가·정산·수급이
한 트리에 모인 것은 실무 동선과 맞습니다.

다만 두 가지만 지켜 주시면 좋겠습니다.
- **경로는 하나만** — 이동이면 구 경로는 없애기 (2항)
- **깊이 4단 이상 주의** — "원부자재 관리 › 원재료 단가관리 › 원재료 단가·정산 › 원재료 톤당 월정산"
  은 4단입니다. 자주 쓰는 항목은 3단 이내가 좋습니다.
