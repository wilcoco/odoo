# 세금계산서·전표 처리 전과정 가이드

작성: 2026-08-25 · 대상: 회계 담당 · 환경: 운영 서버 `http://10.10.21.20/odoo` (DB odoo18)
관련 모듈: `account_kr_guard`(마감·검증), `account_kr_reports`(장부·세금계산서 필드)

**전제 — 이 시스템은 홈택스와 직접 연동하지 않습니다.**
세금계산서 **발행·수취는 홈택스(또는 EDI 업체)에서** 하고, Odoo는 그 결과를
**전표로 받아 장부·부가세 자료로 관리**합니다. 연결 고리는 **승인번호**입니다.

```
[현장/구매 실적]  →  [Odoo 청구서 생성]  →  [게시 = 분개 발생]  →  [홈택스 발행/수취]
                                                          ↘  승인번호 입력·매칭 ↙
                                                     [매입매출장·부가세 신고 자료]
                                                              ↓
                                                     [월 마감 체크리스트 → 잠금]
```

---

## 1. 언제 분개가 생기나 (핵심)

| 시점 | 분개 | 비고 |
|---|---|---|
| 발주(PO) 확정 | **없음** | 약정일 뿐 |
| 입고(QR·ASN 확정) | **없음** (재고평가 "수동"인 경우) | 카테고리 재고평가가 "자동"이면 입고 시 재고자산/입고미착 분개 발생 — 설정 확인 필요 |
| 정산 → **청구서 생성** | 없음 (초안) | 숫자만 잡힌 상태 |
| 청구서 **[게시]** | **← 여기서 발생** | 매입/부가세대급금/미지급금 |
| 결제 등록·전기 | 발생 | 미지급금/현금·예금 |

> 자주 하는 실수: 정산 위저드로 **청구서를 만들기만 하고 게시하지 않는 것**.
> 초안 청구서는 장부·부가세 자료에 잡히지 않아 대사가 어긋납니다.

## 2. 매입(우리가 받는 세금계산서)

### 2-1. 어디서 만들어지나 — 3가지 경로

| 경로 | 트리거 | 만드는 것 |
|---|---|---|
| **부품(무발주)** | MO 완료 → 사용실적 자동 적립 → 월말 **정산 위저드** | 공급사별 매입청구서 |
| **원재료(발주함)** | 사일로 적재 실적 → **톤정산 확정** → [매입계산서 생성] | 공급사별 매입계산서 |
| **일반 경비·기타** | 품의 승인 → 청구 | 매입청구서 |

### 2-2. 처리 순서

1. **청구서 생성** (위 경로 중 하나) — 공급가·수량이 실적과 맞는지 확인
2. **한국 필드 입력** (【회계 › 매입 청구서】 폼):
   - **과세 구분**: 과세 / 영세 / 면세 — 라인 세금에서 자동 추정, 필요시 수정
   - **증빙 종류**: 세금계산서 / 계산서(면세) / 카드 / 현금영수증 / 기타
   - **세금계산서 승인번호**: 홈택스 수취분의 국세청 승인번호
     → **중복 입력은 시스템이 차단**합니다 ("이미 업로드된 세금계산서입니다")
3. **[게시]** — 이 순간 분개 발생
4. 결제 시 【결제 등록】 → 전기

### 2-3. 대량 입력 — 홈택스 내려받기 → 일괄 업로드

1. 【회계 › 업로드 템플릿 다운로드】 → **"세금계산서 매입분"** 선택 → CSV 내려받기
2. 2행(예시)을 지우고 홈택스에서 받은 자료를 채움 (승인번호·사업자번호·일자·금액)
3. 매입 청구서 목록에서 **[가져오기(Import)]** → 헤더가 자동 매핑됨
4. 승인번호 중복분은 자동 차단 — 두 번 올려도 안전

---

## 3. 매출(우리가 발행하는 세금계산서)

1. Odoo에서 **매출 청구서 생성 → [게시]** (분개 발생)
2. **홈택스에서 세금계산서 발행** (별도 작업) → 승인번호 획득
3. 승인번호를 Odoo 전표에 기록 — 2가지 방법:
   - **개별**: 전표 폼의 "세금계산서 승인번호"에 직접 입력
   - **일괄**: 【회계 › 매출 승인번호 매칭】 → 홈택스 발행분 CSV 업로드
     → 사업자번호·일자·금액으로 기존 게시 전표를 찾아 승인번호를 **백필**
     (템플릿은 "매출 승인번호 매칭용" 다운로드)
4. **수정 세금계산서**를 발행한 경우: 환불 전표(또는 음수 전표)에 **원본 세금계산서 번호**를
   기입 → 시스템이 "수정/마이너스분"으로 표시하고 원본과 연결

## 4. 확인 — 장부와 신고 자료

| 보려는 것 | 메뉴 |
|---|---|
| 매입·매출 전체 | 【회계 › **매입매출장**】 (매입장 / 매출장 개별도 있음) |
| 거래처별 합계 | 【**매입처별 합계표**】 / 【**매출처별 합계표**】 |
| 일자별 전표 | 【**오늘 전표**】 / 【**일계표**】 / 【**월계표**】 |
| 자금 계획 | 【수금 예정표】 / 【지급 예정표】 / 【자금 현황】 |
| 재무제표 | 【K-재무제표】 (매핑 설정 필요) |

**부가세 신고 자료가 맞으려면** 각 전표에 ①세금(과세 유형에 맞는 세금 코드) ②과세 구분
③증빙 종류 ④승인번호가 들어 있어야 합니다. 세금 코드가 빠지면 장부엔 보여도
신고 자료에서 누락됩니다 — 마감 체크리스트의 "세금 없는 청구 라인"이 이걸 잡아줍니다.

## 5. 월 마감

### 5-1. 마감 전 체크리스트 (【회계 › 마감 전 체크리스트】)

9개 항목을 세어 보여주고, 숫자를 클릭하면 해당 전표 목록으로 들어갑니다:

| 항목 | 왜 문제인가 |
|---|---|
| 총계 0원 청구서 | 실수로 만든 빈 전표 |
| 미전기(진행중) 결제 | 결제가 장부에 반영 안 됨 |
| 은행 미조정 결제 | 통장과 대사 안 된 건 |
| 사업자번호 없는 거래처 | 세금계산서·신고 자료 누락 |
| 사업자번호 중복 거래처 | 같은 거래처가 둘로 갈라짐 |
| **세금 없는 청구 라인** | 부가세 신고에서 빠짐 |
| 미승인 품의 연계 전표 | 승인 없이 지출 |
| 품의 미연계 청구서 | 승인 절차 우회 |
| 음수 금액 일반 청구서 | 환불이 아닌데 음수 |

→ **0이 될 때까지 정리**한 뒤 마감으로 넘어갑니다.

### 5-2. 마감 잠금

1. 【회계 › 설정 › 잠금일】에 마감 기준일 설정
2. 그 이전 일자로는 전표 입력·수정이 **차단**됨
3. 잠금을 **되돌리면(완화) 차단되지 않고 이력이 남습니다** —
   【회계 › **마감 잠금 변경 이력**】에 누가·언제·어느 필드를·어디서 어디로·완화/해제가
   불변 기록으로 적립 (수정신고 등 정당한 사유가 있어 봉쇄 대신 추적하는 설계)

## 6. 자주 걸리는 것

| 증상 | 원인·조치 |
|---|---|
| 대사가 안 맞는다 (실적 ≠ 계산서 ≠ 원장) | 청구서를 **게시하지 않음**이 1순위. 다음은 소급 단가 미반영, 정산 기간 누락 |
| 승인번호 저장이 안 된다 | 이미 같은 번호가 등록됨 — 중복 차단. 기존 전표를 찾아 확인 |
| 부가세 자료에 안 잡힌다 | 라인에 세금 코드 없음 (체크리스트 "세금 없는 청구 라인") |
| 입고했는데 장부에 아무 것도 없다 | 정상 — 입고는 수량만 움직임. 회계는 정산·청구서 게시 시점 |
| 과거 일자 전표가 안 들어간다 | 마감 잠금일 설정됨 — 잠금일 확인 후 필요시 완화(이력 남음) |
