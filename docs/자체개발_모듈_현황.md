## 10. 개발 규칙 (지켜지고 있는 것)

1. **정본 단일화** — 수요는 `production_planning`, 결재는 `iatf_approval`, 시리얼은 `escon_serial`.
   같은 문제를 푸는 모듈을 새로 만들지 않는다
2. **정책은 데이터** — 요율·단위 기준·검사 기준·점검 주기를 코드가 아닌 마스터에 둔다
3. **자격증명은 DB 파라미터** — 오라클·포털 토큰 등을 코드·git 에 두지 않는다
4. **브랜치 → PR** — main·18.0 직접 push 금지
5. **테스트 동봉** — 기능마다 정상·경계·차단 3종
6. **기존 DB 업그레이드로 검증** — 신선 설치만으로는 마이그레이션 결함이 안 잡힌다
   (실사례: 필드 기본값이 박힌 행은 `COALESCE` 로 못 걸러 실적 라인 이관 누락)
