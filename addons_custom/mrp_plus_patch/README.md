# 수량 소수점 복원 패치 (mrp_plus_patch)

수량 표시 자리수(`decimal.precision` 의 "Product Unit of Measure")를 Odoo 기본값
**2자리로 복원**한다. 운영 DB 에서 이 값이 0으로 내려가 있어 BOM 원재료 소요량,
생산/재고 수량이 전부 정수로만 표시되던 것을 되돌린다.

## 왜 필요한가

- 사출품 BOM 은 부품 1EA 당 원재료(레진) 소요량을 kg 단위 소수로 계산한다
  (예: 0.02 kg/EA). 자리수 0이면 이 값이 화면에서 0 또는 정수로 보인다.
- **값 자체는 살아 있다**: 모든 단위(`uom.uom`)의 반올림 계수가 0.01 이라 저장은
  소수점을 유지한다. 잘린 것은 표시 자리수뿐이므로 되돌리면 즉시 복구된다.
- 금액 쪽 `.00` 제거는 `account_kr_plus_patch` 가 담당한다 — 두 모듈이 자리수
  소스를 금액/수량으로 분리해 서로 간섭하지 않는다.

## 종속성

`injection_worksite` (사출 현장) 와 한 세트로 묶었다 — 원재료 소요량 소수점이
필요한 대표 사용처. worksite 가 `mrp`·`stock`·`product`·`purchase`·
`injection_planning` 을 전부 끌고 오므로, 이 정확도 하나로 BOM·생산오더·
재고이동·구매수량까지 모두 커버된다.

> `injection_worksite` 는 이 레포(addons_custom)가 아니라 `odoo_gh/odoo_plugins`
> 에 있다. 두 경로 모두 addons_path 에 있어 런타임 의존성은 문제없다.

## 조정 방법

- 더 미세한 자리수(예: 3자리)가 필요하면: 설정 > 기술 > 소수점 정확도에서
  "Product Unit of Measure" 를 올린다. `noupdate` 라 업그레이드가 덮어쓰지 않는다.
- 0.01 보다 미세한 **값**이 필요하면 자리수만으론 부족하다 — 해당 단위
  (`uom.uom`)의 반올림 계수도 함께 내려야 한다 (예: 0.001).
- 자리수를 올리는 방향은 안전하다. 단, 과거 자리수 0 시절에 이미 반올림되어
  **저장된** 값이 있다면 그 값은 복구되지 않는다 (uom rounding 0.01 덕분에
  대부분은 무사).
