# Odoo 18 회계 담당자 운영 가이드

- 대상 모듈: `account_kr_plus_patch`
- 대상 사용자: 회계 담당자, 회계 관리자
- 기준 버전: Odoo 18
- 최종 갱신일: 2026-08-31

## 1. 문서 목적

이 문서는 다음 업무를 회사 기준에 맞게 처리하는 방법을 설명합니다.

- 매입처 세금계산서와 매입처 취소 세금계산서 조회·입력
- 일반 전표 입력과 전기
- 당좌예금 계정과 실제 은행계좌 연결
- 저널 및 계정과목 관리
- 한국식 전표번호 형식과 전표유형 코드 관리
- 주요 오류 메시지 확인 및 조치

> 이 문서에서 `전기`는 초안 전표를 회계장부에 확정 반영하는 작업을 의미합니다.

## 2. 권한별 업무 범위

| 업무 | 일반 회계 담당자 | 회계 관리자 |
|---|---:|---:|
| 매입처 세금계산서 입력·조회 | 가능 | 가능 |
| 매입처 취소 세금계산서 입력·조회 | 가능 | 가능 |
| 일반 전표 입력·조회 | 가능 | 가능 |
| 전표 전기·초안 복귀 | 부여된 회계 권한과 잠금 상태에 따라 가능 | 가능 |
| 당좌예금 연결 은행계좌 선택 | 가능 | 가능 |
| 은행 저널·계좌정보 변경 | 불가 | 가능 |
| 계정과목 기준정보 변경 | 불가 | 가능 |
| 전표번호 형식·유형 코드 변경 | 불가 | 가능 |
| 기존 전표번호 점검·수정 | 불가 | 가능 |

회계 관리자 전용 설정은 `회계 > 환경설정 > 한국식 회계 설정`에서 관리합니다.
일반 회계 담당자에게 설정 변경이 필요하면 회계 관리자에게 요청해야 합니다.

## 3. 주요 메뉴

| 메뉴 경로 | 용도 |
|---|---|
| `회계 > 공급업체 > 매입처 세금계산서` | 정상 매입 세금계산서 입력·조회 |
| `회계 > 공급업체 > 매입처 취소 세금계산서` | 환불·취소 매입 세금계산서 입력·조회 |
| `회계 > 회계 > 전표` | 일반 수동 전표 입력·조회 |
| `회계 > 환경설정 > 한국식 회계 설정` | 번호 형식과 회계 기준정보 관리 |
| `회계 > 환경설정 > 은행 > 계좌 설정` | 실제 은행계좌별 저널 관리 |

Odoo 언어 설정에 따라 `공급업체`가 `Vendors`, `환경설정`이 `Configuration`으로
표시될 수 있습니다.

## 4. 매입처 세금계산서 처리

### 4.1 정상 매입 세금계산서

1. `회계 > 공급업체 > 매입처 세금계산서`로 이동합니다.
2. `신규`를 눌러 전표를 만듭니다.
3. 다음 헤더 정보를 확인하거나 입력합니다.
   - 전표일자
   - 거래처
   - 적요
   - 청구서(세금계산서) 참조
   - 세금계산서승인번호
4. `청구 내역`에서 품목, 라벨, 계정과목, 수량, 단가, 세금을 입력합니다.
5. 공급가액, 세액, 총계가 원본 세금계산서와 일치하는지 확인합니다.
6. 품의 승인 여부가 필요한 건은 품의서 화면에서 승인 완료 상태를 확인합니다.
7. 이상이 없으면 `전기`합니다.

세금계산서승인번호는 중복 입력할 수 없습니다. 홈택스 자료와 대조할 때는 승인번호를
그대로 입력하고 공백이나 임의 문자를 덧붙이지 않습니다.

### 4.2 취소·환불 세금계산서

1. `회계 > 공급업체 > 매입처 취소 세금계산서`로 이동합니다.
2. 원본 거래처, 일자, 품목, 세금 및 금액을 확인해 취소 전표를 입력합니다.
3. 세금계산서승인번호와 원본 자료의 관계를 확인합니다.
4. 전기 후 전표번호 앞에 환불 표시 `R`이 붙었는지 확인합니다.

정상 매입 세금계산서를 음수로 임의 수정하는 것보다 취소 세금계산서 메뉴에서
환불 전표로 처리하는 것을 권장합니다.

### 4.3 매입 목록의 주요 열

| 열 | 의미 |
|---|---|
| 전표번호 | 전기 시 확정되는 회계 전표번호 |
| 세금계산서승인번호 | 국세청 승인번호, 중복 저장 불가 |
| 수기 | 시스템이 수동 수정 여부를 표시하는 값 |
| 매입처 | 공급업체 거래처 |
| 매입일 | 공급업체 청구서 일자 |
| 품목명 | 청구 내역의 주요 품목명 요약 |
| 공급가액·세액·합계 | 매입 금액 구성 |
| 증빙유형 | 세금계산서, 계산서, 카드, 현금영수증, 기타 |
| 구분 | 과세, 영세, 면세 구분 |
| 미납금액 | 전기 후 아직 결제되지 않은 금액 |
| 결제기한 | 취소·환불 세금계산서의 지급 기한 |
| 결제완료 금액 | 전기 금액 중 결제가 완료된 금액 |
| 결제상태 | 초안, 미결제, 부분결제, 결제 중, 결제완료 등의 상태 |

초안 전표의 미납금액은 총계로 보일 수 있으며, 결제 완료 금액은 전기 및 결제 처리
이후 계산됩니다. 결제상태는 결제 관련 열의 맨 뒤에 표시됩니다. 품의 결재상태는
결제상태와 혼동되지 않도록 청구서 목록에서 표시하지 않습니다.

### 4.4 승인번호 필드 운영 원칙

업무 화면과 다른 커스텀 모듈에서 사용하는 승인번호 정본은 다음 두 개입니다.

| 필드 | 입력 대상 |
|---|---|
| 세금계산서승인번호 (`kr_approval_number`) | 현재 세금계산서의 국세청 승인번호 |
| 원본 세금계산서 승인번호 (`kr_origin_number`) | 취소·수정분에 연결되는 당초 승인번호 |

Odoo 표준 `ref`는 화면에서 숨겨져 있지만 기존 거래처 청구서 번호와 내부 호환을 위해
보존됩니다. 과거 매입 청구서의 `ref`가 국세청 승인번호 형식이고 정본이 비어 있을
때만 정본으로 한 번 복사합니다. 정본을 `ref`에 되돌려 쓰거나 기존 정본을 덮어쓰지는
않습니다.

승인번호는 반입 중복 차단, 매출 매칭, 마감 점검, 품의서 연결에 사용되는 중요 매핑
데이터입니다. 한 번 입력한 번호는 빈 값으로 삭제할 수 없고, 전기된 전표에서는 다른
번호로 바꿀 수 없습니다. 오입력은 전표를 초안으로 되돌린 뒤 수정합니다.

과거 Studio 필드 `x_escon_tax_approval_no`가 있는 데이터베이스의 처리 순서:

1. 데이터베이스를 백업합니다.
2. `회계 > 회계 점검·조회(K) > 승인번호 필드 통합`에서 미리보기를 실행합니다.
3. 충돌, 형식 오류, 정본 누락과 값 불일치를 해결한 뒤 `실제로 적용`합니다.
4. Studio 화면 요소, 서버 자동화, 사용자 필터 등 표시된 내부 참조를 제거합니다.
5. 외부 API·ETL·BI가 `x_escon_tax_approval_no`를 읽지 않는지 별도로 확인합니다.
6. 시스템 관리자가 `백업 및 외부 연동 확인 완료`를 선택하고
   `Studio 호환 필드 제거`를 실행합니다.

모듈 설치·업그레이드만으로 Studio 필드나 그 값을 자동 삭제하지 않습니다. 필드가
이미 없는 데이터베이스는 별도 작업 없이 정본 두 필드만 사용합니다.

## 5. 일반 전표 입력

1. `회계 > 회계 > 전표`로 이동합니다.
   이 목록에는 일반 전표뿐 아니라 Odoo 청구서·세금계산서도 함께 표시됩니다.
2. `신규`를 누릅니다.
3. 전표일자, 거래처, 적요를 입력합니다.
4. `전표 항목`에서 각 라인의 계정과목, 라벨, 차변, 대변을 입력합니다.
5. 차변 합계와 대변 합계가 같은지 확인합니다.
6. 당좌예금 계정과목을 사용했다면 `연결 은행계좌`를 확인합니다.
7. 이상이 없으면 `전기`합니다.

전표번호와 총계는 사용자가 직접 계산해 입력하는 값이 아닙니다. 전표번호는 번호
규칙에 따라 발급되고, 총계는 전표 항목에서 계산됩니다.

## 6. 당좌예금과 은행계좌 연결

### 6.1 기본 원칙

Odoo에서는 실제 은행계좌마다 은행 저널을 하나씩 만드는 것을 원칙으로 합니다.

예시:

| 실제 은행계좌 | 은행 저널 | 연결 계정과목 |
|---|---|---|
| 국민은행 123-456 | 국민은행 운영계좌 | 당좌예금 또는 국민은행 당좌예금 |
| 신한은행 987-654 | 신한은행 운영계좌 | 당좌예금 또는 신한은행 당좌예금 |

은행별 장부잔액을 명확히 분리하려면 은행 저널과 계정과목을 1:1로 구성하는 것이 가장
안전합니다. 하나의 당좌예금 계정과목을 여러 은행 저널이 공유할 수도 있지만, 이 경우
각 전표 라인에서 실제 은행계좌를 선택해야 합니다.

### 6.2 전표 입력 시 자동 선택

전표 항목에서 계정유형이 당좌·현금성 자산인 계정과목을 선택하면 다음 기준으로
`연결 은행계좌`가 결정됩니다.

- 해당 계정과목에 연결된 은행 저널이 1개이면 자동 선택됩니다.
- 현재 전표 자체가 해당 은행 저널의 전표이면 현재 저널이 우선 선택됩니다.
- 같은 계정과목에 연결된 은행 저널이 2개 이상이면 사용자가 직접 선택해야 합니다.
- 연결된 은행 저널이 없으면 은행계좌 정보가 표시되지 않습니다.

선택한 은행 저널의 기본 계정과 전표 라인의 계정과목은 반드시 같아야 합니다.

### 6.3 회계 관리자의 은행 저널 등록

1. `회계 > 환경설정 > 은행 > 계좌 설정`으로 이동합니다.
2. 실제 계좌마다 은행 저널을 생성하거나 기존 저널을 엽니다.
3. 다음 항목을 확인합니다.
   - 은행계좌/저널명
   - 계좌번호
   - 은행
   - 당좌예금 계정과목
   - 저널 코드
   - 전표유형 코드
   - 회사
4. 저장 후 테스트 전표에서 연결 은행계좌가 자동 또는 수동으로 정상 선택되는지
   확인합니다.

은행 저널의 기본 계정과목을 변경하면 이후 전표의 자동 연결 결과가 달라집니다.
기존 거래가 있는 저널은 변경 전에 영향 범위를 검토해야 합니다.

## 7. 전표번호 관리

### 7.1 번호 구성

회계 관리자는 `회계 > 환경설정 > 한국식 회계 설정`에서 회사별 번호 형식을
선택합니다.

| 형식 | 예시 | 전표유형 코드 규칙 |
|---|---|---|
| 날짜-번호 | `R20260828000001` | 사용하지 않음 |
| 날짜-번호-전표유형 | `R20260828000001PUR` | 영문 대문자 정확히 3자리 |
| Odoo 기본 (관여하지 않음) | 저널별 Odoo 표준 번호 | 이 모듈이 발급에 관여하지 않음 |

번호의 의미:

- `R`: 환불·취소 전표에만 붙는 표시
- `20260828`: 전표일자 `YYYYMMDD`
- `000001`: 일자별 6자리 순번
- `PUR`: 날짜-번호-전표유형에서 사용하는 저널의 전표유형 코드

순번은 회사, 전표일자 및 정상·환불 구분을 기준으로 관리됩니다. `PUR`, `SAL`,
`GEN`처럼 전표유형 코드가 달라도 같은 날짜의 `NNNNNN` 순번을 함께 사용합니다.
전표유형 코드는 번호 끝에서 유형을 표시할 뿐 별도 순번을 만들지 않습니다. 같은
전표유형 코드를 여러 저널이 사용하더라도 각 저널별 순번으로 분리되지 않습니다.

### 7.2 형식 변경 절차

1. 변경 목적과 적용일을 내부적으로 확정합니다.
2. `한국식 회계 설정 > 전표 설정 > 전표유형 및 코드 설정`을 엽니다.
3. 날짜-번호-전표유형을 사용할 경우 모든 저널 코드가 영문 대문자 3자리인지 확인합니다.
4. 전표번호 형식을 선택하고 `저장`합니다.
5. 테스트 전표를 생성·전기해 번호를 확인합니다.
6. 정상 전표와 취소 전표를 각각 확인합니다.

이미 발급된 전표번호는 형식을 변경해도 수정되지 않습니다. 변경 후 새로 번호가
발급되는 전표부터 새 형식을 사용합니다.

Odoo 기본을 선택하면 신규 전표는 Odoo 저널의 표준 번호를 사용하며 이 모듈이
번호 형식에 관여하지 않습니다.

### 7.3 전표유형 코드 변경

`한국식 회계 설정 > 전표 설정 > 전표유형 및 코드 설정`에서 저널별 코드를
변경할 수 있습니다.

- `PUR`, `SAL`, `GEN`, `BNK`처럼 영문 대문자 3자리만 사용합니다.
- 공백, 한글, 특수문자 및 소문자는 사용하지 않습니다.
- 코드 의미를 사내 전표 규정과 함께 관리합니다.
- 사용 중인 코드를 변경할 때는 적용일과 변경 사유를 남깁니다.

코드를 변경해도 기존 번호의 끝 코드는 바뀌지 않습니다. 새 코드로 발급되는 번호도
회사·전표일자·정상/환불 구분의 공통 순번에서 계속 이어집니다. 코드를 바꾼다는
이유로 `NNNNNN`이 다시 시작되지는 않습니다.

> 전표번호 규칙에는 임의 정규식을 입력할 수 없습니다. 전표 발급 중단을 방지하기
> 위해 검증된 두 한국식 형식 또는 Odoo 기본만 선택할 수 있습니다.

### 7.4 기존 전표번호 점검 및 수정

형식이 일치하지 않거나 번호의 순번을 인식할 수 없는 기존 전표, 또는 서로 다른
전표유형이 같은 날짜·순번을 중복 사용한 전표는
`한국식 회계 설정 > 전표 설정 > 전표번호 점검 및 수정`에서 처리합니다.

1. 먼저 `한국식 회계 설정`에서 사용할 번호 형식을 저장합니다.
2. 위저드에서 회사, 기간, 대상 저널을 선택합니다.
3. 필요하면 `번호가 지정된 미전기 전표 포함`을 선택합니다.
4. `대상 찾기 및 미리보기`를 누릅니다. 이 단계에서는 전표가 변경되지 않습니다.
5. 현재 번호, 발견 유형, 변경 예정 번호, 적용 가능 여부와 사유를 한 화면에서
   확인합니다.
6. 검토가 끝난 뒤 `적용 가능한 전표번호 변경`을 누릅니다.

위저드는 전표번호만 변경합니다. 전표일자, 저널, 거래처, 금액, 분개라인 및 결제
정보는 변경하지 않습니다. 해시로 보호된 전표, 잠긴 회계기간의 전표, 저널의 사용자
정규식과 충돌하는 번호는 `적용 불가`로 표시하며 그대로 둡니다. Odoo 기본은 모듈이
번호 형식에 관여하지 않는 선택지이므로 이 위저드의 자동 수정 대상이 아닙니다.

## 8. 계정과목 변경

회계 관리자는 `한국식 회계 설정 > 계정과목 설정` 또는
`회계 > 환경설정 > 회계 > 계정과목표`에서 계정과목을 관리합니다.

변경 전 확인사항:

- 계정코드와 명칭을 기존 거래에서 사용했는지 확인합니다.
- 계정유형 변경이 재무상태표·손익계산서 분류에 미치는 영향을 확인합니다.
- 당좌예금 계정이면 연결된 은행 저널을 확인합니다.
- 세금, 결제, 환차손익 또는 내부이체의 기본 계정으로 사용 중인지 확인합니다.
- 변경 요청자, 승인자, 변경 사유와 적용일을 기록합니다.

권장 운영 원칙:

- 사용 이력이 있는 계정코드를 다른 의미로 재사용하지 않습니다.
- 계정 성격이 달라지는 경우 기존 계정을 바꾸기보다 새 계정을 추가하는 방안을 먼저
  검토합니다.
- 이미 전기된 전표 라인의 계정과목은 직접 바꾸지 않습니다.
- 수정이 필요하면 잠금일과 감사추적 정책을 확인한 뒤 승인된 절차에 따라 초안 복귀,
  역분개 또는 수정 전표를 사용합니다.

## 9. 전기 전 점검표

### 매입처 세금계산서

- [ ] 거래처와 사업자등록정보가 원본 증빙과 일치한다.
- [ ] 전표일자와 세금계산서 일자가 맞다.
- [ ] 승인번호가 정확하며 중복되지 않는다.
- [ ] 품목, 공급가액, 세액, 합계가 원본과 일치한다.
- [ ] 과세·영세·면세 구분이 세금 설정과 일치한다.
- [ ] 품의서가 연결된 경우 승인 완료 상태다.

### 일반 전표

- [ ] 차변과 대변 합계가 같다.
- [ ] 거래처와 적요가 사후 확인 가능한 수준으로 입력됐다.
- [ ] 당좌예금 라인의 실제 연결 은행계좌가 맞다.
- [ ] 전표일자가 회계 잠금일 이후다.

### 설정 변경

- [ ] 변경 권한과 내부 승인을 확인했다.
- [ ] 대상 회사와 저널을 정확히 선택했다.
- [ ] 기존 전표와 보고서에 미치는 영향을 검토했다.
- [ ] 변경 사유와 적용일을 기록했다.
- [ ] 변경 후 정상·취소 테스트 전표를 확인했다.

## 10. 오류 메시지와 조치

### “동일한 당좌예금 계정과목에 은행계좌가 여러 개 연결되어 있습니다”

원인: 한 계정과목을 여러 은행 저널이 공유하지만 전표 라인에서 실제 은행계좌를
선택하지 않았습니다.

조치: 오류에 표시된 계정과목의 전표 라인에서 `연결 은행계좌`를 선택한 뒤 다시
전기합니다.

### “연결 은행계좌의 기본 계정과 현재 계정과목이 일치하지 않습니다”

원인: 전표 라인의 계정과목과 선택한 은행 저널의 기본 계정과목이 다릅니다.

조치: 올바른 은행 저널을 선택하거나 회계 관리자에게 저널 설정 확인을 요청합니다.

### “전표유형 코드는 영문 대문자 3자리로 입력해야 합니다”

원인: 저널의 전표유형 코드가 3자리 규칙에 맞지 않습니다.

조치:

- `PUR`, `SAL`, `GEN`, `BNK`처럼 영문 대문자 3자리로 수정합니다.

### “전표유형 코드를 영문 대문자 3자리로 수정해야 하는 저널이 있습니다”

원인: 현재 등록된 일부 저널 코드가 변경하려는 번호 형식의 조건을 충족하지 않습니다.

조치: 메시지에 표시된 저널의 코드를 먼저 수정한 뒤 번호 형식을 저장합니다.

### “이미 업로드된 세금계산서입니다”

원인: 같은 세금계산서승인번호가 이미 등록돼 있습니다.

조치: 새 전표를 만들지 말고 기존 전표를 검색해 거래처, 금액 및 상태를 확인합니다.

### “품의서가 아직 승인되지 않았습니다”

원인: 전표에 연결된 품의서가 승인 완료 상태가 아닙니다.

조치: 품의 결재를 완료하거나 잘못 연결된 품의서인지 확인한 뒤 다시 전기합니다.

## 11. 월마감 전 권장 확인사항

- 미결 초안과 전기 실패 전표가 남아 있는지 확인합니다.
- 매입처 세금계산서 승인번호 누락과 중복 여부를 확인합니다.
- 미납금액과 결제 완료 금액을 거래처 원장과 대조합니다.
- 당좌예금 전표의 연결 은행계좌 누락 여부를 확인합니다.
- 은행별 Odoo 잔액과 실제 은행 잔액을 조정합니다.
- 계정과목·저널·전표유형 코드와 전표번호 수정 내역을 검토합니다.
- 회계 잠금일을 설정하기 전에 수정 요청이 모두 반영됐는지 확인합니다.

## 12. 문의 시 준비할 정보

오류를 전달할 때 다음 정보를 함께 제공하면 원인 확인이 빨라집니다.

- 회사명
- 메뉴 경로
- 전표번호 또는 초안 식별정보
- 전표일자와 저널명
- 사용한 계정과목과 연결 은행계좌
- 화면에 표시된 오류 메시지 전문
- 오류 발생 직전에 수행한 작업

사업자등록번호, 전체 은행계좌번호 또는 개인정보가 포함된 화면은 사내 보안 기준에
따라 필요한 부분을 가린 뒤 공유합니다.
