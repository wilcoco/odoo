# Odoo 18 회계 담당자 운영 가이드

- 대상 모듈: `account_kr_plus_patch`
- 대상 사용자: 회계 담당자, 회계 관리자
- 기준 버전: Odoo 18
- 최종 갱신일: 2026-08-28

## 1. 문서 목적

이 문서는 다음 업무를 회사 기준에 맞게 처리하는 방법을 설명합니다.

- 매입처 세금계산서와 매입처 취소 세금계산서 조회·입력
- 일반 전표 입력과 전기
- 당좌·보통예금 계정과 실제 은행계좌 연결
- 저널 및 계정과목 관리
- 한국식 전표번호 형식과 전표유형 코드 관리
- 주요 오류 메시지 확인 및 조치

> 이 문서에서 `전기`는 초안 전표를 회계장부에 확정 반영하는 작업을 의미합니다.

## 2. 권한별 업무 범위

| 업무 | 일반 회계 담당자 | 회계 관리자 |
|---|---:|---:|
| 매입처 세금계산서 입력·조회 | 가능 | 가능 |
| 매입처 취소 세금계산서 입력·조회 | 가능 | 가능 |
| 일반 전표 입력·조회 | 가능 | 가능 |
| 전표 전기·초안 복귀 | 부여된 회계 권한과 잠금 상태에 따라 가능 | 가능 |
| 당좌·보통예금 연결 은행계좌 선택 | 가능 | 가능 |
| 은행 저널·계좌정보 변경 | 불가 | 가능 |
| 계정과목 기준정보 변경 | 불가 | 가능 |
| 전표번호 형식·유형 코드 변경 | 불가 | 가능 |

회계 관리자 전용 설정은 `회계 > 환경설정 > 한국식 회계 설정`에서 관리합니다.
일반 회계 담당자에게 설정 변경이 필요하면 회계 관리자에게 요청해야 합니다.

## 3. 주요 메뉴

| 메뉴 경로 | 용도 |
|---|---|
| `회계 > 공급업체 > 매입처 세금계산서` | 정상 매입 세금계산서 입력·조회 |
| `회계 > 공급업체 > 매입처 취소 세금계산서` | 환불·취소 매입 세금계산서 입력·조회 |
| `회계 > 회계 > 전표` | 일반 수동 전표 입력·조회 |
| `회계 > 환경설정 > 한국식 회계 설정` | 번호 형식과 회계 기준정보 관리 |
| `회계 > 환경설정 > 은행 > 당좌·보통예금 은행계좌` | 실제 은행계좌별 저널 관리 |

Odoo 언어 설정에 따라 `공급업체`가 `Vendors`, `환경설정`이 `Configuration`으로
표시될 수 있습니다.

## 4. 매입처 세금계산서 처리

### 4.1 정상 매입 세금계산서

1. `회계 > 공급업체 > 매입처 세금계산서`로 이동합니다.
2. `신규`를 눌러 전표를 만듭니다.
3. 다음 헤더 정보를 확인하거나 입력합니다.
   - 전표일자
   - 거래처
   - 적요
   - 청구서(세금계산서) 참조
   - 세금계산서승인번호
4. `청구 내역`에서 품목, 라벨, 계정과목, 수량, 단가, 세금을 입력합니다.
5. 공급가액, 세액, 총계가 원본 세금계산서와 일치하는지 확인합니다.
6. 품의서가 연결된 청구서는 결재상태가 승인 완료인지 확인합니다.
7. 이상이 없으면 `전기`합니다.

세금계산서승인번호는 중복 입력할 수 없습니다. 홈택스 자료와 대조할 때는 승인번호를
그대로 입력하고 공백이나 임의 문자를 덧붙이지 않습니다.

### 4.2 취소·환불 세금계산서

1. `회계 > 공급업체 > 매입처 취소 세금계산서`로 이동합니다.
2. 원본 거래처, 일자, 품목, 세금 및 금액을 확인해 취소 전표를 입력합니다.
3. 세금계산서승인번호와 원본 자료의 관계를 확인합니다.
4. 전기 후 전표번호 앞에 환불 표시 `R`이 붙었는지 확인합니다.

정상 매입 세금계산서를 음수로 임의 수정하는 것보다 취소 세금계산서 메뉴에서
환불 전표로 처리하는 것을 권장합니다.

### 4.3 매입 목록의 주요 열

| 열 | 의미 |
|---|---|
| 전표번호 | 전기 시 확정되는 회계 전표번호 |
| 세금계산서승인번호 | 국세청 승인번호, 중복 저장 불가 |
| 수기 | 시스템이 수동 수정 여부를 표시하는 값 |
| 매입처 | 공급업체 거래처 |
| 매입일 | 공급업체 청구서 일자 |
| 품목명 | 청구 내역의 주요 품목명 요약 |
| 공급가액·세액·합계 | 매입 금액 구성 |
| 증빙유형 | 세금계산서, 계산서, 카드, 현금영수증, 기타 |
| 구분 | 과세, 영세, 면세 구분 |
| 결재상태 | 연결된 품의서의 승인 상태 |
| 결제상태 | 초안, 미결제, 부분결제, 결제 중, 결제완료 등의 상태 |
| 미납금액 | 전기 후 아직 결제되지 않은 금액 |
| 결제완료 금액 | 전기 금액 중 결제가 완료된 금액 |

초안 전표의 미납금액은 총계로 보일 수 있으며, 결제 완료 금액은 전기 및 결제 처리
이후 계산됩니다.

## 5. 일반 전표 입력

1. `회계 > 회계 > 전표`로 이동합니다.
   이 목록에는 일반 전표뿐 아니라 Odoo 청구서·세금계산서도 함께 표시됩니다.
2. `신규`를 누릅니다.
3. 전표일자, 거래처, 적요를 입력합니다.
4. `전표 항목`에서 각 라인의 계정과목, 라벨, 차변, 대변을 입력합니다.
5. 차변 합계와 대변 합계가 같은지 확인합니다.
6. 당좌·보통예금 계정과목을 사용했다면 `연결 은행계좌`를 확인합니다.
7. 이상이 없으면 `전기`합니다.

전표번호와 총계는 사용자가 직접 계산해 입력하는 값이 아닙니다. 전표번호는 번호
규칙에 따라 발급되고, 총계는 전표 항목에서 계산됩니다.

## 6. 당좌·보통예금과 은행계좌 연결

### 6.1 기본 원칙

Odoo에서는 실제 은행계좌마다 은행 저널을 하나씩 만드는 것을 원칙으로 합니다.

예시:

| 실제 은행계좌 | 은행 저널 | 연결 계정과목 |
|---|---|---|
| 국민은행 123-456 | 국민은행 운영계좌 | 보통예금 또는 국민은행 보통예금 |
| 신한은행 987-654 | 신한은행 운영계좌 | 보통예금 또는 신한은행 보통예금 |

은행별 장부잔액을 명확히 분리하려면 은행 저널과 계정과목을 1:1로 구성하는 것이 가장
안전합니다. 하나의 보통예금 계정과목을 여러 은행 저널이 공유할 수도 있지만, 이 경우
각 전표 라인에서 실제 은행계좌를 선택해야 합니다.

### 6.2 전표 입력 시 자동 선택

전표 항목에서 계정유형이 당좌·현금성 자산인 계정과목을 선택하면 다음 기준으로
`연결 은행계좌`가 결정됩니다.

- 해당 계정과목에 연결된 은행 저널이 1개이면 자동 선택됩니다.
- 현재 전표 자체가 해당 은행 저널의 전표이면 현재 저널이 우선 선택됩니다.
- 같은 계정과목에 연결된 은행 저널이 2개 이상이면 사용자가 직접 선택해야 합니다.
- 연결된 은행 저널이 없으면 은행계좌 정보가 표시되지 않습니다.

선택한 은행 저널의 기본 계정과 전표 라인의 계정과목은 반드시 같아야 합니다.

### 6.3 회계 관리자의 은행 저널 등록

1. `회계 > 환경설정 > 은행 > 당좌·보통예금 은행계좌`로 이동합니다.
2. 실제 계좌마다 은행 저널을 생성하거나 기존 저널을 엽니다.
3. 다음 항목을 확인합니다.
   - 은행계좌/저널명
   - 계좌번호
   - 은행
   - 당좌·보통예금 계정과목
   - 저널 코드
   - 전표유형 코드
   - 회사
4. 저장 후 테스트 전표에서 연결 은행계좌가 자동 또는 수동으로 정상 선택되는지
   확인합니다.

은행 저널의 기본 계정과목을 변경하면 이후 전표의 자동 연결 결과가 달라집니다.
기존 거래가 있는 저널은 변경 전에 영향 범위를 검토해야 합니다.

## 7. 전표번호 관리

### 7.1 번호 구성

신규 전표는 기본적으로 Odoo 저널의 표준 번호 규칙을 사용합니다. 별도의 한국식
번호가 꼭 필요한 회사만 회계 관리자가 `회계 > 환경설정 > 한국식 회계 설정`에서
`한국식 전표번호 규칙 사용`을 켜고 회사별 번호 형식을 선택합니다.

| 형식 | 예시 | 전표유형 코드 규칙 |
|---|---|---|
| 기존 3자리 형식 | `R20260828000001PUR` | 영문 대문자 정확히 3자리 |
| 확장 형식 | `R20260828000001-PURCHASE` | 영문 대문자·숫자 2~10자리 |

번호의 의미:

- `R`: 환불·취소 전표에만 붙는 표시
- `20260828`: 전표일자 `YYYYMMDD`
- `000001`: 일자별 6자리 순번
- `PUR` 또는 `PURCHASE`: 저널의 전표유형 코드

순번은 저널, 전표일자, 전표유형 코드 및 정상·환불 구분을 기준으로 관리됩니다.

### 7.2 형식 변경 절차

1. 변경 목적과 적용일을 내부적으로 확정합니다.
2. `한국식 회계 설정`에서 `저널·전표유형 코드`를 엽니다.
3. 모든 저널 코드가 변경하려는 형식의 규칙에 맞는지 확인합니다.
4. `한국식 전표번호 규칙 사용`을 켠 뒤 전표번호 형식을 선택하고 `저장`합니다.
5. 테스트 전표를 생성·전기해 번호를 확인합니다.
6. 정상 전표와 취소 전표를 각각 확인합니다.

이미 발급된 전표번호는 형식을 변경해도 수정되지 않습니다. 변경 후 새로 번호가
발급되는 전표부터 새 형식을 사용합니다.

한국식 규칙을 끄면 신규 전표는 Odoo 저널의 표준 번호를 사용합니다. 번호 정규식
오류로 신규 청구서 작성이 막히는 경우 먼저 이 설정이 꺼져 있는지 확인합니다.

### 7.3 전표유형 코드 변경

`한국식 회계 설정 > 저널·전표유형 코드`에서 저널별 코드를 변경할 수 있습니다.

- 기존 형식: `PUR`, `SAL`, `GEN`, `BNK`처럼 영문 대문자 3자리
- 확장 형식: `PURCHASE`, `BANK01`처럼 영문 대문자·숫자 2~10자리
- 공백, 한글, 특수문자 및 소문자는 사용하지 않습니다.
- 코드 의미를 사내 전표 규정과 함께 관리합니다.
- 사용 중인 코드를 변경할 때는 적용일과 변경 사유를 남깁니다.

코드를 변경해도 기존 번호의 끝 코드는 바뀌지 않습니다. 새 코드로 발급되는 순번은
해당 일자와 저널에서 새로 시작하거나, 과거에 같은 코드를 사용한 적이 있으면 그
번호에서 이어질 수 있습니다.

> 전표번호 규칙에는 임의 정규식을 입력할 수 없습니다. 전표 발급 중단을 방지하기
> 위해 검증된 기존 형식과 확장 형식만 선택할 수 있습니다.

## 8. 계정과목 변경

회계 관리자는 `한국식 회계 설정 > 계정과목표` 또는
`회계 > 환경설정 > 회계 > 계정과목표`에서 계정과목을 관리합니다.

변경 전 확인사항:

- 계정코드와 명칭을 기존 거래에서 사용했는지 확인합니다.
- 계정유형 변경이 재무상태표·손익계산서 분류에 미치는 영향을 확인합니다.
- 당좌·보통예금 계정이면 연결된 은행 저널을 확인합니다.
- 세금, 결제, 환차손익 또는 내부이체의 기본 계정으로 사용 중인지 확인합니다.
- 변경 요청자, 승인자, 변경 사유와 적용일을 기록합니다.

권장 운영 원칙:

- 사용 이력이 있는 계정코드를 다른 의미로 재사용하지 않습니다.
- 계정 성격이 달라지는 경우 기존 계정을 바꾸기보다 새 계정을 추가하는 방안을 먼저
  검토합니다.
- 이미 전기된 전표 라인의 계정과목은 직접 바꾸지 않습니다.
- 수정이 필요하면 잠금일과 감사추적 정책을 확인한 뒤 승인된 절차에 따라 초안 복귀,
  역분개 또는 수정 전표를 사용합니다.

## 9. 전기 전 점검표

### 매입처 세금계산서

- [ ] 거래처와 사업자등록정보가 원본 증빙과 일치한다.
- [ ] 전표일자와 세금계산서 일자가 맞다.
- [ ] 승인번호가 정확하며 중복되지 않는다.
- [ ] 품목, 공급가액, 세액, 합계가 원본과 일치한다.
- [ ] 과세·영세·면세 구분이 세금 설정과 일치한다.
- [ ] 품의서가 연결된 경우 승인 완료 상태다.

### 일반 전표

- [ ] 차변과 대변 합계가 같다.
- [ ] 거래처와 적요가 사후 확인 가능한 수준으로 입력됐다.
- [ ] 당좌·보통예금 라인의 실제 연결 은행계좌가 맞다.
- [ ] 전표일자가 회계 잠금일 이후다.

### 설정 변경

- [ ] 변경 권한과 내부 승인을 확인했다.
- [ ] 대상 회사와 저널을 정확히 선택했다.
- [ ] 기존 전표와 보고서에 미치는 영향을 검토했다.
- [ ] 변경 사유와 적용일을 기록했다.
- [ ] 변경 후 정상·취소 테스트 전표를 확인했다.

## 10. 오류 메시지와 조치

### “동일한 당좌·보통예금 계정과목에 은행계좌가 여러 개 연결되어 있습니다”

원인: 한 계정과목을 여러 은행 저널이 공유하지만 전표 라인에서 실제 은행계좌를
선택하지 않았습니다.

조치: 오류에 표시된 계정과목의 전표 라인에서 `연결 은행계좌`를 선택한 뒤 다시
전기합니다.

### “연결 은행계좌의 기본 계정과 현재 계정과목이 일치하지 않습니다”

원인: 전표 라인의 계정과목과 선택한 은행 저널의 기본 계정과목이 다릅니다.

조치: 올바른 은행 저널을 선택하거나 회계 관리자에게 저널 설정 확인을 요청합니다.

### “전표유형 코드를 영문 대문자 … 자리로 입력해야 합니다”

원인: 선택된 번호 형식과 저널의 전표유형 코드가 맞지 않습니다.

조치:

- 기존 형식이면 영문 대문자 3자리로 수정합니다.
- 확장 형식이면 영문 대문자·숫자 2~10자리로 수정합니다.

### “선택한 전표번호 형식에 맞지 않는 전표유형 코드가 있습니다”

원인: 현재 등록된 일부 저널 코드가 변경하려는 번호 형식의 조건을 충족하지 않습니다.

조치: 메시지에 표시된 저널의 코드를 먼저 수정한 뒤 번호 형식을 저장합니다.

### “이미 업로드된 세금계산서입니다”

원인: 같은 세금계산서승인번호가 이미 등록돼 있습니다.

조치: 새 전표를 만들지 말고 기존 전표를 검색해 거래처, 금액 및 상태를 확인합니다.

### “품의서가 아직 승인되지 않았습니다”

원인: 전표에 연결된 품의서가 승인 완료 상태가 아닙니다.

조치: 품의 결재를 완료하거나 잘못 연결된 품의서인지 확인한 뒤 다시 전기합니다.

## 11. 월마감 전 권장 확인사항

- 미결 초안과 전기 실패 전표가 남아 있는지 확인합니다.
- 매입처 세금계산서 승인번호 누락과 중복 여부를 확인합니다.
- 미납금액과 결제 완료 금액을 거래처 원장과 대조합니다.
- 당좌·보통예금 전표의 연결 은행계좌 누락 여부를 확인합니다.
- 은행별 Odoo 잔액과 실제 은행 잔액을 조정합니다.
- 계정과목·저널·전표유형 코드 변경 내역을 검토합니다.
- 회계 잠금일을 설정하기 전에 수정 요청이 모두 반영됐는지 확인합니다.

## 12. 문의 시 준비할 정보

오류를 전달할 때 다음 정보를 함께 제공하면 원인 확인이 빨라집니다.

- 회사명
- 메뉴 경로
- 전표번호 또는 초안 식별정보
- 전표일자와 저널명

- 오류 발생 직전에 수행한 작업

따라 필요한 부분을 가린 뒤 공유합니다.
