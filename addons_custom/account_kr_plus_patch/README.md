# 회계 한국식 통합 Plus Patch (`account_kr_plus_patch`)

Odoo 18의 회계 화면과 원화 표시를 회사 운영 방식에 맞추는 통합 패치 모듈입니다.

이 모듈은 다음 두 영역을 함께 담당합니다.

1. 원화 환경의 금액·단가 소수점 표시 보정
2. 매입 화면, 한국식 전표번호, 당좌·보통예금 은행계좌 연결

## 회계 화면·전표번호·은행계좌

- 공급업체 메뉴를 `매입처 세금계산서`, `매입처 취소 세금계산서`로 분리합니다.
- 매입 목록에 승인번호, 수기 여부, 품목명, 공급가액·세액·합계,
  증빙유형, 과세구분, 품의 결재상태, 미납·결제 금액을 표시합니다.
- 회사용 전표 폼은 요청한 헤더 필드만 표시하고 청구 내역과 전표 항목은 유지합니다.
- 회계 관리자가 `회계 > 환경설정 > 한국식 회계 설정`에서 신규 전표번호
  형식을 선택할 수 있습니다.
  - 기존 형식: `R?YYYYMMDDNNNNNNTTT`
  - 확장 형식: `R?YYYYMMDDNNNNNN-TYPECODE`
  - `R`: 환불/취소 전표
  - `YYYYMMDD`: 회계일자
  - `NNNNNN`: 저널·일자·정상/취소 구분별 6자리 순번
  - `TTT`: 기존 형식의 영문 대문자 3자리 전표유형 코드
  - `TYPECODE`: 확장 형식의 영문 대문자·숫자 2~10자리 전표유형 코드
- 당좌·보통예금 계정과목과 실제 은행저널/계좌번호의 연결을 전표 항목에서 표시합니다.

### 은행계좌 설정

`회계 > 환경설정 > 은행 > 당좌·보통예금 은행계좌`에서 실제 은행계좌마다
은행저널을 하나씩 만듭니다. 각 저널의 `은행 계정`에는 해당 계좌용 당좌·보통예금
계정과목을 지정합니다.

한 계정과목을 여러 은행저널이 공유하면 수동 전표에서 `연결 은행계좌`를 반드시
선택해야 합니다. 은행별 잔액을 계정과목에서도 완전히 분리하려면 은행저널과
계정과목을 1:1로 구성하는 것을 권장합니다.

### 기존 전표번호

설치 전에 전기된 Odoo 기본 형식의 전표번호는 변경하지 않습니다. 신규 전표와 새
형식으로 이미 발급된 전표에만 한국식 번호 파서를 적용합니다. 설정에서 번호 형식이나
전표유형 코드를 변경해도 기존 번호는 발급 당시 형식으로 계속 인식합니다.

## 원화 금액 소수점 표시

원화(KRW) 환경에서 회계·구매·판매·재고평가 화면에 남는 `.00` 표시를 제거합니다.
`account_kr_guard`를 건드리지 않는 별도 구현이며, 명시적인 화이트리스트의 필드만
변경합니다.

### 배경

Odoo의 금액 표시 자리수는 다음 세 곳에서 결정됩니다.

| 자리수 소스 | 대상 | 상태 |
|---|---|---|
| `res.currency.rounding` | `fields.Monetary` | KRW 통화 설정으로 처리 |
| `decimal.precision` | `digits="이름"`인 Float | UI 설정으로 처리 |
| 소스 기본값 `(16, 2)` | `digits` 미지정 Float | 이 모듈에서 처리 |

계정과목 잔액, 청구서 분석 금액, 구매 청구 대사 금액, 재고 평가액 등 일부 Float
필드는 통화 설정만으로 `.00`을 제거할 수 없어 별도 보정이 필요합니다.

### 동작 방식

1. `data/decimal_precision.xml`에서 `KR Amount` 정확도를 0자리로 등록합니다.
2. `models/kr_amount_digits.py`의 레지스트리 훅이 화이트리스트 필드만 보정합니다.
   - 금액 필드: `KR Amount`
   - 단가 필드: `Product Price`

### 안전장치

- 화이트리스트에 등록된 필드만 변경합니다.
- 수량 필드는 변경하지 않습니다.
- 저장 필드는 스키마 변경을 피하기 위해 자동 제외합니다.
- 다른 모듈이 이미 자리수를 지정한 필드는 존중합니다.
- 미설치 모델은 조용히 건너뜁니다.
- `account_kr_plus_patch.integer_amounts = 0` 시스템 파라미터와 서버 재시작으로
  소수점 표시 보정을 끌 수 있습니다.

### 적용 대상

- `account.account.current_balance`
- `account.invoice.report`의 공급가액·합계·평균가·마진·재고가치
- `purchase.bill.union.amount`, `sale.order.amount_paid`
- 재고 평가 관련 비저장 금액 필드
- 구매·판매 단가 관련 비저장 필드

## K-Guard 이관 주의사항

소수점 표시 기능의 K-Guard 이관 절차는 [HANDOVER.md](HANDOVER.md)를 참고합니다.
이 모듈은 이제 회계 화면과 전표번호 기능도 포함하므로 **모듈 전체를 제거하면 안
됩니다**. 이관 시에는 소수점 표시 구성요소와 `KR Amount` 데이터의 소유권만 별도로
조정해야 합니다.

## 검증

```text
--test-enable --test-tags=/account_kr_plus_patch
```

소수점 표시, 수량 필드 미변경, 전표번호 호환성, 설정 권한, 은행계좌 연결을 함께
검증합니다.
