# 회계 한국식 통합 Plus Patch (`account_kr_plus_patch`)

Odoo 18의 회계 화면과 원화 표시를 회사 운영 방식에 맞추는 통합 패치 모듈입니다.

회계 담당자의 화면 사용법과 운영상 주의사항은
[`docs/ACCOUNTING_USER_GUIDE_KO.md`](docs/ACCOUNTING_USER_GUIDE_KO.md)를 참고하세요.

이 모듈은 다음 두 영역을 함께 담당합니다.

1. 원화 환경의 금액·단가 소수점 표시 보정
2. 매출·매입 세금계산서 화면, 한국식 전표번호, 당좌예금 은행계좌 연결

## 회계 화면·전표번호·은행계좌

- 회계 앱의 `회계` 메뉴 바로 옆에 회계 관리자용 `자주 쓰는 설정`을 두고 일반 설정,
  한국식 회계 설정, 은행계좌 설정, 조정 방식, 계정과목표, 세금, 전표 유형, 고정자산,
  회계 보고서와 손금불산입 카테고리 바로가기를 한곳에 모읍니다.
- 고객·공급업체 메뉴를 각각 정상 세금계산서와 취소 세금계산서로 분리합니다.
- 매출·매입 목록은 승인번호, 수기 여부, 품목명, 공급가액·세액·합계,
  증빙유형과 과세구분까지 같은 순서로 표시합니다.
- 매출 목록은 받을 돈을 `미수금액·수금기한·수금완료 금액·수금상태`로,
  매입 목록은 낼 돈을 `미지급금액·지급기한·지급완료 금액·지급상태`로 구분합니다.
- 매입 목록에는 `품의서·품의 결재상태`를 별도 배지로 표시하고 미연결·결재대기
  필터를 제공합니다. 초안 공급업체 청구서는 거래처와 회사가 일치하는 지출 품의에
  직접 연결할 수 있으며, 미승인 품의가 연결된 청구서는 전기할 수 없습니다.
- 회사용 전표 폼은 요청한 헤더 필드만 표시하고 청구 내역과 전표 항목은 유지합니다.
- 초안의 Odoo 내부 전표번호 `/`은 업무 화면에서 `전기 시 자동 생성`으로 안내하고,
  전기 후 실제 발급된 전표번호를 표시합니다.
- 전표 목록에는 전표 또는 첫 유효 전표 항목에서 가져온 `거래처·적요·참조`를
  기본 표시합니다.
- `보통예금 종류`는 전표의 당좌예금 라인에 연결된 계좌 설정(은행 저널)을 태그로
  표시합니다. 기본 표시되는 선택 열이며 숨길 수 있고, 비은행 전표는 비어 있습니다.
- 회계 관리자가 `회계 > 환경설정 > 한국식 회계 설정`에서 다음 세 가지 중 하나를
  선택할 수 있습니다.
  - 날짜-번호: `R?YYYYMMDDNNNNNN`
  - 날짜-번호-전표유형: `R?YYYYMMDDNNNNNNTTT`
  - Odoo 기본 (관여하지 않음)
  - `R`: 환불/취소 전표
  - `YYYYMMDD`: 회계일자
  - `NNNNNN`: 회사·일자·정상/취소 구분별 공통 6자리 순번
  - `TTT`: 영문 대문자 3자리 전표유형 코드
- `TTT`는 전표의 유형 표시일 뿐 순번 그룹을 나누지 않습니다. 같은 회사의 같은
  일자에서는 `GEN`, `PUR`, `SAL` 등 모든 코드가 하나의 `NNNNNN` 순번을 공유하며,
  같은 `TTT`를 사용하는 저널이 여러 개여도 순번을 따로 만들지 않습니다.
- `전표번호 소급 변경 적용` 위저드는 현재 저장된 규칙과 다른 기존 번호를 검색하고 변경안을
  미리 보여줍니다. 유형별 발급으로 생긴 날짜·순번 중복도 함께 찾으며, 회계 관리자가
  확인한 건만 적용합니다. 실행 버튼을 누르면 화면의 전표번호 형식을 먼저 저장하며,
  전체 저널이 기본 선택됩니다. `직접 지정 전표도 포함`을 선택하면 번호가 입력된
  초안까지 검사합니다. 회계 내용은 건드리지 않고 전표번호만 변경합니다.
- 당좌예금 계정과목과 실제 은행저널/계좌번호의 연결을 전표 항목에서 표시합니다.
- 전표 메뉴에는 일반 전표와 Odoo 청구서·세금계산서를 함께 표시합니다.
- 증빙유형·과세구분·수금/지급상태와 품의 결재상태를 배지로 표시합니다.
- 청구서 목록 끝의 자금 관련 열은 `기한 → 완료 금액 → 상태` 순서로 표시합니다.
- 회사용 청구서 폼에는 별도의 `기타 정보` 탭을 두지 않습니다. 표준 폼으로
  진입하더라도 인코텀즈, 인도일, QR 방식, 현금반올림, 자동전기 등 국내
  세금계산서 입력에 사용하지 않는 항목은 숨깁니다.
- 세금계산서 업무 화면과 다른 모듈의 연동 정본은 현재 승인번호
  (`kr_approval_number`)와 수정분의 원본 승인번호(`kr_origin_number`)입니다.
  Odoo 표준 `ref`는 화면에서 숨겨 내부 호환용으로 보존합니다.
- 과거 Studio 필드 `x_escon_tax_approval_no`는 `승인번호 필드 통합`에서 전사 값과
  Odoo 내부 참조를 검증합니다. 자동 삭제하지 않으며, 검증·백업·외부 연동 확인이
  끝난 경우에만 시스템 관리자가 명시적으로 제거할 수 있습니다.

### 은행계좌 설정

`회계 > 환경설정 > 은행 > 계좌 설정`에서 실제 은행계좌마다
은행저널을 하나씩 만듭니다. 각 저널의 `은행 계정`에는 해당 계좌용 당좌예금
계정과목을 지정합니다. 이 메뉴에서 신규 생성하면 은행저널 유형을 고정하고,
계정과목을 따로 지정하지 않은 경우 `은행 및 현금` 유형의 당좌예금 계정을 자동으로
생성·연결합니다. 저장 후 Chatter에 연결 계정과 필수 확인 항목을 안내합니다.

한 계정과목을 여러 은행저널이 공유하면 수동 전표에서 `연결 은행계좌`를 반드시
선택해야 합니다. 은행별 잔액을 계정과목에서도 완전히 분리하려면 은행저널과
계정과목을 1:1로 구성하는 것을 권장합니다.

### 기존 전표번호

설치 전에 전기된 Odoo 기본 형식의 전표번호는 변경하지 않습니다. 신규 전표와 새
형식으로 이미 발급된 전표에만 한국식 번호 파서를 적용합니다. 설정에서 번호 형식이나
전표유형 코드를 변경해도 기존 번호는 발급 당시 형식으로 계속 인식합니다.

## 원화 금액 소수점 표시

원화(KRW) 환경에서 회계·구매·판매·재고평가 화면에 남는 `.00` 표시를 제거합니다.
`account_kr_guard`를 건드리지 않는 별도 구현이며, 명시적인 화이트리스트의 필드만
변경합니다.

### 배경

Odoo의 금액 표시 자리수는 다음 세 곳에서 결정됩니다.

| 자리수 소스 | 대상 | 상태 |
|---|---|---|
| `res.currency.rounding` | `fields.Monetary` | KRW 통화 설정으로 처리 |
| `decimal.precision` | `digits="이름"`인 Float | UI 설정으로 처리 |
| 소스 기본값 `(16, 2)` | `digits` 미지정 Float | 이 모듈에서 처리 |

계정과목 잔액, 청구서 분석 금액, 구매 청구 대사 금액, 재고 평가액 등 일부 Float
필드는 통화 설정만으로 `.00`을 제거할 수 없어 별도 보정이 필요합니다.

### 동작 방식

1. `data/decimal_precision.xml`에서 `KR Amount` 정확도를 0자리로 등록합니다.
2. `models/kr_amount_digits.py`의 레지스트리 훅이 화이트리스트 필드만 보정합니다.
   - 금액 필드: `KR Amount`
   - 단가 필드: `Product Price`

### 안전장치

- 화이트리스트에 등록된 필드만 변경합니다.
- 수량 필드는 변경하지 않습니다.
- 저장 필드는 스키마 변경을 피하기 위해 자동 제외합니다.
- 다른 모듈이 이미 자리수를 지정한 필드는 존중합니다.
- 미설치 모델은 조용히 건너뜁니다.
- `account_kr_plus_patch.integer_amounts = 0` 시스템 파라미터와 서버 재시작으로
  소수점 표시 보정을 끌 수 있습니다.

### 적용 대상

- `account.account.current_balance`
- `account.invoice.report`의 공급가액·합계·평균가·마진·재고가치
- `purchase.bill.union.amount`, `sale.order.amount_paid`
- 재고 평가 관련 비저장 금액 필드
- 구매·판매 단가 관련 비저장 필드

## K-Guard 이관 주의사항

소수점 표시 기능의 K-Guard 이관 절차는 [HANDOVER.md](HANDOVER.md)를 참고합니다.
이 모듈은 이제 회계 화면과 전표번호 기능도 포함하므로 **모듈 전체를 제거하면 안
됩니다**. 이관 시에는 소수점 표시 구성요소와 `KR Amount` 데이터의 소유권만 별도로
조정해야 합니다.

## 검증

```text
--test-enable --test-tags=/account_kr_plus_patch
```

소수점 표시, 수량 필드 미변경, 전표번호 호환성, 설정 권한, 은행계좌 연결을 함께
검증합니다.
