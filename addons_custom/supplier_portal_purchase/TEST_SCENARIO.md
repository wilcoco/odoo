# 외주 시스템 전체 테스트 시나리오

## 개요

```
[수요 데이터] → [외주 계획] → [자동 발주] → [협력사 포탈] → [입고/재고]
     ↓              ↓             ↓              ↓              ↓
production.demand → outsource.planning → purchase.order → 응답/승인 → stock.picking
```

---

## 사전 준비

### 1. 모듈 설치 (데모 데이터 포함)
```bash
./odoo-bin -c config.conf -i supplier_portal_purchase --demo
# 또는 업그레이드
./odoo-bin -c config.conf -u supplier_portal_purchase
```

### 2. 데모 데이터 확인

| 구분 | 데이터 |
|------|--------|
| 협력사 | 한국브라켓, 대한하우징, 삼성캡 |
| 외주품목 | 브라켓A/B, 하우징, 엔드캡A/B |
| 협력사발주 | 한국브라켓→삼성캡 5건 |

## Phase 1: 외주 조달 계획 수립

### 1.1 수요 데이터 생성 (또는 Oracle 연동)

**메뉴**: 생산계획 > 수요 데이터 > 새로 만들기

```
제품: 완제품 (BOM에 외주부품 포함된 것)
수요일: 2026-04-20 ~ 2026-04-25
수량: 각 100개
```

### 1.2 외주 조달 계획 생성

**메뉴**: 구매 > 외주 조달 > 조달 계획 > 새로 만들기

| 필드 | 값 |
|------|-----|
| 계획 시작일 | 2026-04-15 |
| 계획 종료일 | 2026-04-30 |

### 1.3 수요 로드 및 계산

```
[수요 로드] 클릭 → 수요 데이터 연결
[계산 실행] 클릭 → BOM 전개하여 외주 부품 수요 계산
```

**확인 사항**:
- [ ] 조달 계획 라인에 외주 부품별 일별 수요 표시
- [ ] 발주일 = 필요일 - 리드타임 계산 확인
- [ ] 안전재고 반영 확인

### 1.4 계획 확정 및 발주 생성

```
[확정] 클릭 → 상태: 검토 → 확정
[발주 생성] 클릭 → 협력사별 PO 자동 생성
```

**확인 사항**:
- [ ] 협력사별 purchase.order 생성
- [ ] PO에 auto_generated = True, portal_state = 'new'
- [ ] 협력사에 알림 발송 (supplier.portal.notification)

## Phase 2: 협력사 포탈 - 1차 협력사

### 2.1 한국브라켓 포탈 접속

> **포탈 URL 확인 방법** — 데모 토큰(`demo_token_…`)은 보안상 서버가 거부합니다.
> 실제 URL 은 백오피스 **구매 › 외주 관리 › 마스터 데이터 › 협력사 관리** 에서 협력사를 열어
> "포탈 접근 토큰" 을 복사하거나, 발주서의 "포탈 URL" 필드에서 확인하세요.
> (토큰이 없으면 [토큰 재생성] 버튼 — 발급 시 만료일 180일이 자동 설정됩니다.)

```
URL: http://localhost:8069/supplier/portal?token=<한국브라켓 포탈 접근 토큰>
```

### 2.2 에스콘에서 받은 발주 확인

**메뉴**: 받은 발주 > 에스콘에서 받은 발주

| 테스트 항목 | 확인 |
|------------|------|
| 신규 발주 목록 표시 | [ ] |
| 발주 상세 확인 | [ ] |
| 전체 승인 응답 | [ ] |
| 조건부 승인 (수량/납기 변경) | [ ] |
| 납품 불가 응답 | [ ] |

### 2.3 응답 제출

```
발주 상세 > [응답 제출]
- 전체 승인: 요청대로 납품 가능
- 조건부 승인: 수량/납기 조정
- 납품 불가: 거절
```

### 2.4 하위 업체에 발주 (2차 협력사)

**메뉴**: 보낸 발주 > 다른 업체에 보낸 발주 > [새 발주]

```
공급업체: 삼성캡(주)
제품: 엔드캡 A
수량: 500
납기일: 2026-04-18
```

**확인 사항**:
- [ ] supplier.order 생성
- [ ] 상태: 발주완료 (sent)
- [ ] 삼성캡에 알림 발송

## Phase 3: 협력사 포탈 - 2차 협력사

### 3.1 삼성캡 포탈 접속

```
URL: http://localhost:8069/supplier/portal?token=<삼성캡 포탈 접근 토큰>
```

### 3.2 받은 발주 확인

**메뉴**: 받은 발주 > 다른 업체에서 받은 발주

| 발주처 | 제품 | 상태 | 액션 |
|--------|------|------|------|
| 한국브라켓 | 엔드캡A | 신규 | [확정] |
| 한국브라켓 | 엔드캡B | 확정 | [출하] |
| 한국브라켓 | 엔드캡A | 출하 | - |

### 3.3 발주 확정 및 출하

```
1. [확정] 클릭 → 상태: confirmed
2. [출하] 클릭 → 상태: shipped, 출하일 기록
3. 한국브라켓에 출하 알림 발송
```

## Phase 4: 입고 확인

### 4.1 한국브라켓 - 입고 현황

**메뉴**: 보낸 발주 > 입고 현황

| 구분 | 설명 |
|------|------|
| 입고 대기 | shipped 상태, [입고확인] 버튼 |
| 입고 예정 | confirmed 상태, 대기 중 |
| 입고 완료 | received 상태, 최근 30일 |

```
입고 대기 건 > [입고확인] 클릭 → 상태: received
```

---

## Phase 5: 구매담당자 - 응답 검토

### 5.1 Odoo 백오피스

**메뉴**: 구매 > 외주 조달 > 응답 검토

| 발주 | 협력사 | 응답 | 액션 |
|------|--------|------|------|
| PO00001 | 한국브라켓 | 전체 승인 | [승인] |
| PO00002 | 대한하우징 | 조건부 | [검토] |

### 5.2 응답 승인/반려

```
[승인] → portal_state = 'approved', PO 확정
[반려] → portal_state = 'rejected', 반려 사유 입력
```

**반려 시**:
- 협력사에 반려 알림
- 협력사가 재응답 가능

## Phase 6: 입고 및 재고 반영

### 6.1 입고 처리 (Odoo 표준)

**메뉴**: 재고 > 입고

```
발주서 관련 입고 확인 → 수량 검증 → [확인]
```

### 6.2 재고 확인

**메뉴**: 재고 > 제품

- 외주 부품 재고 수량 증가 확인
- 재고 이동 이력 확인

## 포탈 URL 요약

| 협력사 | URL (토큰은 협력사 관리 화면에서 복사) |
|--------|-----|
| 한국브라켓 | `http://localhost:8069/supplier/portal?token=<한국브라켓 토큰>` |
| 대한하우징 | `http://localhost:8069/supplier/portal?token=<대한하우징 토큰>` |
| 삼성캡 | `http://localhost:8069/supplier/portal?token=<삼성캡 토큰>` |

> 데모 토큰(`demo_token_…`)은 서버가 거부합니다("접근 토큰이 필요합니다"). 데모 데이터 설치 시에도
> 강한 랜덤 토큰이 자동 발급되므로 반드시 화면에서 복사하세요.

## 트러블슈팅

### 포탈 접속 안됨
```sql
-- 토큰 확인
SELECT name, supplier_portal_token, is_supplier_portal 
FROM res_partner 
WHERE is_supplier_portal = true;
```

### 발주 안보임
```sql
-- 자동생성 발주 확인
SELECT name, partner_id, portal_state, auto_generated 
FROM purchase_order 
WHERE auto_generated = true;
```

### 알림 발송 확인
```sql
SELECT * FROM supplier_portal_notification 
ORDER BY create_date DESC LIMIT 10;
```
