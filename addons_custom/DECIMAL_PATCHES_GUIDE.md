# 소수점 표시 패치 안내

> 대상 모듈: `account_kr_plus_patch` (금액) · `mrp_plus_patch` (수량)
> 작성 2026-08-28 · 브랜치 `merge/20260827` · 커밋 `cec9fd9d` `e0542f2b` `27c2d9e5`
> 상태: **로컬 커밋 완료 / 미러·운영 미배포**

## 한눈에

| | `account_kr_plus_patch` | `mrp_plus_patch` |
|---|---|---|
| 담당 | 회계 **금액**의 `.00` 제거 | **수량** 소수점 자리수 복원 |
| 방식 | 필드 자리수 소스 재지정 (코드) | 소수점 정확도 1회 조정 (설정값) |
| 적용 시점 | 서버 기동 시마다 (레지스트리 로드 직후) | 설치·해당 버전 업그레이드 때 **1회만** |
| 종속성 | `account` | `mrp`, `injection_worksite` |
| 버전 | 18.0.1.0.0 | 18.0.1.1.0 |
| 되돌리기 | 시스템 파라미터로 OFF + 재시작 | 설정 화면에서 자리수 변경 |

두 모듈은 **금액과 수량의 자리수 소스를 분리**하는 것이 목적입니다. 이전에는
하나를 고치면 다른 하나가 망가지는 구조였습니다.

## 1. 배경 — Odoo에서 자리수는 세 곳에서 결정된다

| 자리수 소스 | 적용 대상 | 조정 방법 |
|---|---|---|
| 통화 반올림 계수 (`res.currency.rounding`) | `Monetary` 금액 **전부** | 설정 > 회계 > 통화 (KRW=1 → 0자리, **이미 적용됨**) |
| 소수점 정확도 (`decimal.precision`) | `digits="이름"` 으로 선언된 필드 | 설정 > 기술 > 소수점 정확도 |
| **소스에 박힌 기본값 `(16, 2)`** | `digits` **미지정** Float 필드 | **설정으로 불가능 — 코드만 가능** |

청구서 총액·분개 차변/대변·매입매출장 같은 대부분의 금액은 첫 번째 줄에 속해
이미 소수점 없이 나옵니다. 문제는 세 번째 줄이었습니다.

## 2. 무엇이 문제였나

2026-03-05, 관리자 계정이 설정 화면에서 소수점 정확도 두 개를 같은 시각에
0으로 내렸습니다 — `Product Price`(단가)와 `Product Unit of Measure`(수량).
금액의 `.00` 을 없애려는 조치였지만, **수량 자리수까지 함께 죽는** 부작용이
있었습니다.

그 뒷수습 흔적이 `escon_uom_standard` 모듈 주석에 남아 있습니다. BOM 원단위를
kg로 입력하면 소수점이 잘려(0.784 → 0.78, 마스터배치는 0.00) 자재소요가
왜곡되니, **g 단위로 입력하는 정책**을 만들어 우회한 것입니다.

그런데도 `.00` 은 완전히 사라지지 않았습니다. 위 3번 부류(설정이 닿지 않는
Float 금액 필드)가 그대로 남아 있었기 때문입니다.

## 3. `account_kr_plus_patch` — 금액 `.00` 제거

### 하는 일

소수점 정확도에 **"KR Amount"(기본 0자리)** 항목을 새로 만들고, 코드에 명시한
금액 필드들이 이 값을 따르도록 자리수 소스를 바꿉니다. 단가 성격 필드는
기존 **"Product Price"** 를 따르게 분리했습니다 — 금액과 단가를 따로 관리할 수
있습니다.

### 대상 필드 (15개, 화이트리스트)

**금액 → "KR Amount"(0자리)**

| 모델 | 필드 | 어디서 보이나 |
|---|---|---|
| `account.account` | `current_balance` | 계정과목 폼의 '잔액' 버튼 |
| `account.invoice.report` | `price_subtotal`, `price_subtotal_currency`, `price_total`, `price_average`, `price_margin`, `inventory_value` | 청구서 분석 (피벗·리스트) |
| `purchase.bill.union` | `amount` | 구매 청구 대사 |
| `sale.order` | `amount_paid` | 온라인 결제 수령액 |
| `product.product` | `value_svl` | 제품 재고 평가액 |
| `stock.lot` | `value_svl` | 로트/시리얼 평가액 |
| `stock.valuation.layer.revaluation` | `current_value_svl` | 재고 재평가 위자드 |

**단가 → "Product Price" 설정을 따름**

| 모델 | 필드 | 어디서 보이나 |
|---|---|---|
| `purchase.order.line` | `price_unit_discounted` | 구매 라인 할인 적용 단가 |
| `purchase.bill.line.match` | `product_uom_price` | 구매↔청구 라인 대사 |
| `sale.report` | `price_unit` | 판매 분석 평균 단가 |

### 안전장치

- **화이트리스트 방식** — 이름 패턴으로 긁지 않습니다. 위 표에 적힌 필드만
  건드리므로, 예상 못 한 곳이 딸려 바뀔 일이 없습니다.
- **수량 불가침** — `quantity`, `qty_*`, `product_uom_qty`, `quantity_svl` 등은
  표에서 제외했고, 회귀 테스트로 고정해 두었습니다.
- **저장 필드 자동 제외** — DB 컬럼이 있는 필드는 자리수를 바꾸면 컬럼 타입까지
  바뀝니다. 표시 목적으로 그런 위험을 지지 않도록 자동으로 건너뜁니다.
  (실제 대상은 전부 계산 필드나 리포트 뷰 필드입니다)
- **기존 설정 존중** — 다른 모듈이 이미 자리수를 지정한 필드는 손대지 않습니다.

### 끄는 법

시스템 파라미터 `account_kr_plus_patch.integer_amounts` 를 `0` 으로 두고
서버를 재시작합니다. 자리수는 서버 기동 시 한 번 적용되므로 재시작이 필요합니다.

### 자리수를 0이 아닌 값으로 바꾸려면

설정 > 기술 > 소수점 정확도에서 **"KR Amount"** 값을 바꾸고 재시작합니다.
이 레코드는 설치 때 한 번만 심기 때문에, 바꾼 값을 모듈 업그레이드가
덮어쓰지 않습니다.

## 4. `mrp_plus_patch` — 수량 자리수 복원

### 하는 일

소수점 정확도 **"Product Unit of Measure"** 를 Odoo 기본값 2자리로 되돌립니다.
사출품 BOM은 부품 1EA당 원재료(레진) 소요량을 kg 단위 소수로 잡기 때문에
(예: 0.02 kg/EA), 자리수 0이면 이 값이 화면에서 정수로 뭉개집니다.

### 1회 적용 방식 — 설정을 존중합니다

| 시점 | 동작 |
|---|---|
| 신규 설치 | 자리수가 **2 미만일 때만** 2로 올림 |
| 1.0.x → 1.1.0 업그레이드 | 같은 로직을 **딱 한 번** 실행 |
| 그 이후 모든 업그레이드 | **아무것도 안 함** |

이미 2 이상인 DB(누가 3자리로 올려 둔 경우 등)에는 설치 때도 개입하지 않습니다.
**값을 끌어내리는 경우는 없습니다.**

### 데이터는 무사합니다

모든 단위(`uom.uom`)의 반올림 계수가 0.01이라, 저장된 수량 값 자체는 소수점을
유지하고 있었습니다. 잘린 것은 **표시 자리수**뿐이므로 복원하면 즉시 정상으로
보입니다.

다만 자리수가 0이던 시절에 **새로 입력·계산되어 저장된** 값 중 일부는 그 시점에
반올림됐을 수 있고, 이런 값은 복원해도 되살아나지 않습니다. (g 단위 입력
정책 덕분에 피해 범위는 제한적입니다)

### 더 미세한 자리수가 필요하면

- 표시 자리수: 설정 > 기술 > 소수점 정확도에서 "Product Unit of Measure" 를 올립니다.
- **0.01보다 미세한 값**을 저장해야 한다면 자리수만으론 부족합니다. 해당 단위
  (`uom.uom`)의 반올림 계수도 함께 내려야 합니다 (예: 0.001).

## 5. 설치·배포

현재 로컬 커밋만 되어 있습니다. 운영 반영 절차:

1. `odoo_gh` 미러로 두 모듈 복사 (rsync)
2. 모듈 설치: `-i account_kr_plus_patch,mrp_plus_patch`
   - `-i`(설치)여야 `mrp_plus_patch` 의 1회 복원 로직이 실행됩니다
3. 서버 재시작

운영 `account_kr_guard` 는 1.0.0 그대로이므로 별도 회수 단계가 필요 없습니다.

## 6. 알아둘 점

- **수량이 `5.00` 으로 보입니다.** 소수점 정확도는 전역 설정이라, kg에 소수점을
  주면 EA 같은 정수 단위도 2자리로 표시됩니다. 단위별 표시 분리는 Odoo 기본
  기능으로는 불가능합니다 — 거슬리면 별도 위젯 패치가 필요합니다.
- **`account_kr_guard` 는 건드리지 않았습니다.** 두 모듈 모두 신규이며, 기존
  모듈 수정은 0건입니다.
- **나중에 K-Guard로 편입할 때**: 편입본을 배포하기 전에
  `account_kr_plus_patch` 를 먼저 **uninstall** 해야 합니다. "KR Amount" 정확도
  레코드의 이름 중복 제약에 걸립니다. 자세한 절차는
  `account_kr_plus_patch/HANDOVER.md` 에 있습니다.

## 7. 검증 상태

개발 DB `myodoo202608` 에서 실제 설치·업그레이드로 확인했습니다.

- `account_kr_plus_patch` — 테스트 4건 통과
  (정확도 레코드 / 금액 필드 0자리 / 단가 = Product Price / **수량 필드 미변경**)
- `mrp_plus_patch` — 테스트 4건 통과
  (자리수 ≥ 1 / 수량 필드 참조 경로 / 단위 반올림 / **0→2 복원 + 3 유지**)
- 서버 로그에 금액 필드 15개 패치 적용 1줄, 업그레이드 시 1회 복원 스크립트 실행 확인

운영 DB에는 아직 적용하지 않았습니다.
