IATF 패스 검증 · 로그
====================

기존 입고·생산·공정·출하 업무에 개입하는 IATF 검증 실패를 기록하고 업무를 계속하는
회사별 시험 모드입니다. 검사 합격이나 결재 승인을 생성하는 기능은 아닙니다.

사용 방법
---------

* ``iatf_passive_verify_test``를 설치하면 회사별 ``IATF 업무 차단 패스``가 기본 활성화됩니다.
* 홈 화면의 **IATF 패스 검증 → 통과 로그**에서 분야·모델·원본 이름·오류 메시지로 검색합니다.
* 로그에서 **원본 레코드**, **원본 첨부파일**을 열거나 **원본 파일**의 소스 스냅샷을 내려받습니다.
  원본 업무 레코드와 첨부파일 접근에는 기존 권한이 적용됩니다.
* 시스템 관리자는 **패스 설정**에서 회사별로 끌 수 있습니다. 이후 호출부터 기존 IATF 처리가
  다시 적용됩니다. 설정 변경도 기록합니다. 이미 통과한 재고·업무를 되돌리지는 않습니다.

통과 범위
---------

* 입고: IQC 검사대기 위치 전환을 저장점 안에서 관찰하고 되돌려 원래 입고 위치를 유지합니다.
  이 방식으로 입고한 상세에는 IQC 관리 표시가 남지 않으므로 신규 IQC 초안도 생성되지 않습니다.
  이동 미적용 사유는 관찰 로그로 남습니다. 기존 검사대기 위치의 이동 및 IQC 가용재고 검증도 대상입니다.
* 생산·공정·출하: 보류 LOT 투입, 이전 공정 IPQC 불합격, OQC·포장/라벨 승인 및 검사 수량,
  IATF 조립제품 실재고·예약 검증의 실패를 기록하고 계속합니다. 기존 검사 결과·승인·LOT 보류 상태는
  이 검증 통과만으로 변경하지 않습니다.
* BOM: 미승인 IATF 변경요청으로 인한 수정 잠금을 통과하고 자동 변경요청 생성 실패를 기록합니다.
* 자동 후처리: PQC/IPQC, 추적 이력, 금형 타수, 관리계획 연결, PPAP 요청, 작업자 자격 경고,
  포장 경고, SPC·NC·LOT 보류 증빙 생성의 실패를 분리해 기록합니다. 성공한 후처리는 기존대로 적용됩니다.
  설치된 Engel 앱의 금형·추적·SPC 후처리도 연동됩니다.

통과하지 않는 범위
------------------

품질 문서 자체의 직접 판정·승인·완료 및 수정·삭제 보호, 금융·정산 오류, BOM/Odoo 핵심 처리,
MES 고유 완료 조건, 업무 원본의 접근권한·회사/제품/LOT 식별 정합성, 인증 오류와 SQL 오류는 유지합니다.
업무 원본 권한을 먼저 확인한 후 분리된 IATF 기준 조회 권한 오류, 또는 IATF 자동 후처리 권한 오류는
해당 품질 처리 실패로 기록할 수 있습니다. Odoo 전체 예외를 일괄 무시하지 않습니다.

로그와 주의사항
---------------

``iatf.passive.log``에는 통과 일시, 회사, 실행자, 분야, 내용, 오류 유형·메시지, 호출 지점,
원본 모델·ID·이름, 소스 줄 번호와 호출 경로를 저장합니다. ``iatf.passive.source``에는 당시
IATF/Engel Python 파일 전체와 경로·SHA-256을 보관하며 같은 파일 내용은 재사용합니다.
로그·소스 스냅샷과 그 첨부파일은 일반 수정·삭제를 막습니다. 원본 첨부파일 버튼은 업무 첨부파일을
연결하는 기능이며 당시 첨부파일 전체를 별도 복제하는 기능은 아닙니다.

실패한 품질 처리의 부분 변경은 저장점으로 되돌립니다. 로그 저장에 실패하면 업무도 중단합니다.
로그는 업무와 같은 트랜잭션에 있으므로 이후 핵심 업무 오류로 전체 롤백되면 로그도 함께 롤백됩니다.
독립적인 실패 시도 감사 저장소는 아닙니다.

패스 활성 중에는 검사 미승인 출하, 품질 보류 LOT 사용, 검사대기 없는 입고가 가능하며 자동 품질
증빙이 누락될 수 있습니다. 로그를 확인하고 실제 검사·승인·증빙 보완을 별도로 수행해야 합니다.
모드를 끄거나 앱을 제거해도 이미 진행한 업무를 자동 복구하거나 과거 검사를 생성하지 않습니다.

검증
----

``tests/test_passive.py``는 합성 레코드로 입출고 재고 전기, 비활성 복원, LOT 필수값,
후처리 부분 변경 롤백, 로그 저장 실패, 권한·회사·SQL 경계, 소스 보호, 원본 접근권한,
승인 상태 유지, BOM 변경, 이전 IPQC 및 보류 LOT 소비를 검증합니다.
실행 결과·환경·커밋은 같은 브랜치의 ``docs/tasks/작업/update/iatf_passive/after20260930.md``를
참조합니다. 코드에 시험이 존재한다는 사실만으로 현장 시험 완료를 의미하지 않습니다.
